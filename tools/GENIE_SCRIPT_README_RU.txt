Интерпретатор предметов джина: ядро языка и облачная проверка

Лампа джина выдаёт предметы с программой после облачной и серверной проверки.
GenieWorldHost выполняет игровые операции, а GenieScriptContracts проверяет
ядро VM с отдельным тестовым хостом. Программы предметов и их состояния
сохраняются сервером. Браузерный worker работает через связанный Firefox.

Индекс для модели собирается из текущего реестра сервера после загрузки
датапаков. В нём есть ID всех предметов, их штатные имена, все таблицы
лута и возможные прямые дропы, включая имена из модификаторов таблицы.
Ссылки на вложенные таблицы передаются по ID. Учитываются и ванильные данные.
Раскладка весов, контекстные имена и конкретный результат броска не вычисляются.

Для переведённых имён положите JSON из assets/<namespace>/lang ресурспака
в config/skywars2/genie/lang/ на сервере. Файл называется как локаль, например
ru_ru.json. Если у нескольких пространств имён есть файл одной локали,
объедините их JSON-объекты в порядке загрузки ресурсов. Джин передаёт модели
только переводы использованных в индексе имён. Английские ванильные имена
доступны из самого сервера. Обновлённые переводы подхватываются после /reload.

Модель принимает решение о допустимости желания и придумывает обязательный
подвох. Проверяющий код не оценивает баланс, урон, радиус или силу предмета.
Ограничения в ScriptValues/ScriptProgram относятся к памяти и форме программы.
Высокий урон сам по себе не является синтаксической ошибкой.

Программа — строгий JSON с четырьмя полями:
{"version":1,"state":{},"handlers":{"USE":"main"},"functions":{
  "main":{"parameters":["event"],"code":[
    ["const","particle minecraft:end_rod ~ ~ ~ 0 0 0 0 1"],
    ["call","world.command",1],["return"]
  ]}
}}

state — изменяемые данные конкретного предмета; LOAD state получает корень.
Функции имеют именованные параметры и локальные переменные. CONST кладёт
значение в стек; LOAD/STORE читают/записывают локальную переменную. Корень
state нельзя заменить через STORE, но его содержимое меняется через PUT.
GET получает ключ/индекс из объекта/массива. PUT кладёт копию значения и
возвращает записанное значение. ARRAY n собирает n значений, OBJECT n
собирает n пар ключ/значение. DUP дублирует ссылку, DROP убирает значение.

LABEL задаёт метку, JUMP переходит к ней, JUMP_IF_FALSE снимает условие и
переходит при ложном значении. CALL имя число_аргументов вызывает функцию
или API хоста и возвращает значение. RETURN возвращает верхушку стека,
HALT завершает обработчик. WAIT снимает число тиков, сохраняет продолжение
и отдаёт управление серверу; даже WAIT 0 продолжится не раньше следующего
тика. Поддерживаются рекурсия, циклы, арифметика и сравнения. Точный список
операций/арностей/стековых эффектов экспортируется Java-компилятором:
ScriptProgram.contract(api, events). Этот контракт нельзя переписывать в ИИ.

ScriptMachine.advance получает общий бюджет инструкций и при необходимости
общий deadlineNanos. При исчерпании бюджета продолжение сохраняется.
Асинхронный хост возвращает Pending: ожидание не блокирует вызывающий поток.
cancel прекращает продолжение и отменяет принадлежащую ему работу хоста.
Ошибка инструкции или асинхронного вызова окончательно отменяет обработчик.
Deadline не прерывает уже начатый нативный вызов. Тяжёлые операции хоста
поэтому должны сами быть кооперативными. ScriptMemory учитывает общую живую
память обработчиков, состояний, констант, очередей и результатов нативных вызовов.
Временные значения освобождаются повторным обходом графа, общие ссылки учитываются один раз.

GenieWorldHost исполняет игровые команды с уровнем GAMEMASTER, не наследуя
администраторские полномочия аккаунта. Он сохраняет результаты и вывод команд
в JSON, не рассылая диагностический вывод игрокам. Нативные задачи выполняются
через drain в серверном тике; отмена ожидания удаляет задачу до исполнения.
world.select использует нативные селекторы. world.raycast получает from, to,
запас вокруг хитбокса и флаг поиска сущностей; возвращает столкновение с блоком
и все пересечённые сущности, включая снаряды. Он учитывает реальные формы
столкновения и останавливается на незагруженном чанке, не загружая его даже
ради получения описания блока. Один запрос ограничен отрезком 1024 блока и
запасом 64 блока; длинный поиск надо делить на запросы и тики.

entity.launch создаёт нативного моба или снаряд по ID. lbc.grimoire выполняет
заклинание зарегистрированного гримуара. lbc.cast получает ID из
script_directed_casts и необязательные массивы [x, y, z] для начала и направления.
По умолчанию берутся глаза и взгляд игрока. Например,
lbc.cast("skywars2:electro_arc", position, velocity) выпускает одну дугу из
позиции выстрела. Движение, урон и столкновения обрабатывает механика LuckyWars.

Облачная проверка:
1. Сервер передаёт модели неизменённые verify_genie_program.py, contract.json
   и описание реальных API/событий. Для каждого желания создаётся новый Chat.
2. Модель создаёт program.json и действительно запускает в облачном Python:
   python verify_genie_program.py contract.json program.json
3. При ошибке модель исправляет программу и запускает тот же валидатор снова.
4. Итоговый ответ содержит программу и полученный receipt. Сам по себе текст
   receipt не доказывает выполнение. Браузерный worker должен видеть нативный
   виджет вывода выполнения и совпадающий результат в ЭТОМ разговоре.
5. Сервер заново разбирает строгий JSON, компилирует программу по своему
   контракту и сравнивает program_sha256 и contract_sha256. Техническая ошибка
   не является отказом джина по причине силы/неуважительности желания.

ScriptJson и Python-валидатор используют одинаковый канонический JSON:
порядок ключей UTF-16, строки Unicode без потери символов, числа BigDecimal
без лишних нулей (с компактной экспонентой, где она нужна), отрицательный ноль
равен нулю. Контракт отмечает этот формат как unicode-utf16-bigdecimal-v2.
Проверка отвергает дубликаты
ключей, не-JSON синтаксис, NaN/Infinity и непарные суррогаты Unicode.

Проверки для разработчика:
- tools/GenieScriptContracts.java проверяет реальное выполнение VM, ожидание,
  функции/циклы, отмену, ошибки хоста и технические границы данных.
- tools/check_genie_script_contracts.py сравнивает облачный валидатор с
  настоящим Java-компилятором на корректных и ошибочных входах.
  Аргументы: --java путь/java.exe --classpath классы;gson.jar --output каталог
- tools/genie_chat_page.js читает только текущую разрешённую вкладку:
  выбранную модель, окончательные ответы и нативные виджеты вывода Python.
  Он не читает cookies, историю, sidebar или внутреннее состояние страницы.
  Браузерный worker использует этот адаптер для каждой новой заявки.

Исполнение предметов (этап интеграции):
- GenieScriptRuntime получает обычные игровые события, сохраняет состояние в
  genie_state и приостанавливает собственные часы при TimeStop. Обработчики
  одного сервера делят бюджет инструкций, времени, памяти и нативных задач.
- ScriptRepository сохраняет проверенный канонический код в сжатые .json.gz
  под skywars2/genie/programs в мире сервера. Подготовка и чтение идут отдельным
  потоком низкого приоритета. В предмете хранится только genie_code (SHA-256),
  genie_serial и изменяемое состояние. При загрузке проверяется хеш содержимого.
- Полная копия NBT создаёт отдельное состояние предмета. Снимок последнего
  съеденного/сломанного предмета не должен обновлять похожий предмет в другой руке.
- Квантовый откат сохраняет очередь событий, часы, кадры функций и общие ссылки
  между обработчиками. Невыполненная команда возвращается в очередь, выполненная
  передаёт сохранённый результат. Исходный слот связывается с готовым инвентарём.
- Лампа выдаёт предмет после получения совпадающего результата облачной проверки
  и сохранения кода. При технической ошибке она снимает блокировку и остаётся в
  инвентаре. Решение модели об отказе включает игровой штраф.

Подключение Firefox:
- Установите и спарьте MCP for Firefox с локальным сервером расширения. Личный
  профиль Firefox хранит сессию входа. Команда /skywars genie login даёт оператору
  обычную ссылку на ChatGPT. Откройте её в спаренном Firefox.
- По умолчанию мод ищет .browser-tools/firefox-mcp/dist/server/index.js и каталог
  .browser-tools/firefox-state в рабочем каталоге сервера. Порт по умолчанию 1025.
  Переопределения в config/skywars2/genie/firefox.json: node, mcpDirectory,
  stateDirectory (строки с путями) и port (число). Для каждого желания обработчик
  открывает свою вкладку и проверяет обычный Chat и GPT-5.6 Medium перед отправкой.
  Старый ограниченный Blueprint не является реализацией нового интерпретатора.
