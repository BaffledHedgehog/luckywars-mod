# Проверка игрового цикла на Fabric

Дата: 8 октября 2026. Minecraft 26.3, Fabric Loader 0.19.5, Fabric API
0.161.0+26.3, Polymer 0.18.2+26.3, SGui 2.2.1+26.3, Java 25.
Проверки выполняются на изолированном сервере
`build/verification/key-reuse-server`, порт `127.0.0.1:25576`, с отдельным миром
и конфигурацией. Миры/конфигурация основного сервера и исходный Paper-сервер
не изменялись. После успешных проверок, при остановленном основном сервере,
проверенный JAR установлен в `../mods/skywars2.jar`. Сборка перед изменением
инвентаря сохранена в `build/verification/skywars2-before-lobby-inventory.jar`;
сборка перед асинхронной загрузкой — в `build/verification/skywars2-before-async-maps.jar`.

## Результат

`gradlew build` проходит. Полный живой прогон
`python -X utf8 tools/smoke_game_cycle.py --server-dir build/verification/key-reuse-server`
завершился сообщением `ALL LIVE CHECKS PASSED`: семь сценариев,
186,18 секунды, четыре запуска JVM. Это прогон финального загрузчика после
асинхронного разбиения NBT, предварительной загрузки чанков и открытия меню
во время `LOADING`. Новый JAR: SHA-256
`86c23b9d505fefef2740a8f19d75da398be04d174edffe73a69e159d91c87ac3`.

`tools/check_localization.py --pack build/verification/key-reuse-server/polymer/resource_pack.zip`
проходит: 385 недостающих записей RU и 384 EN, отсутствие дубликатов исходного
ресурс-пака, совпадающий template, параметры переводов, покрытие текстов
Java/loot-таблиц и совпадение переводов готового Polymer-пака с исходниками.
147 прежних ключей используются непосредственно; исходные языковые файлы
ресурс-пака не изменились по SHA-256.
Пак автоматически создан при запуске; раздача Polymer включена как необязательная.
Проверка меню сериализует заголовки, имена и lore всех страниц нативным
`ComponentSerialization.CODEC`: клиентские ключи, аргументы и стили сохраняются.
Числовые Java-аргументы после декодирования могут менять свой внутренний тип,
поэтому сравнивается их представление в сериализованном компоненте.
Отдельно проверены исходные ключи, цвета, `italic=false` и точное число/порядок
lore первого набора, а также первого навыка, «Крыльев ветра» и навыка Vex.

Боты автоматически не создаются при обычном запуске.

## Замеры загрузчика

На карте 1 меню оставалось доступным 189 тиков: 95 во время фоновой подготовки
и 94 во время вставки/ожидания чанков. Максимальное время проверенной навигации
«главное меню → магазин → назад» — 3,1227 мс. Это время серверных callbacks,
а не задержка сети или частота кадров клиента.

Повторная вставка карты в том же JVM заняла 54 рабочих тика; подготовка —
3798 мс в фоне, максимальная измеренная работа вставки за тик — 4,4267 мс.
Один из возвратов в лобби занял 63 рабочих тика. Промежуточный вариант с
лимитом 12 частей занимал соответственно 217 и 289 тиков; сравнение относится
к этому варианту, а не к исходному датапаку. Финальный предел — 64 части,
бюджет — 4 мс, часть не больше 512 блоков.

На первом запуске нативные вызовы превышали этот бюджет: карта — до 11,1075 мс.
Восстановление после перезапуска доходило до 17,7395 мс.
Завершение операции и
запись журнала не входят в этот замер работы очереди. Жёсткая верхняя граница
времени всего тика не заявляется; нужен отдельный нагрузочный тест больших карт.

## Файлы и повторение

Логи: `build/verification/game-cycle.log`, `restart-cleanup.log`,
`loading-shutdown.log`, `loading-recovery.log`. Промежуточный прогон с пределом
12 частей сохранён в `async-12-slices-game-cycle.log` и
`async-12-slices-results.json`.
Итог: `build/verification/results.json`. `final-launch.log` относится к предыдущему
прогону 7 октября. Профили тестовых UUID сохранены в
`build/verification/key-reuse-server/config/luckywars/players.json`; они не связаны
с профилями настоящих игроков. Тестовый сервер после проверок штатно остановлен.

Повторить на подготовленной изолированной копии, из папки мода:

```powershell
$env:JAVA_HOME = 'E:\servers_mew\skywars2_last\runtime\jdk-25'
.\gradlew.bat --console=plain build
Copy-Item -LiteralPath build/libs/skywars2-0.1.0.jar -Destination build/verification/key-reuse-server/mods/skywars2.jar
python -X utf8 tools/smoke_game_cycle.py --server-dir build/verification/key-reuse-server
python -X utf8 tools/check_localization.py --pack build/verification/key-reuse-server/polymer/resource_pack.zip
```

Для прогона непосредственно на основном сервере его сначала нужно остановить:

```powershell
$env:JAVA_HOME = 'E:\servers_mew\skywars2_last\runtime\jdk-25'
.\gradlew.bat --console=plain build deployServerMod
python -X utf8 tools/smoke_game_cycle.py
```

Carpet нужен только для тестового соединения. Его обычный fake player отключается
при смерти, поэтому проверки создают обычные `ServerPlayer` с `FakeClientConnection`.
После респауна посылаются и `PERFORM_RESPAWN`, и штатное подтверждение загрузки
игрока `ServerboundPlayerLoadedPacket`, требуемое в 26.3.

## Пределы проверки

- Графический клиент не подключался: внешний вид GUI, принятие и отображение
  resource pack и сетевое представление будущих Polymer-предметов ещё нужно
  проверить с настоящим клиентом. Переводы в ZIP и сериализация компонентов
  проверены на сервере.
- Для прежних ключей необходим включённый клиентский `all_in_one_1.21.8`.
  Серверные логи могут показывать эти ключи буквально, поскольку исходные
  переводы не копируются в JAR. Это не проверка перевода на настоящем клиенте.
- Сохранены исходные описания наборов; обнаруженные расхождения количества
  выдачи наборов 5 и 9 отмечены в `agent_notes/RESOURCE_PACK.md` и
  `resourcepack_template/KEY_REUSE.json`. Этот прогон не меняет их механику.
- Каталог содержит 42 полные карты и 1296 NBT; живой цикл проверен на карте 1
  и её разрушенном варианте. Остальные карты не проходили полноценный матч.
- Полный каталог импортирует 268 loot tables; в JAR включены 13 таблиц сундуков
  и наборов. Старые GUI-функции, GUI-таблицы и ванильные registry overrides исключены.
  Проверены обычные `*_0` сундуки; Lucky-пулы и специальные наборы не прошли этот прогон.
- Polymer пишет предупреждение о packet context при подключении фиктивного
  соединения; без графического клиента это не проверка корректности клиентских
  chunk packets. Лог сохраняет сообщение, оно не скрыто.
- У Halloween-набора осталось предупреждение проверки loot context для старого
  `entity=this`. Этот набор в прогоне не выдавался; его точный перенос относится
  к этапу предметов. Ошибок загрузки реестров и пропущенных сундуковых таблиц нет.
- Это функциональный прогон с двумя игроками, не нагрузочный тест. Остановка
  для проверки журнала была штатной; внезапное завершение процесса не проверялось.
- LBC, BedWars, кейсы, разблокировки и косметика остаются следующими этапами.
