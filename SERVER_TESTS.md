# Проверки серверной сборки

Нативные проверки находятся в `src/checks/java` и поставляются только в
`*-test-server.jar`. Обычная сборка не должна содержать проверочные классы,
validation Mixin и тестовые Fabric entrypoints.

## Структура и артефакты

```powershell
python -B tools/check_java_layout.py
.\gradlew.bat --console=plain productionJar testServerJar
python -B tools/check_map_editing_artifacts.py build/libs/skywars2-0.1.0.jar build/libs/skywars2-0.1.0-test-server.jar
```

Первый инструмент проверяет исходники и регистрации. Второй сравнивает готовые
ZIP-записи, исключение проверок из production и сохранение вложенных зависимостей.
Эти проверки не заменяют запуск сервера и проверку игрового поведения.

## Нативные сценарии

`GameChecks` регистрирует имена сценариев и их тиковые обработчики. Проверочная
сборка предоставляет `/skywars check` через отдельный backend. Сценарии используют
настоящий сервер, мир, сущности и пакеты; некоторым нужен Carpet для тестовых
игроков. Используйте отдельный тестовый сервер и подходящий драйвер из `tools/`.

`tools/smoke_game_cycle.py` — общий драйвер интеграционных проверок; он поддерживает
`--server-dir` для отдельного экземпляра. Его настройки по умолчанию относятся к
локальной рабочей среде: перед запуском проверяйте целевой каталог. Не запускайте
сценарии на публичном сервере или в пользовательском мире.

Перед тестом целевой экземпляр должен быть остановлен и отпустить `session.lock`.
После теста проверяйте нормальное завершение дочернего процесса, восстановление
снимков, отсутствие оставшихся блокировок и результат самого сценария.

Обычный JAR дополнительно проверяется запуском без Carpet: сервер должен дойти
до лобби, а тестовые команды и backend не должны быть доступны. Проверки запускайте
последовательно, с ограниченным heap и низким приоритетом CPU/диска; количество
потоков и affinity без отдельного запроса не ограничивайте.

## Исторические результаты

Прежние сценарии, результаты и ограничения сохранены в
[справочнике проверок](docs/history/SERVER_TESTS_2026_11_21.md).
Старые отметки `PASS` относятся к указанным там артефактам и не подтверждают
новую сборку. Локальные отчёты, миры и запечатанные JAR лежат в игнорируемом
`build/verification` и `build/deployment`; `gradlew clean` удалил бы их.
