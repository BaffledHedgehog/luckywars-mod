# Sheep native checks

Implementation prepared on 25 October 2026. This note does **not** claim a
successful build, recorded runtime result, client rendering qualification, or
ready artifact. The root agent owns compilation and runtime qualification.

`SheepChecks.run/tick` advances five phases on successive native game ticks:

- Real ordinary/Academy loot identities, source flags, six authored lore rows,
  model and A/X tiers; native input in both hands at499/500 mana, offhand
  configuration, personal/dimension Time Stop and real antimagic field guards.
- Actual first-impact ray transforms one Cow into native permanent `jeb_` sheep
  with8HP and knockback resistance20. The later Cow survives; ordinary items and
  another player's hotbar remain intact; original replacement creates no loot.
- A real normal Academy assigns the trial, which is moved to the actual used
  offhand. A malformed potion fails. A matching dropped potion creates a hole,
  clears nearby unrelated dropped items as required by source, and immediately
  readies that used stack. Native token-school promotion occurs on a subsequent
  server tick and yields X tier. A separate inventory branch clears matching
  potions from nearby players without transforming them.
- Direct native Academy transformation preserves male/female tags; males create
  unconditional holes.48 unassigned creatures each receive exactly one sex and
  exercise both random branches. This verifies reachable branches, not a
  statistical proof of the source50% probability. Technical roles are guarded.
- Native hole admission exposes the actual shared disc shader handle with
  radius sqrt552/14. Source10 outside_border kills a native10HP Cow with caster
  damage credit; caster and teammate take the same10. Greed, technical roles and
  void resistance preserve HP. Strong inner and weak outer velocity pull retain
  existing outer player motion. Core obsidian and shell stone are consumed,
  outside-sphere stone survives, actual disc tilt stays within18degrees,
  dimension Time Stop freezes point/velocity, and owner retirement closes holes.

`sheep-stop-probe` retains an actual permanent sheep and actual native hole.
Both are tagged frozen before any service tick; the hole has no terrain work yet.
`sheep-cleanup` checks actual match-stop epoch invalidation, empty service views,
and removal of both retained actors.

The fixture isolates the school atY240 and ray lane atY254; the hole center is
80blocks away. It requires an empty high-air cube with32block margin. Bounded
fixture chunk reads admit only those columns using native getChunk and temporary
fixture force tickets. The fixture snapshots the preexisting forced-chunk set and
tracks only newly forced columns. It releases its own tickets after block/tick
restoration in close, including the initialization-failure cleanup path; existing
forced chunks remain forced. Runtime service behavior still only operates on
resident chunks and introduces no production forcing. School blocks, the four explicit terrain probes, and scheduled block/
fluid ticks are restored. No giant hole block snapshot is made. Cleanup owns
only created entities and narrowly identified native loot at the fixture death.

Players restore inventory, crafting/cursor, effects/tags, position/motion,
health/maxHP, game mode/abilities, food/experience, all existing scoreboard
values (including absent-score restoration), profile fields, custom/item/entity
statistics, advancements, Academy click timestamps, config and configured cost.
Mana regeneration is paused during real phase ticks to prevent accidental
Overload Crux creation at zero mana; this does not block authorized casts.

Boundaries: explicit native service calls do not establish elapsed-time lifetime,
physical disk restart/disconnect, real client pixels, or peak-load performance.
The random sample is probabilistic. The fixture does not claim exhaustive
source particle packet or per-line range validation, terrain fairness under
concurrent load, or actual player movement packet/input simulation.

## Focused fixture correction after first native run

The first focused run reached the hole physics phase after passing native input,
ray replacement, potion/Greed handling, Academy promotion and sex branches. Its
combined pull assertion failed. The fixture had placed its outer Cow/player at35,
outside its32block preflight cube, and had supplied velocity without voluntary
client input. This was insufficient evidence for a production defect.

The revised outer probes are at28: beyond sqrt552 yet inside the loaded fixture
cube. Before the service tick, the fixture verifies that the outer Cow has a
resident block column and appears in the actual native entity query. Failure
includes block/entity residency, position and query diagnostics. Separate checks
report weak inward Cow pull, stronger inner pull, and actual forward-input player
motion. `ServerPlayer.setLastClientInput` supplies forward input explicitly; Saved
captures/restores each player's original native input. This revision has not been
compiled or run by this agent; production code is unchanged.


## Fixture residency correction after intermittent Academy failure

A later focused run intermittently lost the +80X hole columns while the player
returned to the school between phases. Native temporary getChunk admission did
not keep those columns resident for the full asynchronous fixture. The fixture
now temporarily forces only bounded school and hole columns, preserving the
preexisting forced set and releasing only its own tickets in close after terrain
and scheduled-tick restoration. The finally path releases them even when
initialization or later verification fails. Production residency is unchanged.

The first preassigned-male assertion now includes original removal, sheep/hole
counts, owner health, match/stage/item eligibility, block/entity residency and
positions. This is fixture implementation only; this agent did not build or run
the revised check.
