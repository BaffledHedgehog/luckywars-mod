## Пользовательская поправка к #9 (user)

> Исправить: здоровье, броня и прочность брони уменьшаются на 2

Это целевое поведение переноса. Текущий исходный callback не реализует прочность брони: вместо неё его третий вызов `armor_update` повторно меняет armor, используя toughness base. Порт уменьшает все три характеристики отдельно; это намеренное исправление исходного дефекта.
## Границы реализации #9

В текущем проекте `LbcItems` хранит только загруженные nano markers текущей эпохи. Каждый игровой tick сначала получает локальные marker-query около `alivePlayers()`, объединяет найденные markers, затем для каждой мины проверяет полный набор active целей в радиусе ≤1. Таким образом пассивные мины не запускают индивидуальный периодический query; работа ограничена уже активными игроками, ближайшими маркерами и целями при срабатывании. Все цели обрабатываются один раз, marker удаляется; при unload ссылка снимается, загруженные markers discard-ятся при stop/выходе матча, а epoch tag отсеивает сущности старого раунда после повторной загрузки чанка. Спавн яйца вне матча или в чужом dimension не должен оставить marker. На reset игрока сохраняются исходные три base-значения; `effectsChanged` штраф не очищает. Источник не хранит владельца, поэтому self-trigger возможен; owner/team иммунитет не добавляется. Источник исключает только spectator gamemode; порт использует observer-aware `game.isObserver` по пользовательскому правилу.
