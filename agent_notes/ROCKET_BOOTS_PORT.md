# Ракетные ботинки — набор 22

Исходный контракт и авторское исправление крафта: [ROCKET_BOOTS_SOURCE.md](ROCKET_BOOTS_SOURCE.md).
Выбор — исходный GUI slot 22, доступ — `lbc:true_advancements/legends/academy/exasperato`.
Каталог содержит десять наборов: 1/2/4/5/7/9/10/15/22/23.

## Способность

Выдаётся предмет из `lbc:kit/explosive_feets`: серверный `skywars2:rocket_boots`,
который Polymer показывает клиенту как кольчужные ботинки,
прочность 280, броня +2, модель `lbc:armors/rocket_boots`, armor asset `lbc:rocket`.
Имя `lbckit.21` белое, lore `lbckit.21.lore.2/.3/.4` серое; исходные стили сохранены.
Новый предмет распознаётся напрямую по серверному типу. Для старых предметов
и ботинок с перенесённой способностью сохраняются исходный marker и Paper PDC
aliases `lws`, `luckywars`, `lucky_wars`.
Обычный компонент glider сам по себе не делает предмет ракетным.

Смена экипировки создаёт три заряда. Нативная попытка начать планирование
проверяет землю, пассажира, левитацию, воду, поломку предмета и слот glider;
только затем `LbcItems` добавляет прежний импульс. При положительной текущей Y-скорости
к ней прибавляется 0.5; иначе при взгляде вниз Y становится 0.5; затем добавляется
полный вектор взгляда. Клиент получает обычный пакет скорости.

Без нагрудных элитр планирование отменяется, с элитрами сохраняется.
Каждый успешный импульс расходует заряд; три импульса можно сделать подряд.
После первого расхода заряды восстанавливаются по одному: исходные 300 decrement-тиков
и восстановление на следующем, то есть интервал 301 тик. При нуле зарядов glider
с ботинок снимается, после восстановления возвращается. Смена одной ракетной пары
на другую сохраняет состояние; снятие, смерть, выход и конец матча очищают его.
Очищающее зелье не сбрасывает независимое состояние зарядов Paper-обработчика.

Сохраняются explosion 1, flame 10 со spread 0.5 и исходным extra 1.0, звук взрыва volume 1.5/pitch 2,
а также строка actionbar с четырьмя пробелами, glyph E173, белыми числом зарядов
и секундами до восстановления. Новых текстов и дополнений ресурспака нет.
Наблюдатели исключены по серверной роли. `stopper` в кубе 20 блоков подавляет
импульс; измерения `minecraft:nexus` и `minecraft:imprinted` исключены.

## Перенос способности

В сетках инвентаря 2×2 и верстака 3×3 действует нативный shapeless-рецепт
`skywars2:rocket_boots_transfer`: ровно один донор и одни обычные трансформируемые
ботинки в любых двух клетках. Лишние ингредиенты убирают результат.
Предпросмотр появляется в выходном слоте и не меняет ингредиенты.
Обычное взятие результата и Shift-клик расходуют по одному предмету через
ванильный `ResultSlot`; закрытие верстака возвращает исходные ингредиенты.
При заполненном инвентаре Shift-клик ничего не расходует.

Нативный `lbc:add_lore_rocket` сохраняет предмет получателя,
модель, характеристики, имя, старые lore/custom data и добавляет исходные три
строки lore, Paper marker и glider. Получатель требует `transformable:1,boots:1`.
Исправление пользователя в [аудите](ROCKET_BOOTS_SOURCE.md) запрещает повторный
перенос на уже ракетную пару и расходует ровно одного донора.

Рецепт доступен во время матча в мире арены. Пакеты изменения инвентаря
наблюдателей блокируются существующим ограничением роли. Ракетный донор
исключён из ванильного ремонта: иначе две кольчужные пары конкурируют с этим
рецептом и ремонт стирает custom components. Обычный ремонт без донора сохранён.
Рецепт специальный, без recipe-book display и регистрации синхронизации
кастомного сериализатора; клиент получает обычный ванильный предмет результата.

Перенос между выброшенными предметами также сохранён.
Брошенные доноры учитываются через ENTITY_LOAD/UNLOAD;
пространственный запрос раз в 20 тиков ищет получателя на расстоянии 0.001–1 блок.
Сохраняются прежние flame/iron-block частицы и звуки firecharge/anvil.

## Polymer

`LbcItems` регистрирует `skywars2:rocket_boots` до freeze реестров. Использован
готовый `SimplePolymerItem` с ванильным proxy `minecraft:chainmail_boots` и
`useModel=true`: двухаргументный конструктор скрывал бы исходный `item_model`.
Не добавлены собственный item-класс или обработчик сетевой подмены.
Стандартный конвертер Polymer передаёт модель, equippable, glider, damage,
атрибуты и имя; полный серверный стек хранится в служебных данных proxy.
Клиенту не требуется установка мода. Для прежнего оформления нужен прежний
ресурспак пользователя; его файлы не менялись и новые ресурсы не создавались.

Loot table сохраняет все прежние modifiers и меняет только registry ID
выдаваемого предмета. Для полной исходной выдачи вручную используется
`/loot give @s loot lbc:kit/explosive_feets`; `/give skywars2:rocket_boots`
создаёт базовый тип без оформления/характеристик из loot table.
Дополнение тега `minecraft:foot_armor` сохраняет участие нового типа
в обычных механиках зачарования ботинок. Результат переноса способности
на чужие ботинки сохраняет их тип: Polymer-предмет не подменяет получателя.

Polymer строит tooltip клиента по серверному tooltip и передаёт его как lore,
скрывая дублирующие ванильные строки атрибутов. Поэтому проверяется видимый
текст и итоговое оформление строк, а не равенство внутренних LORE компонентов
серверного предмета и клиентского proxy. Настоящий клиент остаётся отдельной
визуальной проверкой.

## Структура и CPU

Механика находится в существующем `LbcItems`. `PlayerMechanicsMixin` объединяет
прежний callback приземления и валидный glide-start; `LbcEquipmentMixin` сообщает
о смене ботинок через все `RETURN` нативного callback, включая ранний выход
на первом тике/после респауна. Общий `LbcCraftingRecipe` (прежний `RocketBootsRecipe`) подключает обычный механизм
крафта; `LbcCraftingResultMixin` запускает эффекты только при взятии результата,
а общий `LbcRepairRecipeMixin` устраняет конфликт с ремонтом. Собственного движка
транзакций, очереди изменений сетки и опроса инвентарей для крафта нет.

Заряды обновляются только у восстанавливающихся владельцев; HUD обновляется
раз в секунду у учтённых владельцев. Нет постоянного обхода всех инвентарей
или сущностей мира для поиска способности. Все изменения Minecraft выполняются
в серверном потоке; отдельный worker для физических сущностей не создаётся.
Эта структура сокращает лишние обходы, но ускорение CPU ещё не измерялось.

## Проверки

Предыдущая сборка с автоматическим изменением сетки: адресный
`smoke_lbc_loadouts.py --rocket-only` прошёл
за 69.83 с: source gate/GUI/выдача, перенос в сетке и на земле, расход одного донора,
запрет повторного улучшения, сохранение компонентов и оформления, три быстрых
импульса, четвёртая попытка без заряда, stopper в углу куба, элитры,
границы 300/301 тик, наблюдатель, смерть/респаун и очистка после остановки.
Полный regression baseline этой сборки также прошёл: пять матчей, 13 групп,
115.38 с. Проверенный JAR установлен с резервной копией предыдущего;
основной сервер оставлен остановленным. Артефакт, результаты и ограничения —
[SERVER_TESTS.md](../SERVER_TESTS.md). Серверные проверки не заменяют визуальную
сверку на настоящем клиенте и CPU-профиль под нагрузкой.

Нативный рецепт прошёл адресный сценарий за 82,74 с через настоящие InventoryMenu,
CraftingMenu и пакеты кликов: выходной слот, сохранение компонентов, лишний
ингредиент, повторное улучшение, обычный ремонт, заполненный инвентарь,
Shift-клик, закрытие верстака и запрет взятия результата наблюдателем.
Проверенная сборка установлена, основной сервер оставлен остановленным.
Результат актуального запуска — [SERVER_TESTS.md](../SERVER_TESTS.md).

После регистрации Polymer-предмета адресный прогон прошёл за 73,81 с.
Проверены выдача нового серверного типа, proxy кольчужных ботинок, передача
модели/брони/glider/износа/имени, итоговый текст и оформление tooltip,
сохранение переводов, обратное восстановление серверного стека и крафт
с настоящим Polymer-донором. Игровые rocket/observer/lifecycle проверки
также повторно прошли. Точный артефакт установлен с резервной копией.
