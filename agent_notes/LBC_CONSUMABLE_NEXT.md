# LBC consumables: наборы 2 и 17

Аудит только для `lbc:kit/3_purify_potion` и `lbc:kit/brbad`; исходный datapack, старый Paper и Ignite, новый Fabric и resource pack сверены read-only. Это описание наблюдаемого source-поведения, не подтверждение работающего нового порта.

## Набор 2 — `3_purify_potion`

- Выдача: [kit/3_purify_potion.json](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/kit/3_purify_potion.json) имеет три пула с фиксированным числом выдач: 3 очищающих зелья, 3 ведра молока, 4 взрывных зелья лечения. Последнее — `minecraft:instant_health`, amplifier `5` (эффект уровня VI), цвет `16739179`, максимум стопки 4 и `item.minecraft.splash_potion.effect.healing` с `italic:false`.
- Пул очищения ссылается на [purifypotion_1.json](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/purifypotion_1.json): один `minecraft:splash_potion`, цвет `16777215`, custom effect `minecraft:raid_omen`, amplifier `43`, duration `100`, частицы выключены. У предмета скрыт `potion_contents`, `tooltip_style=lbc:tier_b`, custom data `{transformable:1,potion:1}`. Lore-компоненты упорядочены так: `type` aqua, `potion.lbc` aqua, `purification_potion.lore` white; имя `purification_potion`; у всех указано `italic:false`.
- **Sentinel и callback.** Датапак не обнаруживает custom data очищающего зелья при применении. Фактический триггер — критерий `minecraft:effects_changed` у advancement [purify.json](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/advancement/purify.json), когда на игроке появился `minecraft:raid_omen` amplifier `43`. Критерий исключает измерения `minecraft:nexus` и `minecraft:imprinted`; advancements применимы к игрокам, не мобам. Это эффектовый receiver после попадания/добавления эффекта, а не `PlayerItemConsume`/`Consumable.onConsume` (зелье бросают).
- Награда вызывает [other/purify.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/other/purify.mcfunction): сначала очищает все активные эффекты, удаляет `lightningist` и `greed_cursed`, затем сбрасывает большой набор scoreboard-состояний и в конце отзывает `lbc:purify`, чтобы триггер снова был доступен. Это run-state очистка LBC-способностей, а не удаление выбранного набора/навыка игрока. При переносе сопоставить сбрасываемые score/tag только существующему native runtime state; не удалять сохранённые выборы и не придумывать cooldown state для незапортированных движков.
- Соседняя цепочка: [true_advancements/potions/purify.json](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/advancement/true_advancements/potions/purify.json) отдельно выдаёт достижение по `minecraft:inventory_changed` за наличие предмета с цветом `16777215`, raid_omen amplifier `43`, duration `100`, `show_particles:false` и custom data `{transformable:1,potion:1}`. Оно не ожидает попадания/эффекта. При переносе не смешивать inventory-reward с очисткой по effect-added.

## Набор 17 — `brbad`

- [kit/brbad.json](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/kit/brbad.json) содержит по одному каждому из четырёх `minecraft:lingering_potion`. Во всех `potion_contents` скрыт в подсказке; name и одна строка lore используют translate key и `italic:false`.
- Их sentinel-эффекты все имеют ID `minecraft:raid_omen`, duration `20` тиков и различаются amplifier/color/key: `234` / `3672329` / `termit`, `235` / `16760906` / `sulfur`, `236` / `10197915` / `phosphin`, `237` / `16777215` / `gremuch`. Это не обычные raid-omen бафы. Локальные ключи и точный текст уже существуют в пользовательском pack (`assets/minecraft/lang/{ru_ru,en_us}.json`): `termit`/`termit.lore`, `sulfur`/`.lore`, `phosphin`/`.lore`, `gremuch`/`.lore`. Не создавать дубли переводов.
- Реакция срабатывает на lingering cloud, а не на исходный item use: [tick_not_timestopped.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/tick_not_timestopped.mcfunction) каждый тик выбирает `area_effect_cloud` с `raid_omen`, [raycastselector_area_cloud.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/raycastselector_area_cloud.mcfunction) читает amplifier и маршрутизирует signed-byte значения `-22..-19` к четырём handler-ам соответственно. Это соответствует byte-представлению `234..237`; при портировании сверить именно фактический NBT/API тип amplifier.
- Поведение/вторичные зависимости: `termit_tick` увеличивает cloud `Lifetime`, на каждом тике с радиусом, растущим через `Lifetime`, вызывает `termit_tick_storage`: преобразует блоки в радиусе вплоть до 80 блоков (nylium/logs/leaves/shroomlight/soulsand/magma/netherrack/liquids/air->fire/to-lava), наносит `4` lava damage мобам в радиусе `tmp1`, создаёт частицы/звук (звук шанс `20%`). Зависимости: block tags `to_nylium`, `logs`, `leaves`, `to_shroomlight`, `to_soulsand`, `to_magma`, `to_netherrack`, `fluids`, `airs_to_fire`, `to_lava`, `solid`, плюс `minecraft:mobs`.
- `sulfur_tick`: каждый cloud tick создаёт sneeze particles, с шансом `3%` вызывает `lbc:drops/muravei_acid`, даёт наземным целям в радиусе 6 Slowness IV на 2 тика и Wither I на 10 тиков; требует drop/кислотную систему LBC. `phosphin_tick`: каждому `#minecraft:mobs` в радиусе 8 постоянно обновляет Poison I, Wither I, Weakness I и Slowness I по 10 тиков. `gremuch_tick`: вызывает TNT с fuse `2s`, затем сразу убивает cloud; при штатном вызове срабатывает один раз. Источники обработчиков: [effects/termit_tick.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/effects/termit_tick.mcfunction), [termit_tick_storage.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/effects/termit_tick_storage.mcfunction), [sulfur_tick.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/effects/sulfur_tick.mcfunction), [phosphin_tick.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/effects/phosphin_tick.mcfunction), [gremuch_tick.mcfunction](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/effects/gremuch_tick.mcfunction). Clouds без явного `kill` живут/истекают по vanilla lifetime.

## Нативные точки и степень самостоятельности

- В новом Fabric-проекте есть `ConsumableSkillMixin` для еды/выпиваемых consumables, но поиском Java Mixins не найден receiver на `LivingEntity.addEffect`; одного consume callback для очищающего splash potion недостаточно. Самостоятельный native callback для purifier возможен на успешном добавлении sentinel effect игроку с условиями advancement (не мобы, не nexus/imprinted), затем применяет только существующую игровую state-cleanup семантику. Он не требует реализации других LBC предметов; нужен аккуратный список уже существующих runtime полей из исходного reset-list, а не фиктивные cooldown поля.
- На старом Paper найден только общий `SwrgNativeService.hasRaidOmenEffect` -> native mobs tick dispatch в `projectiles/arrows2`; отдельной Java-реализации purge или четырёх brbad handlers нет. Старый Ignite содержит лишь unrelated Bedwars mixin.
- Для `brbad` нативный event по броску/добавлению эффекта не покрывает полный source: нужны облачный lifecycle/tick, четыре sentinel dispatcher-а, ticking block damage/effects/random drop/TNT и соответствующие block/entity tags. Поэтому набор 17 нельзя считать полностью перенесённым автономно как «четыре лута»; это отдельная механика, зависящая от нескольких LBC-систем. Относительно набора 2 он существенно шире.

## Вывод

Набор 2 — лучший самостоятельный следующий native slice: его фиксированную выдачу можно оставить loot-table-driven, а очищение прикрепить к `addEffect` receiver и воспроизвести текущие reset side effects только для реально имеющегося состояния. До реализации нужно сопоставить scoreboard reset-list с runtime state нового проекта. Набор 17 отдельно не полностью реализуем без облачного движка, урона, изменений блоков, mob эффекта и LBC acid drop. Исходных доказательств ошибки в старом datapack здесь не обнаружено; его скрытая sentinel-маршрутизация намеренная и подтверждается signed-byte dispatcher-ом.


## Проверка native slice (11 октября 2026)

Read-only сверка текущих новых файлов: [LbcItems.java](../src/main/java/me/skywars2/game/LbcItems.java), [LbcEffectTriggerMixin.java](../src/main/java/me/skywars2/mixin/LbcEffectTriggerMixin.java), [import_lbc_loadouts.py](../tools/import_lbc_loadouts.py), `data/lbc/loot_table/kit/{broken_totem,3_purify_potion}.json` и `data/lbc/loot_table/purifypotion_1.json` против read-only datapack.

- Три loot JSON совпадают с источником по item IDs, количеству, potion/custom data, цветам, эффектам, моделям, имени, lore-компонентам и стилям. Единственное структурное преобразование — целевое обновление codec: `function`→`type`, `functions`→`modifier`; payload исходных операций сохранён. `broken_totem` сохраняет model `lbc:broken_totem`, name `broken_totem` с `italic:false`, custom data `{broken_totem:1}`. Purifier table также сохраняет hidden `potion_contents`, tier B tooltip style, точные переводы/цвета lore и `{transformable:1,potion:1}`.
- `LbcEffectTriggerMixin` внедрён в хвост `EffectsChangedTrigger.trigger(ServerPlayer, Entity)`, поэтому receiver только для игроков и вызывается при любом player effect-change источнике; `LbcItems.effectsChanged` отфильтровывает всё, кроме действующего `raid_omen` amplifier 43. Это не прямой mixin к `LivingEntity.addEffect`, и мобов/их облака сама purge-логика не обходит.
- Пурж удаляет эффекты, два исходных curse-тега и временную карту `turnCurses`; он не вызывает `LbcLoadouts.clear`, не трогает `PlayerStore`, выбранные kit/skill/levelups или attribute modifiers. Это верно сохраняет границу между временной runtime state и сохранёнными выборами/levelups. Побочный эффект `removeAllEffects` намеренно снимает активный Resistance пассивного навыка, как исходный `effect clear`.
- Расхождение для решения: исходный advancement фильтрует только `nexus` и `imprinted`; текущий `LbcItems.active` дополнительно требует `game.allowDamage(player)` и запрещает `awaitingRespawn`. Следовательно новый receiver уже не очищает эффекты в иных состояниях, где advancement source очистил бы их. Также trigger исполняется для эффектовых изменений вообще, не только при application; точный amplifier guard делает реакцию узкой.
