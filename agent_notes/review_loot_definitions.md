# Независимая строгая сверка loot definitions

Проверил все 669 источников из research_jobs.json. Это 666 корректных JSON-таблиц и три специальных/нечитаемых как loot JSON источника: custom_data_list.txt (список custom_data), tagscraper.py (генератор этого списка) и пустой 0-байтовый reroll_9999/material_block.json. Для последнего основная заметка правильно фиксирует отсутствие определения дропа; поиск буквальных ссылок на него в пакете не нашёл вызовов. Все специальные источники имеют отдельные секции в основной заметке.

Структурный аудит 666 JSON сопоставил таблицы с секциями основной заметки: все 828 pools и все 7 680 прямых entries найдены в совпадающих количествах. Проверены 12 194 function records: для каждого пула число записанных изменений совпадает с суммой функций entries и самого pool; отдельно для всех 666 таблиц совпадает число table-level функций. Это учитывает opbook, где одна pool-level функция описана после entry. Все 13 712 числовых значений JSON встречаются в секции своей таблицы.

Проверены вложенные loot-table references: 747 ссылок (369 уникальных ID) в JSON отражены в секциях; разрешение по всему LBC datapack дало 0 отсутствующих таблиц. Вложенные условия/функции/параметры компонентов представлены в карточках; веса, rolls, bonus_rolls, count/UniformNumber, random_chance, score/value_check и порядок применения изменяющих функций сохранены таблицей. Основной контракт правильно поясняет, что веса не равны конечным процентам, а эффект складывается по уровням entry → pool → table. В этой проверке scope ограничен definitions JSON и их ссылками на loot tables; карточки отделяют их от function callers, которые не являются частью выдачи таблицы.

Строгие проверки: JSON parse; соответствие source → точный section heading; совпадение количества pools/entries; соответствие счётчиков entry/pool/table functions; числовые поля в соответствующих секциях; вложенные LBC table IDs и разрешение ID по полному набору пакета. В исходники и coverage не вносились изменения, content_reviewed не менялся.
