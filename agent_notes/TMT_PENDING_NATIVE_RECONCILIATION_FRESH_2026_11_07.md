## Smallest coherent next adapter: retained loose copier + tablets2/3/4

Concrete producer evidence in OLD LBC functions:

- items_tick_tag:13/15-17 and27-30 mark copypaster and multiply2/3/4 physical
  ItemEntities as working; items_tick:3 dispatches copier; items_tick_act:8
  dispatches multiply_select against a nearby physical donor.
- items_copypaster:1-5 copies the donor's whole Item and copier Motion, retaining
  donor; remaining lines debit one copier. Source multiply_select dispatches
  exact integer2/3/4 modes. The native tablet engine already owns approved
  no-op/quantity/component rules; do not rewrite that engine from commands.
- TMT source lottery explicitly includes copypaster1 (set_storage_nbttags:101)
  and multiply2/3/4 (:397-399). multiply5 (:400) has no corresponding source
  physical working-item branch here; do not silently admit it as a fourth mode.

Actual current owner path: `LbcItems.entityLoaded:1610` calls
`LbcLooseRewards.loaded`, which indexes only actual public copier/tablet flags;
`LbcItems` tick invokes looseRewards.tick; that calls copy/tablet and rechecks the
flags every work quantum. copy:48+ preserves complete donor stack/components,
nearest donor, donor survival, copier motion, original thrower/source and one
carrier debit. tablet:75+ handles native default attributes, direct enchantments
and split triple quantities, keeping no-op donors/tablets unchanged.
`LooseRewardChecks` and `TabletGroundChecks` contain real ordinary owner tests
(source prototypes, no-target/no-op, full metadata, cadence), not TMT closure.

Missing adapter is therefore concrete: read-only private-property admission to
the existing loaded index plus retained selected source replay at each real
copy/tablet work quantum. One temporary projection during ENTITY_LOAD is
insufficient because subsequent ticks reread item data. Preserve actual ItemEntity,
donor selection, source coordinates/motion/epoch, ordinary owner policies,
physical single debit, private sibling payloads, failure remainder and rewind.
Reuse LbcTmtAbilities invocation and native dropped-token source/debit patterns;
do not create another independent loose scheduler. LbcSpecialDrops already has
private admission/work/debit staging, but its nativeRecognized list does not
include copier/tablets, and those actual owners are LbcLooseRewards.

Catalog also needs explicit typed integer multiply recognition: multiply is
currently in SERVICE prerequisite keys, so the pending native rows display
keys=[] despite meaningful payload2/3/4. It is not the inert multiplying armor
category. Admit only source-supported payloads through the new real boundary.

Why before the alternatives: charged trident needs genuine charge/release and
wet/dry/native projectile/pickup behavior across five non-trident TMT carriers.
Magnum ammo needs selected-mode inventory query and exactly one real debit before
its accepted burst; LbcMagnum:134-137 currently only matches public custom data.
Both are genuine later adapters, larger than replaying one existing loose owner.
Broader Academy/BadApple/encounter lifecycle integration should follow separately;
protected Academy source must not be edited or compiled merely to simplify this.

This is a proposal and source reconciliation, not native qualification. Existing
weighted loot, all-item logical pools, public gates and author checklist remain
unchanged.
