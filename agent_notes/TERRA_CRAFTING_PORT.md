# Нативные рецепты Terra и Razorterra

## Требования (user)

> да, исправить расход, и сделать крафт полноценным крафтом (чтоб и в воркбенче работало) и закрепи для последующих крафтов это

Проектное правило закреплено в [AGENTS.md](../AGENTS.md) для всех следующих
крафтов. Источники: [TERRA_RECIPES_SOURCE.md](TERRA_RECIPES_SOURCE.md).

## Рецепты

| Два занятых слота в любом порядке | Результат |
| --- | --- |
| Tiny Terra + Tiny Terra | Обычный Terra Wand |
| Terra Wand + Terra Sword | True Terra Sword |
| Terra Wand + обычный Razorpine | Razorterra |

Работают сетка игрока 2×2 и верстак 3×3. Результат находится в выходном
слоте; предметы не выбрасываются. На один результат расходуется один предмет
из каждого из двух входных слотов. Остатки стопок остаются. Два Tiny Terra
нужно разложить по двум слотам: стопка из двух в одном слоте — не рецепт.
Любой третий занятый слот отменяет рецепт. Уже улучшенные результаты
повторно не пробуждаются. Academy Terra имеет исходный `stterra` и также
подходит как донор жезла, как в исходнике.

Результат — новый предмет из прежней таблицы добычи; компоненты доноров,
их урон/зачарования/добавленные способности не копируются. Это соответствует
исходной выдаче нового loot. Сохраняются исходные name/lore/tooltip/model.
Обычный Razorpine принимается по прежнему `custom_data.razorpine`; его
обычная стрельба и источник из transformables_shooter не включены в этот этап.
Проверка рецепта не выдаёт ему отсутствующую обычную способность.

## Общая реализация

`LbcCraftingRecipe` заменяет узкий RocketBootsRecipe, сохраняя старый
serializer/recipe ID ракетных ботинок. Он обслуживает четыре варианта,
не создавая отдельный класс для каждого рецепта. Matches/assemble читают
вход и строят preview; расход выполняет vanilla ResultSlot. Нативное взятие
результата через `LbcCraftingResultMixin` запускает исходные частицы и звук.
Просмотр результата и закрытие сетки не запускают эффектов.
Дополнительного обработчика ground-крафта или tick-сканера нет.
`LbcRepairRecipeMixin` не позволяет ванильной починке перехватить две Tiny Terra.
Два обычных Terra не составляют рецепт улучшения; обычная ванильная починка
такой пары остаётся доступна.

## Razorterra

Polymer-предмет `skywars2:terra_razorpine`, loot
`lbc:ported/terra_razorpine`, прежняя модель предмета `lbc:terra_razorpine`.
Снаряд использует указанную пользователем модель `lbc:terrasword_true_beam`.
Существующий `LbcTerra` обслуживает движение, модель и hitbox без нового
движка: скорость 7.5 блока/тик, 17 cactus-урона, разброс yaw/pitch ±3°,
10 рабочих тиков жизни (до 75 блоков). Как у остальных быстрых Terra, возможны пробитие
существ и обычный hurt cooldown. Препятствие завершает полёт и создаёт
исходные цветы; отсутствующий чанк не загружается.

Выстрел бесплатный: мана и боеприпасы не расходуются. Только ПКМ использует
native Item.use; Razorterra не запускается от ЛКМ или ServerboundPunchPacket.
Main-hand имеет приоритет, иначе ПКМ может использовать offhand при включённом
offhandWands. У чужого предмета с
перенесённым `razorterra` используется та же способность без смены его дизайна.
На ПКМ основная рука при включённом offhandWands также обрабатывает
Razorterra/жезл во второй руке. Отдельная дуга Terra Sword, вызванная
попаданием ближней атаки, сохраняет свой melee/LMB-триггер.

Старый datapack подтверждает input по использованию предмета: `load.mcfunction`
задаёт `RC_Raycast` как `minecraft.used:minecraft.carrot_on_a_stick`,
`players_tick.mcfunction` вызывает `items/spells` при положительном score,
а `interaction_rightclickable.json` использует `minecraft:player_interacted_with_entity`
и reward `items/spells`. В `items/spells.mcfunction` ветка `spell1_left`
проверяет `weapon.offhand`; `_left` означает левую руку, не ЛКМ. Legacy
вызов Razorterra находится в `spell1_default.mcfunction:57`, а offhand-вариант
в `spell1_default_left.mcfunction:47`.

Магический щит (user):

> Останавливать магическим щитом, как остальные Terra-снаряды

Срок жизни (user):

> 10 тиков — исправить отсчёт по значению исходника, до 75 блоков

В исходнике `lifetime:10` не отсчитывался из-за отсутствующего marker_2t;
в новой реализации срок должен действительно ограничивать полёт.

Это целевое отличие от отсутствующего старого shield-тега. Применяется
общая проверка `LbcTerra` на границе щита. Роль наблюдателя, союзники,
заморозка, остановка времени и подавление используют существующие проверки.
Исключений по Creative/developer нет. Нативный урон имеет настоящего автора;
дальнейшее падение использует общий `LbcIndirectKills`.

Для модели сохранены текущие пользовательские настройки масштаба остальных
Terra; новый вариант использует ориентацию дуги TRUE_BEAM. Visual lead,
interpolation/teleport duration=1 и короткое окончание визуала общие.

## Проверка

Build и четыре native suite прошли на JAR `5a0aacc1…`: крафты, Razorterra,
оба Terra Sword и регрессия ракетных ботинок. [SERVER_TESTS.md](../SERVER_TESTS.md)
содержит результаты и статус готового JAR: основной сервер работает,
поэтому сборка подготовлена отдельно. Настоящий клиент не подключался.
