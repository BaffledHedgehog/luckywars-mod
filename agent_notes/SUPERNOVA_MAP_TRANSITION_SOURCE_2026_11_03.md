These map functions place templates (map/1 inspected) and set #map=0; this is not the ordinary new-game/reset pipeline. Then clear center roof, kill lobby markers outside Nexus, title outside Nexus, clear levitation and absorption from ALL nonspectators (including Nexus), slow falling/move/face/clear cage volume only nonspectators outside Nexus. No blanket death-to-alive conversion occurs: spectator players are excluded from spawn placement and remain spectators, unless another explicit near-spawn gamemode command catches them in raw start/1. Offline players are absent from @a. A player joining before delayed newworld runs participates according to their current online gamemode/dimension; no captured cohort exists.

Raw SWRG start/1 calls config (all-online reset_attributes), heals all, refills chests, resets game timer/stage schedules, and conditionally reruns trinket, vanilla kit, LBC kit, levelup, skill, challenge selectors for @a; sets game_started=1; start_after_all calls start_player for @a (skill on_game_start, remove darkness_player, get_team). No lives assignment or inventory clear here. Thus raw legacy can grant additional kit/perk payloads while preserving old inventory. reset_attributes resets attribute BASES, configured HP/PVP modifier, heals, zeroes swrg.death/removes dead tag; it does not itself remove every modifier or all effects.

## Existing Fabric owners and minimal reuse boundary

F/GameController.restartFromRune :796 -> stopMatch -> restoreLobby -> runeRestartPending -> requestStart(null,true). This is Nautiz's FULL round replacement, intentionally not a terrain-only transition. restoreLobby :874 stops Vanity, team colors, modifiers/items/events, clears LBC online state and participants, resets time/border/rules, transitions through lobby. begin :513 captures online cohort, clears/rebuilds participants, sets configured lives, resetPlayer (inventory/effects/XP/health/attributes and item state), increments games and adds start coins. Previously eliminated online spectators can enroll again; offline do not. Joining during active match never enrolls (join :276); joins while LOADING wait and become lobby/new-match members only according to begin's captured cohort. This is unsuitable unchanged for a same-match Supernova.

F/LbcImbaRunes :37 GlobalActions delegates restart/clearMap/addLives to LbcRuneGlobals, which delegates restart to that controller. Hagalaz clearMap is destructive sweep of fixed -192..192 XZ / 0..319 and epoch-bound shared terrain queue, plus entity cleanup. It neither selects nor pastes a replacement map and is not an appropriate full transition primitive.

F/MapManager.load(id,broken,Consumer<Result>) :491 is the existing canonical terrain replacement API. It validates manifest/templates/heights; asynchronously prepares templates; journals combined prior/target bounds before edits; removes old map entities, restores cages, releases arena forced chunks, clears prior map bounds, queues native paste, finishes through existing loading/lighting/chunk-ticket work and completion. It already owns spawn/look metadata, bounds, template caching, respawn-island images and safe queued placement. Reuse this loader and its completion; do not implement a second block reset/paste framework. It operates its arena level, not a blanket Nexus world clear.

F/MapManager.quickStartCandidates :333 returns numeric available catalog maps with actual player capacity and optional broken availability; it is the normal native random selection pool, not legacy fixed 56, and excludes nonnumeric local IDs. catalog(boolean)/catalog() can expose different sets. Selection policy must be explicit; blindly using requestStart(quick) adds full-match semantics and rewards. Existing source does not authorize silently choosing between exact fixed 56 and current native capacity-aware catalog.

There is no inspected existing controller API for **same-match** map replacement plus source-specific player reassignment/timer restart while retaining participant lives/inventory and scoped runtime state. Least change is a narrow GameController-owned event transition calling MapManager.load and remapping retained participants after completion, using existing player teleport/respawn metadata, stage timer/bar and chest/cage owners. The missing part is controller orchestration, not new map/reset storage. Do not invoke resetPlayer, restoreLobby, begin, startPlaying or restartFromRune wholesale: startPlaying resets resources, invokes lbc.apply/events.start and other start hooks; begin additionally destroys inventory and changes lives/profile stats. Preserve ownership of participants and profiles.

## Decisions requiring author clarification / scope gaps

1. Final policy: retain inventory/XP/lives and revive nobody, as effective source implies, or intentional fresh-match reset? Confirm kit/perk regrant: raw datapack grants again, registered Paper beginMatch does not.
2. Nexus isolation: author intent to leave Nexus players untouched conflicts with explicit unfiltered pre teleport and all-online reset/heal/effect removal. Need desired final native behavior, not guessed isolation.
3. Spectator/vanity/dead/offline/new join: preserve existing participant and observer membership, or include new online players? Raw selectors are execution-time, native ownership is explicit. Actual dead-screen players are not revived by removing dead tags.
4. Map choice: literal 1..56 versus current native eligible catalog, capacity and broken/Bedwars policy. Existing APIs support both explicit token load and normal pool; they do not settle intent.
5. Source stages restart, not just terrain; establish whether repeated stage rewards/events and active item/cooldown/jobs reset or survive. Raw final has no global reset; full native items.stop/epoch rollover would erase unrelated state and Nexus ecology.
6. Failure semantics: map busy/load failure, no valid map/capacity/spawns and disconnected or joined players during asynchronous preparation need controller policy. Existing loader has Result failure and ownership; source synchronous command sequence provides no reliable native answer.

No source claim here establishes full Supernova readiness. Natural Nexus/native chunk MOVE qualification remains separate from event creation, final map transition and this policy closure.
