## Confirmed damage order and hooks

`ServerPlayer.hurtServer(ServerLevel, DamageSource, float)` first checks invulnerability and `canHarmPlayer` for player attackers; then delegates to `Player.hurtServer`. `Player.hurtServer` performs its own invulnerability/dead checks and may modify amount for difficulty (peaceful/easy/hard), then delegates to `LivingEntity.hurtServer`. The player-only raw bonus therefore belongs at HEAD of `ServerPlayer.hurtServer`, editing its sole float argument once. It runs before the team check's eventual vanilla damage processing and before difficulty scaling, while preserving the same subsequent `Player` and `LivingEntity` path. Exact Mixin target: `ServerPlayer.hurtServer(ServerLevel, DamageSource, float): boolean`, `@ModifyVariable(at=@At("HEAD"), argsOnly=true, ordinal=0)` with an electric-source guard. Existing `ConductionDamageMixin` already targets `ServerPlayer.hurtServer`; co-locate the amount modifier there if retaining that class, or rename it as planned. No reflection or entity scan is needed.

Fabric's `ServerLivingEntityEvents.ALLOW_DAMAGE` source is documented pre-mitigation, and its actual mixin invokes the event at `LivingEntity.hurtServer` immediately before the `isSleeping()` call. It can cancel damage, not mutate amount. A shared helper checking electric identity and Techno equipment can return false from the callback for full immunity; it covers every LivingEntity and therefore also a ServerPlayer's inherited processing. This check occurs after earlier `isInvulnerableTo`, dead, and fire-resistance checks, but before sleeping handling and damage application. Keep the player-only raw multiplier in the ServerPlayer hook, separate from this common immunity.

`LivingEntity.hurtServer` source clamps negative damage to zero, applies item blocking, freezing/helmet adjustments, checks cooldown, then calls `actuallyHurt`. `actuallyHurt` runs `getDamageAfterArmorAbsorb` then `getDamageAfterMagicAbsorb`, then subtracts absorption. The latter retain armor/toughness, Resistance and Protection behavior unless their explicit bypass tags are used. No mod-specific post-armor raw mutation is in these vanilla sources. Do not hand-calculate defenses or add `bypasses_armor`, `bypasses_resistance`, `bypasses_effects`, or `bypasses_enchantments`.

## Vanilla damage type tags

`DamageTypeTags.java` declares exact tags `BYPASSES_COOLDOWN` and `NO_KNOCKBACK`. In `LivingEntity.hurtServer`, cooldown immunity is directly guarded by `!source.is(DamageTypeTags.BYPASSES_COOLDOWN)`, and the normal hurt knockback is directly guarded by `!source.is(DamageTypeTags.NO_KNOCKBACK)`. All three electric types inherit the alias referenced by the repository's `data/minecraft/tags/damage_type/bypasses_cooldown.json`. The repository's `data/minecraft/tags/damage_type/no_knockback.json` references `#skywars2:electric`, which groups all three electric types. Note: vanilla's tag suppresses `dealDefaultKnockback`; shield-specific/other independently issued knockback paths are outside this one check.

## Direct/team-safe versus conductor/team-harmful

`LbcWands` has distinct `skywars2:electro_bolt` and `skywars2:electro_conduction` types. `ConductionDamageMixin` wraps the `ServerPlayer.hurtServer` `canHarmPlayer` call and permits team damage only for conduction. Keep that exception keyed only to conduction; a common electric classification may be used for the player amount modifier, cooldown, knockback, and immunity without changing direct bolt's team-safe behavior. Current equipment matching convention is `minecraft:custom_data` in `LbcMagic`; `protectsLevitation` is not an electric immunity predicate and currently is private.

## Static review of current implementation (read-only)

Reviewed `LbcDamage.java`, `LbcDamageMixin.java`, the `ALLOW_DAMAGE` registration, electric tag, and cooldown/no-knockback tag resources against the exact 26.3 sources above; no build was run.

- `LbcDamageMixin`'s `@ModifyVariable(method="hurtServer", at=@At("HEAD"), argsOnly=true, ordinal=0)` targets `ServerPlayer.hurtServer(ServerLevel, DamageSource, float)`, whose exact 26.3 signature has one float argument. The `@Local(argsOnly=true) DamageSource` capture is an existing argument, not a computed local; MixinExtras local sugar supports argument capture at this point. The adjusted amount is handed once to the original method. `ServerPlayer` checks authorization then delegates to `Player.hurtServer`, which applies difficulty scaling then delegates to `LivingEntity.hurtServer`; armor/toughness, resistance, enchantment protection, and absorption are later. Thus the multiplier is once on incoming raw amount before vanilla defense calculations.
- `ALLOW_DAMAGE` returns false for the electric source when every armor slot matches either Techno or Techno Mk2. This is a full four-slot set rule and allows mixed Techno/Mk2 pieces. It cancels before LivingEntity's sleeping, noActionTime reset, blocking, damage cooldown, health/absorption, damage effects, and knockback logic. Native pre-damage bookkeeping still runs in `Player.hurtServer` before Fabric gets control: it resets `noActionTime` and calls `removeEntitiesOnShoulder()`. This does not let electric damage through or cause health/armor/cooldown/knockback effects; it is normal subclass prework rather than a failure of the requested damage immunity.
- `bypasses_cooldown.json` and `no_knockback.json` each now add only `#skywars2:electric` with `replace:false`; the native exact tag checks and alias definition support this narrow additive form. The base electric tag correctly includes the base, direct bolt, and conduction type, so all three receive those behaviors. Existing conduction-only PvP exception remains gated by `isConductionDamage`.
- `data/minecraft/tags/damage_type/is_projectile.json` lists `skywars2:electro_bolt`, preserving the existing approved direct Electro projectile classification. Its `replace:false` definition layers onto native projectile sources. This is intentional and is not a new behavioral regression from the electric cooldown/no-knockback changes.


## Native generic damage and armor test oracle

The exact 26.3 jar's `data/minecraft/tags/damage_type/bypasses_armor.json` includes `minecraft:generic`. Therefore a test that compares electric damage against a `DamageSource` built from `DamageTypes.GENERIC` is not a valid ordinary-armor baseline: vanilla generic skips armor/toughness, while electric damage intentionally retains them. The electric damage JSON's `message_id: "generic"` only selects death-message localization; it does not make its registry key `minecraft:generic` or inherit that type's tags. `minecraft:player_attack` is a suitable ordinary non-bypassing test source (its exact damage type entry has no `bypasses_armor` membership).
