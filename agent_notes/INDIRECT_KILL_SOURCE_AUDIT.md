# Indirect wand kill ownership audit

Read-only source audit, 2026-10-16. No code changed; no build or server was run.
Scope: Tiny Teleport, Tiny Ruby, Tiny Stone, Tiny Acid, their block/effect hooks,
death attribution, and existing native check fixtures.

## Current behavior and gap

- **Tiny Teleport:** `LbcWands.ray()` scans at most 101 points (`.35` each, 35 blocks), checking the first target cell before stopping at a non-`AIRS` block. `rayEnd(TELEPORT)` considers `LivingEntity`s passing the caster-relative `target` predicate, then the `MOBS` tag and either distance ≤2 or distance ≤12 plus intersection with the terminal unit cell. It applies native `LEVITATION` for **20 ticks, amplifier 30**, with the caster passed as effect source (`LbcWands.java:443-477,502-508`). It does not teleport the target. The short, extreme levitation can cause a later fall/void death; that later environmental damage has no wand owner in this code.
- **Tiny Ruby:** `rubyRay()` walks the same 35-block ray, samples each block once, calls `destroyBlock(pos, true, player, ...)`, then explicitly replaces it with AIR to remove fluids (`LbcWands.java:196-215`). It never checks living entities or which block was supporting them. `ArenaBlockMixin` observes successful `Level.setBlock` returns for map journaling and magic-beacon updates only; it does not retain actor/cause (`mixin/ArenaBlockMixin.java:15-30`). A later fall/void damage therefore loses Ruby ownership.
- **Tiny Stone:** terminal `rayEnd(STONE)` fills the inclusive `point ± (1,1,1)` cube with stone at strict flags, if each chunk is already loaded (`LbcWands.java:485-500`). It does not test whether a write changed AIR to collision or whether a living entity's bounding box now intersects a newly placed block. Later suffocation has no wand owner.
- **Tiny Acid:** `wandAcid()` emits six owned `AcidProjectile`s, each tagged `skywars2.wand.acid` and the match epoch (`LbcClouds.java:316-329`). Every `LbcClouds.tick()` advances age and applies the impact pulse (`:339-353,207-224`). Non-burning impact applies `POISON` **300 ticks, amplifier 0**; the wand path calls `addEffect(poison, projectile.getOwner())`. Burning wand Acid instead directly deals **3 ON_FIRE damage** per pulse with `DamageSource(direct=projectile, owner=projectile.getOwner())`; burning adds 3 extra lifetime ticks each tick, while the tracked age expires at 300 (`:377-401,339-353`). `acid_age` is a persistent integer entity attachment initialized to 1 and restored into `AcidState` on load (`:62-64,143-147`). The owner passed while applying vanilla poison is available at application, but no Acid-owned persistent target status/source ledger is kept for a later poison death. `ACID_STUCK` keeps a block-hit projectile stationary while pulses continue; it is not a living-target cause marker (`:77-84,96-107`).
- **Death scoring is player-only:** `ServerLivingEntityEvents.AFTER_DEATH` routes only `ServerPlayer` victims to `GameController.died`; that method credits a killer only from `damage.getEntity() instanceof ServerPlayer` (`SkyWars2.java:94-99`; `GameController.java:498-520`). Vanilla fall, void, and suffocation sources have no wand caster here. Existing direct Acid burning damage does retain owner as `DamageSource.getEntity()`.
- **All LivingEntity targeting:** `target()` for ray wands requires alive, nonremoved, nonallied, nonspectator entities and active eligibility for player targets. Teleport then additionally filters to `MOBS`; Acid pulse's `targets()` uses the same all-living/MOBS target family and wand owner/team exclusions (`LbcWands.java:528-533`; `LbcClouds.java:227-235,331-337`). Any future causal metadata should live on/against `LivingEntity`, not only `ServerPlayer`; player kill rewards can still be applied when an attributed death victim is a player.

## Narrow cause-marking points

- **Teleport:** mark only when `entity.addEffect(LEVITATION, player)` returns true. Carry victim→caster/cause with an expiry tied to the 20-tick effect window; do not mark every cast target candidate or every ray. To credit a later environmental death, consume only for matching fall/out-of-world damage while the mark is live.
- **Ruby:** mark only after a successful block removal, and only for living entities actually standing on that removed collision support (feet at the old collision top, horizontal footprint overlaps, grounded before removal). Do not mark entities along the ray or on blocks that Ruby sampled but did not successfully remove. The destructive call's `destroyBlock` result and subsequent successful AIR replacement are the local success gates.
- **Stone:** mark only living entities whose bounding boxes intersect a block that this terminal actually changed from non-colliding/AIR to colliding STONE. The bounded 27 writes and their `setBlock` return values provide an exact opportunity; do not mark all entities near the terminal or all targets that only triggered the ray.
- **Acid:** direct burning damage already carries owner. For poison, `addEffect(poison, owner)` is the current source hook, but eventual native poison damage needs explicit short-lived owner attribution if the desired behavior includes poison kills. Limit that mark to hostile living targets where the wand's poison application succeeds; preserve existing `muravei`, owner/team, observer, and player eligibility filters. Do not infer Acid cause merely from a projectile being nearby later.
- A narrow per-target, short-expiry cause record consumed at player fatal environmental damage/`died` is the smallest common place to translate these causes into kill credit. Clear/expire it on unrelated player damage, match stop, owner invalidation, and after use. `ArenaBlockMixin` is too generic to attribute a wand action by itself; if a block hook is reused, scope it only around the wand's individual writes and require a successful state change.

## Existing native checks to extend

- `GameChecks.checkWandsSecond()` already creates a real mob target and verifies Tiny Teleport's `LEVITATION` duration/amplifier, insufficient mana, observer filtering, and that the caster did not move (`GameChecks.java:7200-7253`). Extend the same cow fixture for effect-source success and a controlled fall/void death; the existing real player death/respawn pattern uses `deferredCheck` (`GameChecks.java:10278-10305,10933-10962`).
- `GameChecks.checkWandsThird()` already snapshots/restores ray corridor blocks and verifies Ruby drops/fluid/bedrock behavior; use its `originalBlocks`, clear corridor, and temporary-cow helpers for support-removal (`GameChecks.java:7387-7590`, especially `7440-7510`). Tiny Stone's exact 27-block cube check belongs to `checkWandsSecond()` (`GameChecks.java:6903-7253`, assertion at `7196`); extend that fixture with bounding-box overlap vs nearby controls. Add grounded-on-support vs adjacent/not-supported living controls before extending into native fall/void attribution.
- `GameChecks.checkWandsFourth()` verifies six owned Acid projectiles, native motion/collision, hostile-only poison, owner/ally immunity, and burning damage source `entity=owner`, `directEntity=projectile` (`GameChecks.java:8915-9155`, especially `9060-9083`). Reuse the existing projectile selection and `temporaryMobs` cleanup; add a poison-source/owner attribution regression rather than duplicating spawn infrastructure.
- `checkZoneBarrierLethal()` is the existing compact example for real lethal damage, `AFTER_DEATH`, life/death counters, native respawn and deferred assertions (`GameChecks.java:15224-15277`). It is useful for a player-victim attribution check, while the three wand checks should separately verify non-player `LivingEntity` cause marking.

## Evidence boundary

Source confirms the indirect triggers and current loss of owner information. It does not establish that existing server hooks already credit wand-caused environmental deaths; current `GameController.died()` reads only the final `DamageSource` entity. The causal ledger/marking points above are recommendations, not implemented behavior.
