# Razorpine runtime source audit

Read-only audit of the disabled legacy datapack at `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC`. This note records source behavior; the source folder is disabled and does not establish that the datapack was live on the old server.

## Provider and ammunition

- [`data/lbc/loot_table/razorpine_with_leaves.json`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/razorpine_with_leaves.json) provides a carrot-on-a-stick with item model `lbc:razorpine`, custom data `craftusable,transformable,shooter,magicwand,razorpine`, translated name/lore; its other pool gives 16 wheat seeds. [`data/lbc/loot_table/transformables_shooter.json`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/transformables_shooter.json) includes this table as an option. I found no separate LBC invocation proving it is naturally awarded.
- `data/minecraft/tags/item/razor_ammo_best.json` contains spruce leaves and spruce saplings. `razor_ammo.json` contains leaves, moss, saplings, seeds, flowers, grasses, and pale garden flora. [`razorpine_ammo_check.mcfunction`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/workingitems/razorpine_ammo_check.mcfunction) consumes one best-tag item first, falling back to one regular-tag item. Best ammo sets `coldown18b=20`; regular ammo sets `coldown18=20`. No mana cost. With no ammo, the function leaves both scores unchanged and spawns no arrow.

## Inputs, hands, and burst count

- Legacy input evidence: `data/lbc/function/load.mcfunction:8` defines `RC_Raycast` as `minecraft.used:minecraft.carrot_on_a_stick`, and `players_tick.mcfunction:19` calls `items/spells` when that use score is positive. `data/lbc/advancement/interaction_rightclickable.json` also uses the `minecraft:player_interacted_with_entity` trigger and rewards `items/spells`. In `items/spells.mcfunction`, `spell1` handles `SelectedItem` while `spell1_left` checks `weapon.offhand` and the left-hand-wands setting. Therefore `_left` means offhand RMB; the old LBC source found here provides no LMB activation route for Pine.
- RMB/mainhand route: `data/lbc/function/workingitems/spell1_default.mcfunction:41` requires Razorpine in `SelectedItem`, both `coldown18` and `coldown18b` below 1, and no nearby `stopper`; it calls the ammo check.
- RMB/offhand route: `data/lbc/function/workingitems/spell1_default_left.mcfunction:16` requires Razorpine in `weapon.offhand`; it tests `coldown18b` twice and does not test `coldown18` or `stopper` before the ammo check. This looks like a copy/paste bug: holding regular ammo and repeated offhand RMB activation can consume another regular ammo unit while its burst score is already running. The current port uses a shared queue and resolves this separately from the mouse-button binding.
- `items/changed_inventory/sel.mcfunction:65,69,77` sets `razorpine_active` if the item is in `hotbar.*` or `weapon.*`, and removes it only when absent from both. `players_2t.mcfunction:6` calls `other/workingitems/razorpine2t.mcfunction` for active players. Thus a weapon in main hand/offhand or elsewhere in hotbar keeps the repeated-fire loop active; shooting itself checks selected main hand and offhand separately.
- `razorpine2t.mcfunction` tests each of `coldown18` and `coldown18b` against `-2..` (score >= -2), calls the regular 3-arrow function for `coldown18` and the best 2-arrow function for `coldown18b`, then subtracts 4 from each score. Starting from 20, each ammo unit therefore produces volleys at 20, 16, 12, 8, 4, and 0: six volleys / 18 regular arrows or 12 best-ammo arrows, then score -4 stops the loop. `tick2t.mcfunction` reschedules itself after `2t`, so each step is every two ticks (six volleys span 12 ticks). No shot-side guard/reset exists. If both ammo channels become positive, both can fire in the same tick (five arrows total per tick).

## Arrow setup and lifecycle

- [`razorpine.mcfunction`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/workingitems/razorpine.mcfunction) makes three native `minecraft:arrow` entities per volley. Each gets `damage:0.5d`, tags `razorpine,prestart2,killedarrow`, custom azalea-leaf-break sound, and owner UUID copied from shooter. It copies shooter yaw/pitch into arrow Rotation and sets each Motion component to the aim component multiplied by 2 plus independent random offset in `[-0.3,+0.3]` (`random value -300..300` stored at scale 0.001). The repeated setup in [`razorpine2.mcfunction`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/workingitems/razorpine2.mcfunction) makes two arrows per volley with `damage:1.5d` and aim velocity multiplier 5, with the same per-axis spread. This leads to base/best ammo terminology mapping to regular 3-arrow weak volley and best 2-arrow fast/high-damage volley; note the earlier wrapper's branch actually calls regular function for `coldown18` and best function for `coldown18b`.
- Arrow source explicitly sets neither `pickup`, `PierceLevel`, critical flag, nor a pine hit/damage handler. Those properties follow vanilla arrow defaults. The `damage` NBT value is a projectile damage field, not a documented final target damage number. Vanilla arrow collision, crit behavior (not enabled here), pickup defaults, and shield handling should remain native unless new target requirements say otherwise.
- [`projectilestick.mcfunction`](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/projectilestick.mcfunction:3) dispatches arrows to `projectiles/pre.mcfunction`. `pre.mcfunction:17` calls `projectiles/prein.mcfunction` only when `inGround:1b`; `prein.mcfunction:8` then runs `kill @s[tag=killedarrow]`. Therefore the `killedarrow` tag does not kill a Razorpine arrow on its next airborne tick: it marks it for removal once the arrow is in ground. The old note claiming removal during `pre` is incorrect. No pine-specific entity-hit hook was found in this path. This tag is projectile cleanup, not saved player state.

## Migration helper boundary and audit leads

- There is no Java Razorpine implementation or registration found under `src/main/java/me/skywars2/game`; `LbcTerra.java` only consumes the `razorpine` flag as a crafting donor for the distinct `razorterra` item.
- Existing generic arrow tracking is in `src/main/java/me/skywars2/game/LbcMagic.java`: loaded/refresh entity-index registration (`loaded`, `refreshEntityIndexes`), removal (`unloaded`), per-tick `tickArrows`, and `intercept(..., NO_ARROWS)` for the no-arrows artifact. That hook enforces an unrelated arena ability; it is not a Razorpine projectile implementation. Reuse entity creation/tracking/owner conventions only if they exist in another shared projectile helper; do not repurpose the artifact interceptor as Pine-specific hit logic.
- Source attribution gap: arrows copy the shooter's UUID into native Owner, but the audit did not find a separate persistent attacker record or delayed-hit attribution hook for these arrows. Preserve native direct owner attribution and meet the project's shared delayed-kill attribution contract during migration.
- Suspicious datapack behavior to resolve before implementation: (1) offhand RMB checks `coldown18b` twice, apparently bypassing regular-ammo cooldown; (2) mainhand RMB has `stopper`, while offhand RMB does not; (3) selected/offhand shooting both consume ammo but the repeated wrapper can shoot both channels regardless of the current hand once scores are primed; (4) rare risk: arrow searches use broad tags and short distance/`limit=1` selectors, and the third weak arrow's owner selector uses `distance=..3` while other owner selectors use `..0.1`, potentially assigning the wrong nearby prestart arrow under simultaneous shots. These deserve an implementation decision; don't silently normalize them as intended design.




## Current shooter integration review

Read-only integration review of the migration implementation at audit time:

- `src/main/java/me/skywars2/game/LbcShooters.java` owns one six-volley queue per player and charges one ammo unit when it starts. Each volley emits once per currently held Pine (`hands()`), so two held Pine items double the same queue without a second ammo charge. `tick()` steps every two server ticks and pauses the queue during global/player time stop; it drops the pending queue when its owner is no longer active. `stop()` discards tracked arrows at match cleanup; player `forget()` drops only pending volleys and leaves already-fired native arrows in flight.
- `src/main/java/me/skywars2/mixin/WandProjectileMixin.java` checks both `LbcWands.canHit` and `LbcShooters.canHit` before entity impact, and forwards terminal `onHit` to `shooters.hit`. Generic `LbcWands.canHit` returns true for projectile types outside its fire/air tags; Pine owner/team eligibility then uses shared `LbcWands.target`. `shooters.hit` discards Pine-tagged arrows only for block collision, matching the legacy `prein` grounded-arrow removal without per-tick projectile NBT scans. `LbcItems.entityLoaded/entityUnloaded` register and unindex them.
- The review found a mixed-hand right-click gap before final integration: native Pine's item use bypassed the common offhand dispatcher. This was corrected by routing Pine item/legacy ability use through `LbcWands.use`, whose per-hand dispatch now recognizes Pine before mana checks. Thus Pine + wand share the existing RMB path, with offhand activation governed by the left-hand-wands setting. Legacy `_left` names refer to offhand dispatch, not LMB. The current input contract is RMB-only for wands and both Pine forms; Terra Sword's separate melee-triggered beam remains an LMB ability.
- No old Pine-specific trinket-on-shot hook was found: `LbcTrinkets.shot` is called only by `TrinketBowMixin` for bow/crossbow projectiles, and the audited Pine trigger/ammo/arrow functions have no equivalent call.
