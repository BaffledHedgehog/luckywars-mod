# Tiny Electro port review

Read-only review of `LbcWands.java`, `LbcItems.tick/stop`, `LbcMagic.suppressedAt` and local Minecraft 26.3 sources. Runtime/build checks were not run here.

## Findings

- **Shield sequencing was corrected after review and user clarification.** The old datapack's shield advancement separately killed the marker; it could not undo damage already applied by earlier recursive samples. The first port incorrectly cancelled all effects of a two-block segment if any later point met a shield. The user chose exact stopping at the protective boundary. `electroShield` now finds the nearest segment/sphere entry; `electroStep` clips movement, visuals and direct hits to it while retaining any earlier conductor pulse. Native-server assertions exercise a target before the boundary, one behind it and a conductor before it. Their runtime result is recorded separately in `WANDS_ELECTRO_CHECKS.md` / `SERVER_TESTS.md`.

- **Global time-stop threshold mismatch found and fixed by root during review.** Old `tick.mcfunction` skips the entire `tick_not_timestopped` pipeline for every `time_stopped >= 1`; `time_stop.mcfunction` sets 11 (powerful stop sets 21), and the once-per-second countdown leaves value 1 active until `datapack_enable` resets it. Core now checks `>=1` in `electroTimeStopped`, so the final active second pauses trace motion, age and conductor damage. Owner `time_stopped` tags also pause without consuming age.
- **The `nocd` source contract is repeated native damage, not manual cooldown clearing.** Old `dmg_bypl_0_5nocd` issues `/damage ... 0.5 arrow`; it does not write `hurtTime` or a cooldown field. Correction to the prior static review: the old vanilla `arrow`/`generic` entries visible in the source-tree `bypasses_cooldown.json` were not in the earlier mod JAR, so they were not live configuration. The current `processResources` allowlist includes the damage-type tag paths, whose source files now list only `skywars2:electro_bolt` and `skywars2:electro_conduction` for `bypasses_cooldown`, and only `skywars2:electro_bolt` for `is_projectile`; the new mod does not add a broad arrow/generic vanilla override. `data/skywars2/**` is also in the allowlist: `electro_bolt` carries arrow-like parameters (exhaustion `.01`, `message_id: arrow`, scaling `never`), while `electro_conduction` carries generic parameters (exhaustion `0`, `message_id: generic`, scaling `never`). This read-only update did not inspect a newly built JAR. In local 26.3 `LivingEntity.hurtServer`, the cooldown tag skips the `damageCooldownTime > 10` reduction branch (source lines 1212–23); accepted hits still reset native cooldown/hurt time. Port samples target-hit contact at 0.2 spacing, caps two targets per sample, and preserves distinct 0.5 hit calls, matching the stated requirement to keep damage proportional to segment contact length rather than aggregate it.
- **Conductive hits follow the explicit user choice, including when vanilla PvP/team friendly fire is disabled.** `electroConduction` uses a `DamageSource` carrying the custom `skywars2:electro_conduction` type with the owner as source entity. `ConductionDamageMixin` wraps the `ServerPlayer.hurtServer` `canHarmPlayer(attacker)` guard only when `LbcWands.isConductionDamage(source)` matches that type, letting this one damage route continue to native/Fabric damage handling. Other damage still calls the original guard; observer/gameplay eligibility remains checked before conductor damage. Direct segment hits use `skywars2:electro_bolt` and `target`, excluding owner/allies and observers; conductive damage includes owner/allies as requested. There is one conductor query/pulse per trace tick while the segment intersects conductive blocks; any conductive block is pass-through. Water is queried once per bolt per tick in the port, without the old datapack's duplicate water/non-air callback.
- **Job lifecycle and geometry have no further concrete defect found.** Each job retains owner, source level and epoch; every tick validates epoch/map level, owner level/alive/removed/gameplay eligibility, loaded chunk and magic suppression. `stop()` clears jobs without marker entities; the tick snapshots jobs so synchronous death/stop callbacks do not invalidate iteration. One step has 11 sample positions (`i=0..10`, ten 0.2 moves), checks shield along that segment, performs a native hitbox query once, then one optional conductor query. Non-conductive block contact clips the segment to the block face and ends the trace; a clear/conductive step moves exactly two blocks, turns yaw and pitch by independent ±8° random offsets, and expires after 40 completed steps. The source note's earlier “10 samples” wording was corrected to 11 positions / 10 moves.

Old datapack source contains `bigTesla` / `yellow_lightning` branches, but this Tiny Electro native port has no provider for those special mechanics; their inventory/craft-related behavior remains a separate deferred plan. This review does not claim those branches are ported. No performance benchmark or runtime pass is inferred from static review.
