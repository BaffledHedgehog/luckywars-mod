# Tiny Electro: ресурсная часть

Перенесена ровно одна запись из OLD LBC `world/datapacksdisabled/LBC/data/lbc/loot_table/random_sauvojen_wand_tiny.json` в `src/main/resources/data/lbc/loot_table/ported/tiny_electro_wand.json`. Источник и результат сверяются независимо по полному normalized payload; единственная ожидаемая замена — item ID `minecraft:carrot_on_a_stick` на `skywars2:tiny_electro_wand`. Предикат `stelectro_tiny:1` должен выбрать ровно одну запись.

Контракт предмета: proxy `minecraft:carrot_on_a_stick`, количество 1; custom data сохраняет исходные флаги `craftusable:1,transformable:1,staff:1,magicwand:1,cyberset:1,stelectro_tiny:1`; metadata wand — `stelectro_tiny`, cyberset 1, стоимость 100 маны. Компоненты выдачи включают `minecraft:item_model=lbc:st/electro_tiny`, `minecraft:tooltip_style=lbc:tier_a`, исходное имя `wand_electro_tiny` и полный порядок lore из source, включая динамический score `tiny_electro_wand_mana_use` в `lbc.math` и существующие translate keys.

Read-only RP содержит `assets/lbc/items/st/electro_tiny.json` → `lbc:item/st/electro_tiny`. Ключи `wand_electro_tiny` и `.lore.1`–`.lore.3` присутствуют в EN/RU; lore также использует существующие `type`, `staff`, `mana_on_activate`, `wand_electro.lore.4`–`.7`. Поэтому новые lang/template записи не нужны. Основная Electro-цепь здесь не исследовалась.

`tools/import_lbc_weapons.py` имеет узкий `import_electro_wand_resources()`; широкая генерация не запускалась. В allowlist добавлена только `data/lbc/loot_table/ported/tiny_electro_wand.json`; `tools/check_design_sources.py` сравнивает этот payload с источником и отчётно считает его отдельно. Независимая exact source-проверка прошла; общий `python tools/check_design_sources.py` завершился `design source check passed`, включая `nativeElectroWandPayloads: 1`.

## Yellow Lightning и источник Electro

`raycast_molnia.mcfunction` продолжает луч пока не встретит `mushroom_stem[down=false,east=false,north=false,south=false,up=false,west=false]` либо armor stand `tag=mom` в `distance..2`. В обоих случаях `lbcr:raycast_molnia_cunny{,_mom}` спаунит loot `lbc:yellow_lightning` и marker `electropissardy,instant`; `_mom` добавляет ещё `milf`. Значит, жёлтая молния — самостоятельный выдаваемый item, не только crafting ingredient: в OLD LBC recipe tree рецепта не найдено, а предмет также имеет собственную inventory/equipped-triggered механику и snowball (`tag=piss`) с hit handler.

Контракт `lbc:yellow_lightning` из `loot_table/yellow_lightning.json`: proxy `minecraft:repeating_command_block`, `item_model=lbc:yellow_lightning`, `tooltip_style=lbc:tier_b`, custom data `{yellow_lightning:1}`, имя/lore `yellow_lightning` / `yellow_lightning.lore`. Read-only RP item definition → `lbc:item/yellow_lightning`; модель `assets/lbc/models/item/yellow_lightning.json` наследует `minecraft:item/handheld`, текстура `minecraft:item/yellow_lightning.png` существует. Модель скрывает предмет scale `[0,0,0]` во всех четырёх hand-display transforms. EN: `Yellow Lightning` / `[Shishch's condemning sounds]`; RU: `Желтая молния` / `[осуждающие звуки Щища]`.

`electropissardy` — отдельный источник/consumer branch: `raycastselector_instant.mcfunction` направляет marker в `lbcr:raycast_molnia_cunny_2`, который выбирает `_loli` или `_milf`, иногда запускает `_sound`; обе стартовые функции вызывают `lbcr:dmgwithid_un_playeronly`, вручную выдают advancement `true_advancements/staffs/tesla` и убирают временные tags/marker. Сам Tesla advancement имеет `impossible` criterion. Это не dependency payload Tiny Electro. Его можно добавить одним выделенным branch к уже существующим нативным targeting/damage hooks без импорта всех provider branches, но простой loot/model import его не реализует. Yellow Lightning при полном переносе также требует отдельной active-item/inventory/tick/projectile-hit логики; считать её только ресурсной добавкой к Electro нельзя.
