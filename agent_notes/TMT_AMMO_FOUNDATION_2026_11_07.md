# TMT ammo descriptor foundation — 7 November 2026

Source implementation only; no build, JVM, fixture, installation or release claim.

`LbcTmtAmmoPayloads.install(game, owner, fired, acceptedFamily)` belongs before
physical expansion in the accepted TMT volley transaction. It resolves supported
native arrow properties, captures at most seven count-one source snapshots and
attaches them independently of actual ammunition. `fromSource` /
`installDescriptors` admit exact captured source components; `copyPayloads` handles
manual native child factories. Infinite-arrow economy is deliberately excluded.

The typed persistent attachment caches source color, variant and scaled effects
once. Each descriptor retains age, ground-terminal state and reactive/age tick
guards; save/restore rebases once-in-frame guards. Physical arrows retain accepted
cause until an actual owner change. Quiver clone images copy the independent state.

Real Arrow and other AbstractArrow tick/post-hurt/block hooks reuse Quiver's current
effect, terrain, trail and terminal owners. Payload expiry disables that property
while genuine projectile/pickup behavior remains authoritative. No extra ammo debit
or fabricated accepted hit occurs. IMBA physical expansion and old-double manual
copies explicitly copy descriptors.

Shulker conversion preserves exact actual ammo and stores descriptors in its existing
State copy/save/load/clone path. Actual native tick, accepted entity damage and block
contact dispatch the same Quiver helpers. Trapper children retain their original
non-recursive child behavior. Existing Shulker base damage remains authoritative.

`LbcBeamAmmo` captures descriptor state alongside real ammo, shares its existing
query/contact sets, copies and checkpoints that state, and delegates effects to
Quiver. Its existing detached Arrow is still only the native trinket context; no
extra virtual arrows are created for properties. `hasVariant(int)` and `variants()`
include real ammunition and all descriptor variants for scalar owner integration.
