# Оптимизации Fabric 26.3: первичная проверка источников

Проверено 2026-10-16. Цель: SkyWars (`Minecraft 26.3`, Fabric API `0.161.0+26.3`, Polymer `0.18.2+26.3`, Java 25). Проверялись страницы авторов и список версий Modrinth API `GET /v2/project/{id}/version?game_versions=["26.3"]&loaders=["fabric"]`; JAR не скачивались и не устанавливались. Наличие билда не означает совместимость с этим модом.

## Приоритет

1. **Lithium — `mc26.3-0.26.2-fabric`, release**, Modrinth version ID `xS0Q8LSi`, опубликован 2026-09-28. [Версия](https://modrinth.com/mod/lithium/version/xS0Q8LSi), [настройки mixin автора](https://github.com/CaffeineMC/lithium/blob/develop/lithium-fabric-mixin-config.md). Общие ускорения игровой логики, физики, ИИ, блоков, чанков; заявленная цель — сохранить ванильную механику, но отдельные оптимизации имеют оговорённые отличия. Особенно важно: включённые по умолчанию `mixin.world.explosions.block_raycast` и `...entity_raycast` ускоряют raycast разрушения и расчёт экспозиции сущностей. Подопция `...block_raycast.skip_air` прямо документирует неванильное поведение: взрыв пропускает air-блоки и тем самым может пропустить особую логику, которая защищает воздух (пример автора — рельса над пустотой при TNT-вагонетке); некоторые блоки, поставленные во время взрыва, тоже могут вести себя иначе. Для SkyWars высокий риск механического пересечения: `HazardPropagationMixins$Blast` патчит `ServerExplosion.calculateExplodedPositions`, оборачивает `ExplosionDamageCalculator.shouldBlockExplode`; также оборачивает `ServerLevel.getEntities` в `hurtEntities` и `ServerExplosion.explode`. Это прямой участок кастомного TNT, фильтрации целей и наследования kill attribution. Не подтверждено, что совместный запуск ломается; требуется отдельный тест цепочек TNT, волн/массовых взрывов, отбора целей и источника урона. Lithium позволяет отключать отдельные mixin-настройки; начинать можно с отключения explosion raycast, если тест обнаружит расхождение.

2. **Moonrise — `v1.2.0`, релиз для Minecraft 26.3**, авторский GitHub release от 2026-09-27 (`61c1328`, changelog: обновление на 26.3). [Репозиторий и README](https://github.com/Tuinity/Moonrise), [релиз](https://github.com/Tuinity/Moonrise/releases/tag/v1.2.0). README перечисляет оптимизацию движения/столкновений/физики/трекинга сущностей, тиков/загрузки/генерации/сохранения чанков, доступа к блокам и сущностям. Автор говорит, что изменения стремятся сохранить ванильное поведение; сам README указывает: **Lithium и FerriteCore объявлены совместимыми с автоматическим отключением перекрывающихся частей**, но этот механизм надо проверять на каждой паре релизов; **C2ME объявлен несовместимым**, т.к. заменяет ту же систему чанков. Приоритет для TPS потенциально высокий, риск интеграции средний/высокий из-за широкого покрытия. Пересечения в SkyWars: explosion raycast, поиск сущностей и `Entity`-урон/молния; точные конфликтующие mixin точки без разбора JAR не подтверждены. Есть именно официальный GitHub релиз; Modrinth API не подтвердил версию Moonrise, поэтому сторонние зеркала не использовались как доказательство.

3. **FerriteCore — `9.0.0-fabric`, release**, Modrinth version ID `d5ddUdiB`, опубликован 2026-03-24; заявлен для 26.1/26.2/26.3. [Версия](https://modrinth.com/mod/ferrite-core/version/d5ddUdiB), [авторская документация изменений](https://github.com/malte0811/FerriteCore/blob/26.1/summary.md). Основной профиль — уменьшение потребления памяти за счёт представления/дедупликации данных, а не прямое снижение TPS; серверная установка имеет смысл при давлении на heap. README Moonrise объявляет автоматическое отключение перекрывающихся участков, однако требует проверять связку на текущих релизах. Вмешательство в память/структуры блок-состояний потенциально широко, но прямого пересечения с TNT mixin не установлено. Для механик риск ниже, чем у Lithium/C2ME, но совместимость с модом не проверена.

4. **ServerCore — `1.5.20+26.3`, release**, Modrinth version ID `LCG1Bm84`, опубликован 2026-09-16. [Версия](https://modrinth.com/mod/servercore/version/LCG1Bm84), [changelog автора](https://github.com/Wesley1808/ServerCore/blob/main/CHANGELOG.md). Серверные патчи против лагов/спайков; конфигурируемые activation range, spawning/mobcaps и прочие настройки могут менять игровое поведение. Автор утверждает, что значения по умолчанию не меняют vanilla behavior; это не гарантия для включённых опций и не гарантия работы с SkyWars. Потенциально проще изолировать настройки, начать с defaults. Прямой конфликт с TNT точками этого мода не подтверждён.

5. **VMP — `0.2.0+beta.7.238+26.3`, prerelease (`alpha`)**, Modrinth project ID `wnEe9KBa`, опубликован 2026-09-15. [Официальная Modrinth-страница](https://modrinth.com/mod/vmp-fabric), [репозиторий автора](https://github.com/RelativityMC/VMP-fabric). Проект нацелен на высокое число игроков: карты областей и кэши для player/entity lookup/tracking, оптимизации natural spawning, entity collision, chunk send и сети. Репозиторий прямо предупреждает, что VMP всё ещё ранней разработки и поведение может ломаться; рекомендация автора использовать совместно с Lithium. Для обычного небольшого матча выигрыш не подтверждён; транспорт/трекинг и структурные кэши затрагивают много систем. С Polymer/network packet rewriting нет подтверждённого конфликта, но это требует проверки реального логина, чанков, наблюдателей и отправки кастомных пакетов.

6. **C2ME — `0.4.2-alpha.0.104+26.3`, alpha**, Modrinth version ID `s5lf4njU`, опубликован 2026-10-15. [Версия](https://modrinth.com/mod/c2me-fabric/version/s5lf4njU), [репозиторий автора](https://github.com/RelativityMC/C2ME-fabric). Ускоряет generation, IO и loading чанков параллельной/асинхронной работой. Релиз для 26.3 найден, но это alpha; тестовая нагрузка и композируемость важнее обещаний. Повышенный риск порядка выполнения/совместимости модов, работающих с миром и chunk lifecycle. Особенно: Moonrise прямо объявляет C2ME несовместимым. Не выбирать вместе с Moonrise; даже по отдельности — только на копии карты с нагрузочными тестами.

## Практический вывод

Самая узкая стартовая оценка: сначала проверить Lithium на TNT, потому что он наиболее непосредственно покрывает проблемную стоимость explosions; затем сравнить Moonrise как широкий альтернативный набор оптимизаций, не подключая его одновременно с C2ME. FerriteCore — низкорисковый кандидат при проблемах памяти. ServerCore использовать с дефолтным конфигом до осознанной настройки поведения. VMP/C2ME оставить экспериментальными. Совместимость ни одного варианта с SkyWars/Polymer не подтверждена запуском или тестом; эти выводы только по описаниям и точкам исходного кода.
