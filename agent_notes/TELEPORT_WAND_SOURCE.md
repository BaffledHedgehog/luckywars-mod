# Teleport wand source audit

Scope: legacy datapack behavior read from `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/workingitems/sauvojen_staffs/teleport*.mcfunction`, its `lbcr` raycast functions, and Academy dispatch. This records source behavior; unusual values are not treated as design defects. Legacy paths below are read-only references.

## Ordinary wand cast

`items/libspells/select_wand.mcfunction` and `items/libspells/select.mcfunction` route spell 173 to `workingitems/sauvojen_staffs/teleport_preloop`. Normal cast dispatch is also in `workingitems/spell1_default.mcfunction` and `_left.mcfunction`; upgraded cast dispatch is in `spell1_upgraded.mcfunction` and `_left.mcfunction`. The dispatch requires at least `stteleport_wand_mana_use` mana and no `stopper_magic` marker within 20 blocks. `config.mcfunction` sets the cost to **3000 mana**. `teleport.mcfunction` calls the common preloop, subtracts that cost, applies the four-piece mage set maximum-mana bonus, and invokes the trinket cast hook when enabled.

The base wand fires a `raycastteleportwand` marker from the caster's eye direction. It copies caster `lbcID2` and `team_number`; marker `data.lifetime` is **200**. `lbc:raycastselector` increments `Lifetime` once each time the marker is processed by the tick function, then dispatches its ray function. The recursive 0.3-block ray steps happen within that one dispatch and do not increment `Lifetime`; the cap is therefore **200 processing ticks**, not 200 ray-step callbacks. `lbcr:raycast_teleport_wand` resets `Distance` at 7, so the marker advances **1.8 blocks per tick** (six moves) before continuing from its new position; it stops on a non-air block. Each step checks the selector volume (`dx=0,dy=0,dz=0`, one-block cube, also constrained by `distance=..10`) and calls `damagewithid8`, which applies the wand kick-up effect to up to two eligible targets found there, then calls the damage/kill helper. The mode-1 helper levitates the target, summons lightning, puts a 3×3 cobweb patch at Y+10, and emits falling-water particles.

## Academy upgrade and modes

The Academy trial starts from the NPC's generic `interacted_2.mcfunction`: it sets `upgradable:1` on the held item and dispatches `can_upgrade/stteleport.mcfunction` for `stteleport`. During a shift cast, `teleport_preloop.mcfunction` calls `teleport_preloop_upgrade.mcfunction` only when the held item's `upgradable` flag is set. Each such cast adds **5 shock** and has a **35%** chance (`lbc:chance35`) to call generic `other/magic_academy/can_upgrade`; that wrapper calls `can_upgrade_book` unless the item is an unstable spellbook. The generic ready path plays the experience sound, shows `can_upgrade`, sets `upgrade_available:1`, and clears `upgradable`. The cast still follows its ordinary mana charge path.

When the ready wand is clicked on the Academy NPC, `interacted_upgrade.mcfunction` applies the shared upgrade flags (`upgraded:1`, `mode:1`), adds the shared upgrade description, and then dispatches `upgrade/stteleport.mcfunction`. That family function shows `upgrade_succesful_stteleport` and applies tier A. Mode switching is separate from casting: the upgraded pre-use paths route sneak input to `other/magic_academy/change_mode_3.mcfunction` (main hand) or `_left.mcfunction` (offhand); these cycle `mode` through **1–3**, wrapping to 1, and tell the player the selected mode. The mode is read from the actual casting hand.

- **Mode 1, default:** `teleport_default.mcfunction` creates a `raycastteleportwand_fast` marker with `data.lifetime:200`. Its `lbcr` handler advances **0.3 blocks per step** and resets `Distance` at 11, giving **3.0 blocks per tick** (ten moves) until a solid block or the shared Lifetime cap ends it. Target selection/effects match the base marker.
- **Mode 2, inverted:** creates `raycastteleportwand_inverted`, also advances **3.0 blocks per tick** (ten moves of 0.3) before continuing from the new position. Its handler calls `damagewithid8_1`; `wand_teleport_kickdown.mcfunction` clones the 3×1×3 layer below the target down one block, replaces the source layer with cobweb, moves the target down 0.5, summons lightning, and emits cloud particles, followed by the shared damage/kill helper.
- **Mode 3, cloud:** `teleport_cloud.mcfunction` summons a no-gravity arrow tagged `rided`/`killedarrow`, aims it along the caster's view using `raycast_vpered_slower`, copies caster ID/team values, and mounts it under the caster. Projectile ticking calls `teleport_snowball.mcfunction`: while no non-spectator player is within 3 blocks it turns gravity on; it emits cloud/water particles. The arrow has no explicit lifetime field in this creation function; it is tagged `killedarrow` and passes through the existing projectile tick/cleanup functions. This mode is a distinct rider-arrow effect, not one of the marker raycasts.

The ordinary/upgraded marker raycasts carry owner/team identifiers, and the target helper excludes self and same-team players through `nodamage`/`nodamage1` handling. Legacy source does not establish modern native damage-source attribution for delayed/world effects; follow the documented indirect-kill ownership contract in the Java implementation.

## Separate source branches

The tiny teleport wand is a separate item (`sauvojen_staffs_tiny/teleport*.mcfunction`): cost **750 mana** (`config.mcfunction`), advances **0.35 blocks** up to Distance 100 (nominal **35 blocks**), and stops on a nearby mob (8-block check) or solid block. Its end helper applies levitation, including a broad radius-12 effect. Do not infer ordinary/Academy behavior from this tiny-wand branch.

Tuntija NPC teleport effects are separate again: `raycast/sauvojen_teleport.mcfunction` and `items/wands/sauvojen_wand/flying_wand_tick_teleport.mcfunction` make `tuntija`-tagged charge/player markers, routed through `raycastselector_tuntija.mcfunction` to `lbcr:raycast_teleport` / `raycast_teleportplayer`. They are not casts of the ordinary `stteleport` item.

## Current Java implementation

The ordinary and Academy items are registered and dispatched in `LbcWands`; `LbcAcademy.Wand` includes `TELEPORT`. `LbcTeleport` implements the native charge and cloud-arrow paths. Ordinary charges use mode 0, while the Academy wand reads modes 1–3 from the casting stack. The Academy trial is wired for the held wand and awards readiness from the shift-cast shock chance.

Java charges are tracked by the shared `ProjectileLifetimes` with its default **targets-only** policy (`terrain=false`): a charge has no hard age TTL and remains in flight while an eligible live target can still be reached. Solid blocks are not a reason for lifetime reviews to preserve a charge, and unloaded chunks are not loaded for this work. The cloud mode remains a separate native arrow carrier.

The inverted Java effect moves the same 3×1×3 block slice immediately below the target down by one block, including block entity/container data, and replaces the source slice with cobweb. It uses the shared map paste path; the source container is replaced without producing a duplicate inventory through secondary drops, as requested by the user. The shape follows the source; suppressing duplicate container drops is the confirmed migration correction.

Legacy branches above describe the datapack only; they are not a claim that Java reproduces every source detail. In particular, the Java resource import supplies item presentation while the native classes own casting, collision, effects, Academy state, and projectile lifetime behavior.
