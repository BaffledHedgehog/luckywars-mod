# Атрибуция ловушек из камня

После интеграции build и серверные проверки прошли: native удушение засчитывает
автора, союзник защищён, замена блока снимает старое авторство. Прежние
Teleport/Ruby/Tiny Stone/Acid и награда за убийство игрока также проверены.
Снимок: `build/verification/stone-wand-verification.json`;
подробности — [STONE_WAND_PORT.md](STONE_WAND_PORT.md).

`LbcIndirectKills.trapChanges(ServerPlayer, Runnable)` оборачивает серию нативных записей блоков существующим writer-контекстом `worldChanges` и вложенным `TrapFrame`, привязанным к уровню. `ArenaBlockMixin.beforeBlockChange` сохраняет неизменяемую позицию и последнее состояние блока, если активный кадр относится к тому же `ServerLevel` и новое состояние вызывает suffocation; попытка записать несuffocating-блок удаляет позицию из ожидающих кандидатов. `blockChanged` по-прежнему сбрасывает устаревшую атрибуцию при успешной записи. В `finally` обёртка сверяет кандидатов с итоговым состоянием мира и вызывает `stonePlaced` только для совпавших блоков, которые всё ещё вызывают suffocation. Вложенный вызов восстанавливает родительский кадр; подтверждённый внутренний блок убирается из кандидатов родителя, чтобы внешний вызов не перезаписал владельца.

Так несколько шаблонов и записей за один cast атрибутируют только итоговые suffocating-блоки без сканирования всего объёма. `fillTrap` учитывает только успешные записи, где новое состояние вызывает suffocation, а прежнее — нет. Поиск владельца для `IN_WALL` общий для защиты окружения и кредита за смерть: он находит актуально учтённый suffocating-блок, чья форма столкновения пересекает стандартную точку проверки глаз. Фильтр урона окружения использует того же владельца, чтобы ловушка не душила союзников или защищённых NPC; владелец может воздействовать на себя. Изменение блока сбрасывает устаревшую запись.

Точка интеграции: обернуть серию размещений вызовом `game.items().indirectKills().trapChanges(owner, writes)`. Mixin-callback находится в `src/main/java/me/skywars2/mixin/ArenaBlockMixin.java`. Исследователь проверок не запускал; итоговую сборку и серверные прогоны выполнил главный агент после интеграции, результаты указаны выше.
