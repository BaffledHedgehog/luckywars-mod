# Independent Void Arcanum review — 24 October 2026

Read-only source review of LbcVoidArcanum, BlackHoleVisuals, BlockAreaWork, LbcIndirectKills, LbcItems and the hand-swap mixin. No builds, runtime measurements, world mutations or source edits performed. Findings describe the inspected working tree and may be superseded by parent fixes.

## Findings sent to parent

1. WILD direct-damage policy is lost in the shared causal hook. WildDamage passes the native WILD admission path, but LbcIndirectKills.damaged resolves its player and calls displaced(target,player), creating a NEW non-WILD Owner. This outranks the original sticky-WILD contribution cause used for subsequent pull/support removal. A WILD hit against an allied player or friendly mob can therefore leave a non-WILD fall/void cause, which the shared allow-policy rejects. Preserve the WILD policy on this accepted hit; ideally retain the intended cause semantics explicitly. Ordinary direct hits correctly count as later actual hits; do not broadly disable their priority.

2. terrain() creates its replacement lambda once and captures the method's owner argument. Later majority changes/rebinding refresh hole.terrainCause, but levels1/2 still call destroyBlock(pos,true,owner) with that first author, even after that contribution has gone. Shared trap/support attribution uses the refreshed cause, so this is specifically stale native destroyBlock actor/context. Resolve the current terrain author at execution rather than retaining the first owner. High levels return AIR and do not use this captured native actor.

## Positive source checks

Parent fixed both findings during this review. Follow-up read confirms damaged now passes `source instanceof LbcVoidArcanum.WildDamage` into the fresh displacement policy, and low-level destruction resolves its native author from current hole.terrainCause. These two findings are closed by source inspection; runtime confirmation remains with parent.

Merge consumes the second native body, clears its terrain queue and removes its visual. All contributions survive merge while level saturates at5. Mixed hostile-team membership is examined independently of the cap; wild is sticky and ORs across bodies. Majority selection counts original contributions per owner and chooses uniformly among tied owners; it does not weight tied owners by iteration order. Each physics pass selects one author and uses its cause for that pass's pull/terrain. Level5 selects the large/disc model, others small. Lens scale is destruction radius/14, consistent with the shared renderer's existing shader-size convention; pixel equivalence was not measured.

Upkeep computes one body price 11/22/44/88/176, proportionally floors owner contribution shares, then distributes the indivisible remainder with a rotating owner order. Shares sum to the whole body price. Aggregation across bodies prevents a shared owner's earlier failure from recomputing other payers against a newly shrunken body in the same tick. Over-cap contributions increase ownership weight without exceeding176. Failed payers lose all their contributions; remaining owners are not retroactively charged extra in that tick. Upkeep currently pauses individually frozen owners, so mixed frozen/live members can yield less than the normal whole-body debit during that interval; verify intended freeze policy in runtime tests.

F reset runs after successful vanilla hand mutations at stopUsingItem. Existing hand latch state is cleared and each held hand can admit a new4000-mana hole next tick; no replacement of the existing body occurs. Technical/observer roles use the shared gameplay admission and target protections; ordinary allied players are excluded and sticky WILD retains role guards. Ordinary friendly mobs remain physical damage/pull targets, while ordinary homing uses the stricter shared enemy selector. Source never pulled players; native code retains that exclusion. Native velocity pull scales by level and radius, source damage .2/.25/.3/.35/.4 and movement .13/.5 are retained. Radial destruction replaces the source template/obsidian mechanism according to user ruling.

Unheld/suppressed/dead/disconnected owners lose contributions. Empty bodies, invalid epochs, removed bodies, wrong levels, unloaded centers and suppression at the center remove the body and visual. Marker is unsaved; stale load callbacks discard unknown bodies. Forget removes/rebinds contributions before shared visual forget. Match stop clears bodies, hand states, terrain queues and visuals. Existing shared visual nearest16 slots, four-tick collapse tail and holder cleanup are reused; no duplicate renderer was added.

Terrain uses bounded section bitsets with early empty-section filtering, a shared8192-cell/4ms loop and rotating body priority. It avoids forced chunk loads. Support candidates are collected once per synchronous terrain operation and live shape/ground checks remain per write; newly loaded living entities join active scopes. The explicit-cause BlockAreaWork overload preserves the caller's old causal order instead of minting fresh trap causes for every section. Shared later accepted player hits can supersede old pull/support causes.

## Performance and measurement limits

The terrain4ms deadline does not bound all work: merge is quadratic in body count, each body searches all loaded entities for homing every active tick, updateLevel can compare contribution pairs until WILD, and queue setup/candidate collection occur outside the inner timed loop. Membership has no independent count cap because all over-level5 contributions are intentionally retained. Repeated F creates real contributions/bodies subject to mana, not an independent hard object cap. These are explicit scaling risks, not measured regressions; inspect representative peak entity/contribution loads before claiming peak-load qualification.

No actual packet-path execution, disk restart, disconnect timing, chunk-unload callbacks, visual client pixels, timing profile or native death-priority integration test was run by this reviewer. Source inspection alone cannot qualify those boundaries. Parent owns fixes and validation.
