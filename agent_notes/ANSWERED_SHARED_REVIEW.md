## Finding: P2 — Incoming native TNT chains lose damage after their author becomes observer

`src/main/java/me/skywars2/game/LbcItems.java:892` checks whether a player source has become an observer. Lines893–899 exempt an explicit set of current-epoch delayed managed actors (TNT drops, creepers, cages, etc.). IncomingArtifacts is absent from that list.

The incoming family keeps actual TNT/children alive through a creator's ordinary death: `GameController.died:577` calls `items.clear`, not incoming `forget`; `LbcItems.clear:1752` leaves its actors alive. Its creator is still resolved by `LbcIncomingArtifacts.owner:283`, and both native explosion authority paths use that result (`HazardPropagationMixins.java:43`, `:140`). Therefore a pending incoming TNT/child DamageSource has the observer player as source and is rejected by the outer LbcItems guard before reaching its family admission at `LbcWands.java:1548`.

Consequently the same explosion can impart native enemy knockback while all its player-attributed HP damage is suppressed. This differs from the explicit current-epoch allowance already given other retained managed TNT families and from the required original-author handling of deferred consequences.

Primary native evidence: read-only `javap -p -c` on the local Minecraft26.3 merged JAR, `ServerExplosion.hurtEntities`: bytecode358 calls `Entity.hurtServer`, bytecode361 discards its boolean return, and bytecode423 independently calls `Entity.pushFromExplosion`. The source contract is [INCOMING_ARTIFACT_SOURCE_2026_10_27.md](INCOMING_ARTIFACT_SOURCE_2026_10_27.md).

Root subsequently added the current-epoch Incoming managed-source observer exception. Static correction acknowledged; its native qualification remains root-owned. Chaos ends flight under its own valid-owner lifecycle, so this finding does not require a Chaos delayed-author exemption.

Original recommended narrow correction: include current-epoch `LbcIncomingArtifacts.managed(source.getDirectEntity())` in the existing retained-source observer exception, retaining the family target filters. ## Follow-up: concrete Piston placement callback gap (read-only, build99299)

Cached native Minecraft26.3 primary evidence was inspected using `javap -p -c` only; no code/build/server changes. JAR: `.gradle/loom-cache/minecraftMaven/net/minecraft/minecraft-merged-d6f9bb6878/26.3/minecraft-merged-d6f9bb6878-26.3.jar`.

- `CloneCommands`: bytecode607–621 selects final flags2 for ordinary non-strict clone. Destination BARRIER staging uses flags|816 at840; actual final block placement uses flags2 at892. Block tick copy follows neighbor updates at1098; there is no fluid tick copy.
- `LevelChunk.setBlockState`: bytecode525 tests UPDATE_SKIP_ON_PLACE512 and skips native `BlockState.onPlace` only when that flag is present; otherwise calls it at542. Ordinary source clone final placement runs it.
- `ServerLevel.updateNeighboursOnBlockSet`: bytecode0–63 updates previous-state removal consequences, SIX neighboring cells and comparator output. It does not call the current cell's native onPlace.
- `LiquidBlock.onPlace`: calls shouldSpreadLiquid then schedules the cell's native fluid tick at27, plus relevant bubble-column block scheduling. `LiquidBlock.neighborChanged` also schedules that fluid tick; `updateShape` can schedule it for source liquid.

Current Piston transactional writes include UPDATE_SKIP_ON_PLACE and UPDATE_KNOWN_SHAPE. The commit pass only invokes updateNeighboursOnBlockSet, so a newly placed cell's onPlace is missing. An axis chain can incidentally schedule the moved liquid through an adjacent changed chain cell's neighbor notification, which explains why a simple horizontal water check can conceal the gap. A one-cell DIAGONAL shift of stable water/lava has no adjacent changed chain cell: its destination gets neither self-onPlace nor a neighborChanged call from the old diagonal source position. It can remain without the fluid tick that ordinary native clone schedules. This is a concrete behavior gap, not a request to copy fluid tick queues.

Recommended correction is a commit-only native final-placement callback for moved destination states, before the existing neighbor pass and after failure rollback is no longer possible. Ordinary native clone's final placement sees BARRIER as the previous state because of staging; passing the original destination state can change block-specific onPlace guards, especially when old/new native block types match. A meaningful native control uses a stable single fluid source shifted diagonally into air, compares destination fluid scheduling with ordinary /clone, and verifies a rejected transaction schedules no destination callbacks.
