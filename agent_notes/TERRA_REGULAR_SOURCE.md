# Ordinary Terra wand source audit

Scope: the regular `stterra` wand only. The upgraded academy wand and Terra swords remain separate stages. Source files below are read-only old-server evidence; this note adds no behavior requirements beyond existing user notes.

## Cast and projectile

- `world/datapacksdisabled/LBC/data/lbc/function/workingitems/sauvojen_staffs/terra.mcfunction`: ordinary `terra_preloop` is called unless sneaking with an upgradable wand. The special branch checks grass and can invoke the upgrade flow. `terra` charges `stterra_wand_mana_use` and applies Mage/trinket hooks; `terra_preloop` plays the amethyst sound and creates the projectile.
- `.../terra_preloop.mcfunction`: spawns marker `raycastterra` with `lifetime:200` and tags `player,slowraycast,shield_blockable2,magic`; copies caster `Rotation`, `lbcID2` and `team_number`; marks it `actived`.
- `.../raycastselector_player.mcfunction` dispatches `raycastterra` to `lbcr:raycast_terra`. Seven samples contain six 0.3-block moves: sample seven invokes `raycast_end_with_tp`, resets Distance and ends recursion. Actual speed is 1.8 blocks/tick, not the earlier audit's 2.1; old 200-tick travel is about 360 blocks. A block outside `minecraft:airs` invokes `placegrass` and kills the marker. Entity hits do not stop it. The user’s [PROJECTILE_LIFETIME.md](PROJECTILE_LIFETIME.md) supersedes the legacy TTL for both regular and Academy wands; Terra swords remain finite.
- The legacy entity selector’s `dx=0,dy=0,dz=0` anchors a fractional 1×1×1 cell at each ray sample; `distance=..10` does not turn it into an unrestricted radius-10 AoE. At each of up to seven 0.3-block samples per tick, an intersecting cell candidate triggers `lbcr:dmg_bypl_8`, which uses the same cell-relative selector flow and attempts 8 cactus damage against up to two eligible targets. The ray pierces targets and can attempt damage again on later movement ticks while a target remains intersected. This selector geometry is superseded by the user-approved native swept-hitbox behavior for Terra; preserve piercing and 8 cactus damage attempts for each target intersected during a movement tick. Do not impose Tiny Terra’s once-per-cast deduplication on this persistent wand. `dmg_bypl_8` contains Prism-specific advancement/upgrade checks inherited by this call path; these are suspicious incidental side effects, but no user question is needed about native hit geometry or pierce policy.

## Item, cost, ownership and blockers

- Source item is a carrot-on-a-stick with model `lbc:st/terra`, tooltip style `lbc:tier_c`, display name translation `sauvojen_wand_terra` (“Virtus Naturae”), and custom data `{craftusable:1,transformable:1,staff:1,magicwand:1,stterra:1}`. Lore keys are `sauvojen_wand_terra.lore.1`–`.4`: “The Power of Nature”; “Shoots a Terra-beam”; “Natural properties have not yet reached their limits”; “Can be combined with Terra Sword or Pine Needle Launcher”. Source definition: `world/datapacksdisabled/LBC/data/lbc/loot_table/sauvojen_tuntija_terra.json`; English text: `plugins/luckywars/resourcepack_lang/en_us.json`.
- Cast costs 1000 mana (`lbc:function/config.mcfunction`, `stterra_wand_mana_use`). The current mana subtraction in `terra_preloop.mcfunction` is unconditional after entering its cast path; unlike several other wand paths, this function has no visible `mana >= cost` gate. Verify surrounding wand dispatch/eligibility if preserving low-mana behavior.
- Projectile ownership and ally avoidance are carried by copied `lbcID2` and `team_number`. The common player raycast selector marks nearby players matching either owner id or team as `nodamage`/`nodamage1`; `dmg_bypl_8` excludes those tags. The shield tag is `shield_blockable2`; `items/shields/shield_block_2.mcfunction` exempts matching owner/team and destroys hostile shield-intercepted projectiles in air. Terra markers have no explicit entity-hit terminal behavior. Although the Terra cast/preloop has no local `stopper_magic` check, the global `lbc:function/tick.mcfunction` calls `tick_not_timestopped` only when scoreboard `time_stopped` is inactive; that function dispatches `slowraycast` markers. Therefore in-flight Terra movement pauses during global time stop. Player tick processing also has a separate `time_stopped_tickentity` path; the cast/preloop itself has no local stopper guard, so this audit does not establish whether a new wand cast can be initiated during time stop.
- `terra.mcfunction` calls ordinary `terra_preloop` only when not sneaking with an upgradable wand. Sneak + upgradable wand runs grass/upgrade handling instead; off grass it reports `not_on_grass`. The paired upgraded branch is separate and should not be folded into this port. User notes call out `lbc:terra_charge` as regular wand projectile display model; the chaos-sword fixed transform is only a display transform reference, not projectile movement.

## Reuse and constraints

The new-mod note [TERRA_PROJECTILE_MODELS.md](TERRA_PROJECTILE_MODELS.md) already records the reusable Polymer virtual `ItemDisplayElement` APIs and the Chaos Sword transform. Use its guidance for the projectile display attached to the real projectile; it identifies `lbc:terra_charge` for this wand. Apply the lifetime contract from `PROJECTILE_LIFETIME.md`, including no fixed map boundary, no chunk loads, and deleting the visual with its projectile.

The ordinary wand can be assembled from two `stterra_tiny` items in the inventory crafting grid: `lbc/function/other/craft/crafted_terra_inv.mcfunction` checks for exactly two and emits loot `lbc:sauvojen_tuntija_terra`; `crafted_terra.mcfunction` is the ground-craft counterpart. The ground-craft dispatcher also recognizes regular `stterra` + `terrasword` → awakened Terra and `stterra` + `razorpine` → Razor Terra (`lbc/function/other/craft_ground.mcfunction`); another branch combines it with `wtf_item`. These are optional downstream combinations, not casting dependencies.





## Grass feature migration note (26.3 registry)

The old `lbcr:function/placegrass.mcfunction` calls four vanilla configured features; the old LBC datapack contains no matching `data/minecraft/worldgen/configured_feature` or `placed_feature` overrides. In `C:/Users/yarik_temp/.gradle/caches/fabric-loom/26.3/minecraft-merged.jar` (MC 26.3 bundled merged JAR), the active feature registry is `Registries.FEATURE` (`net.minecraft.core.registries.Registries.FEATURE`); feature JSON is under `data/minecraft/worldgen/feature/`, and matching named Java keys are `VegetationFeatures.GRASS`, `TALL_GRASS`, `TAIGA_GRASS`, and `GRASS_JUNGLE` (`net.minecraft.data.worldgen.features.VegetationFeatures`). Their direct IDs and states are:

| Old configured-feature call | 26.3 direct `Feature` key | Single placement behavior |
|---|---|---|
| `minecraft:patch_grass` | `minecraft:grass` / `VegetationFeatures.GRASS` | `minecraft:short_grass` |
| `minecraft:patch_tall_grass` | `minecraft:tall_grass` / `VegetationFeatures.TALL_GRASS` | lower half of `minecraft:tall_grass` |
| `minecraft:patch_taiga_grass` | `minecraft:taiga_grass` / `VegetationFeatures.TAIGA_GRASS` | weighted: short grass 1, fern 4 |
| `minecraft:patch_grass_jungle` | `minecraft:grass_jungle` / `VegetationFeatures.GRASS_JUNGLE` | weighted: short grass 3, fern 1 |

Those 26.3 `Feature` JSON definitions are `simple_block`; they place one candidate block and carry no patch spread. The old 1.21.x configured-feature definitions (confirmed from `C:/Users/yarik_temp/Desktop/bingoserverfabric/versions/1.21.8/server-1.21.8.jar` as the available vanilla comparison; target 1.21.4 datapack has no overrides) wrap the same block choices in `random_patch`: `patch_grass`, `patch_taiga_grass`, and `patch_grass_jungle` use 32 tries; `patch_tall_grass` uses 96; all use xz spread 7 and y spread 3. All four filter for air; jungle also rejects podzol below. Thus the new keys are direct block-choice equivalents, not behavior-equivalent replacements for the old scattered patch. If preserving the old placement pattern is required, reproduce its attempts/spread/filter around the direct feature placement; do not expect `Feature.place` itself to spread candidates.



In the 26.3 deobfuscated JAR, use `new PlacedFeature(Holder<Feature>, List<PlacementModifier>)`, `CountPlacement.of(int)`, `OffsetPlacement.of(IntProvider xz, IntProvider y)` (`OffsetPlacement`, not `RandomOffsetPlacement`), and `BlockPredicateFilter.forPredicate(BlockPredicate)`. `TrapezoidInt.of(-7, 7, 0)` samples `nextInt(8) - nextInt(8)`, and `of(-3, 3, 0)` samples `nextInt(4) - nextInt(4)`; bytecode confirms these exactly match the old random-patch triangular offsets. For jungle, compose `ONLY_IN_AIR_PREDICATE` with `not(matchesBlocks(new Vec3i(0, -1, 0), Blocks.PODZOL))`. A representative per-patch composition is `new PlacedFeature(grassHolder, List.of(CountPlacement.of(32), OffsetPlacement.of(TrapezoidInt.of(-7, 7, 0), TrapezoidInt.of(-3, 3, 0)), BlockPredicateFilter.forPredicate(BlockPredicate.ONLY_IN_AIR_PREDICATE)))`; call `.place(level, chunkGenerator, random, origin)`. Current direct lookup of old `patch_*` IDs in `Registries.FEATURE` returns empty because these are not 26.3 feature keys.
