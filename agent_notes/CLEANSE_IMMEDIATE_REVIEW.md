# Immediate status prevention review

The initial read-only audit below describes the old five-tick implementation and motivated the new guard. The established user requirements in `ARTIFACT_DEBUFF_PORT.md` remain authoritative: type `1:5` keeps its exact native debuff list and levitation item protection; type `1:6` clears custom cold/frozen state as well as native effects, and clears even when native effects are empty. The `(user)` blocks in `ARTIFACT_DEBUFF_PORT.md` and `ARTIFACT_PASSIVES_PORT.md` are preserved.

## Prior artifact behavior (before this fix)

- `LbcMagic.tickPassives()` in `src/main/java/me/skywars2/game/LbcMagic.java:680-710` runs passives on its existing five-tick cadence. It preserves game eligibility, beacon suppression, and 8→5→6 ordering.
- Type 5 (`clearDebuffs`, `:709-729`) removes Blindness, Slowness, Weakness, Mining Fatigue, Glowing, Hunger, Instant Damage, Nausea, Poison, Unluck, Wither, plus Levitation unless `protectsLevitation` matches. That protection (`:730+`) checks feet/legs equipment, inventory slots 0..35 and offhand; cursor/crafting are intentionally excluded from levitation protection.
- Type 6 delegates to `LbcItems.clearEffects` (`LbcMagic.java:706`; `LbcItems.java:689-697`). It calls `clear()` first (turn curse, Frost, Colors teleport timer, Mana potion/stat timers and overload), removes `lightningist` and `greed_cursed`, then removes all native effects. This path is unconditional on native-effect presence.
- `LbcMana.clearEffects` (`LbcMana.java:145-150`) clears all five `POTION_TIMERS`, `reverse_mana`, pending/stat effect tracking, no-magic and overload state. `LbcColors.clearEffects` (`LbcColors.java:240`) clears teleport timer/index. `LbcFrost.clear` (`LbcFrost.java:~250-~310`, locate exact current line) removes attachment/tracking and thaws owned ice, including shared-owner bookkeeping.

## Custom status production / guards

- Frost/cold is custom state, not a potion effect: `LbcFrost.add` (`:90-100`) increments cold and calls `check`; threshold freeze state begins at `:103-119`, and emits debuff potion carriers at `:120-132`. Frozen maintenance reapplies fatigue/weakness every tick at `:134-144`. This is the key non-native entrypoint an immediate guard must reach before state increments; native `canBeAffected` alone cannot stop cold/frozen attachment state.
- Mana potion/stat statuses use short-lived `RAID_OMEN` carriers with amplifiers 16..20: `LbcMana.effectsChanged` (`:151-161`) queues capture; `consumePotion` (`:166-177`) converts carrier into score timers. This is the custom status entrypoint to audit against a canBeAffected cancellation; current class has no such check. Score timers then apply resource changes in `tickPotions` (`:178+`); `clearEffects` resets them.
- Color curse uses `RAID_OMEN` amp 40 as a gate and custom `effect_rtp_1` timer: `LbcColors.curse` (`:235-238`) already calls `target.canBeAffected(...)` before incrementing. Reuse the same common guard semantics there; cleanup at `:240` resets timer/index.
- `LbcColors.effect` (`:186-187`) and `LbcFrost.effect` (`LbcFrost.java:130-132`) directly call `addEffect`; these native effects are covered by a LivingEntity.addEffect/canBeAffected interception. Review `LbcClouds` poison/wither/slow effects (`:255-266`, projectile hit `:371`) and `LbcWands` levitation/blindness (`:489`, `:508`) as ordinary native addEffect sources. `LbcOverload` likewise emits native effects from its tick loop.
- Existing reusable predicate: native source applications should pass through `LivingEntity.canBeAffected(MobEffectInstance)`; `LbcColors.curse` already demonstrates it. A general canBeAffected mixin can make native exclusions immediate, but doesn't cover custom Frost's cold counters or mana/timer transitions unless those custom entrypoints consult the same policy.

## Existing focused verification and policy collisions

- `agent_notes/ARTIFACT_DEBUFF_TESTS.md`: `tools/smoke_lbc_loadouts.py --server-dir <isolated-server> --artifact-debuff-only` covers type 5 list/levitation protection, type 6 cold-only + turn curse without native effects, ice restoration/tracking cleanup, mixed 5+8 and 5+6+8 ordering, inventory capability mask, cleansing-potion callback, shared ice ownership. Report documents a past fixture-only ordering correction.
- `agent_notes/ARTIFACT_PASSIVES_TESTS.md` covers active five-tick phase, inventory 36/offhand and levitation exclusions, cursor and 2x2/3x3 crafting inputs, type 6 clear-all, ordering with 8, type-1 coexistence, beacon suppression, Creative eligibility and observer exclusion. These are the best addresses to extend with an application-before-artifact-tick assertion.
- Collision: 1:5's existing list excludes custom freeze/cold and mana curse; 1:6 deliberately clears Frost and custom timers. Don't broaden 1:5 into all of 1:6. Also preserve artifact gate (gameplay permission, alive, arena, non-observer), beacon suppression, and order 8→5→6. Native eligibility at effect application must not accidentally change non-artifact gameplay semantics or unrelated 1:8 Hunger/Regen behavior.
- Important source note (`ARTIFACT_DEBUFF_PORT.md`, user block): continuing contact from an external cloud/projectile can reapply after cleansing; the cloud/projectile itself is not destroyed. An immediate status veto must not silently imply source destruction.

## Immediate guard test section

`GameChecks.checkArtifactCleanseImmediate` is dispatched as `sw check artifact-cleanse-immediate`. It covers the public `LbcMagic.rejectEffect`/`beforeEffects`/`rejectCustomEffect` contract, type-5 debuff versus positive-effect behavior, type-6 pre-existing poison cleanup on a native `ServerPlayer.doTick()` before its damage phase, direct `applyInstantaneousEffect` harm/heal paths, native `forceAddEffect`, frost/turn-curse custom-state rejection, same-tick acceptance after removing type 6, and beacon/observer exclusions. The existing `artifact-debuffs` case now arranges cold/frozen/custom curse before type-6 acquisition and checks the actual player effect-phase head after acquisition, because an active purifier rejects a new frost state at `LbcFrost.add`.

`tools/smoke_cleanse.py <isolated-server>` runs bot creation, existing passive loot/loadout setup, immediate guard, existing debuff/passive checks in one match, then stop cleanup, and writes a SHA-256 report to `build/verification/cleanse-immediate-results.json`. The root agent ran it successfully: **55.49 seconds, one match, six check groups**, on SHA-256 `67c7a14aff86aedd82592f88019b1af24336e204ef0f52a1224fa1a61b52120c`. Cursor/crafting coverage remains in the established passive fixture (`ARTIFACT_PASSIVES_TESTS.md`); no duplicate packet fixture was introduced.

## Implemented guard and phase ordering

`LbcMagic.rejectEffect` resolves a dirty inventory snapshot before inspecting the type mask and existing passive eligibility/beacon gates. It never removes effects itself: callers may be inside a native effect iterator. `LbcColorEffectsMixin` invokes it from `canBeAffected` and calls `beforeEffects` at native `tickEffects` HEAD. `LbcInstantEffectMixin` covers both base `MobEffect.applyInstantaneousEffect` and the healing/harming override, before actual heal/hurt.

The pending-cleanse set survives lazy snapshot refresh. `LbcItems.tick` flushes it before mana/custom processing; `beforeEffects` removes old native effects before their first tick. Immediate custom-status guards cover frost, turn curse, mana setters/carriers, and transient Overload armor state; existing status loops also protect transitions out of beacon suppression. No new world scan or every-tick inventory polling was added. Five-tick passive cleanup remains a fallback.

The fixture includes real unprotected instant harm as a control, old poison at damage-due duration 25 for both artifact types, instant healing allowed by type 5 but blocked by type 6, immediate acceptance after removal, native/custom guards under a beacon, and old mana statuses cleared before the first unsuppressed mana step. Initial fixture failures and final results are recorded in [SERVER_TESTS.md](../SERVER_TESTS.md).

The same JAR also passed existing mana-potion delivery/timer/cleanup checks (55.09 s) and full-invisibility plus observer-camera regression (56.99 s). The prepared artifact is `build/verification/skywars2-cleanse-immediate-67c7a14a.jar`; the main server still runs the previous installed JAR. These checks use native fake players, not real client connections.
