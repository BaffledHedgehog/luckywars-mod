# Невидимость III и выше

Требование (user):

> ещё - я хочу реворкнуть ванильный эффект Невидимость 3 (и выше) - чтоб игрок не рендерился вообще у других игроков (даже броня, даже хитбокс с f3+b) - полная невидимость. (Однако удары все равно должны проходить, и любое нанесение урона)

Уточнение для наблюдателя, вселившегося в цель (user):

> Да, внутри цели оставить обычную камеру и вид

## Поведение

Только у игроков vanilla Invisibility с amplifier >= 2 включает полное
скрытие от внешних зрителей. Уровни I/II и невидимость мобов остаются
ванильными. Creative и developer не являются исключениями.

Polymer отправляет внешнему зрителю невидимую vanilla `Interaction` с тем же
entity ID и шириной/высотой настоящего игрока. Нет тела, брони, предметов рук,
имени, огня, свечения и potion particles на этой клиентской сущности.
Ванильный F3+B пропускает сущности с invisible flag. Interaction остаётся
pickable: клиент может послать обычный пакет атаки по этому ID.

На сервере это по-прежнему исходный ServerPlayer: экипировка, броня, эффекты,
команда, роли, физика, снаряды и правила урона не подменяются. Невидимость
не даёт новой неуязвимости и не отменяет существующую защиту союзников/наблюдателей.
Звуки и созданные игроком отдельные мировые объекты не стираются.

Владелец получает своё обычное представление. Зритель внутри камеры цели
также получает PLAYER, обычную экипировку и прежнее зеркалирование инвентаря/
эффектов через Spectators. При выходе из камеры снова получает скрытый тип.
Переключение уровня эффекта не пересоздаёт цель у уже вселившегося зрителя,
чтобы не потерять клиентскую ссылку камеры.

ПКМ по клиентской Interaction потребляется самим proxy. Для серверного PASS
используется готовый fallback Polymer (`isPolymerEntityInteraction`), чтобы
обычное использование лука/зелья/жезла продолжалось без собственного движка
обработки пакетов. Нормальные игроки и зритель внутри камеры этот fallback
из-за невидимости не включают. Доступ камеры очищается при выходе и respawn,
чтобы новый объект игрока с тем же UUID не унаследовал старое исключение.

## Обновления и CPU

[FullInvisibility](../src/main/java/me/skywars2/game/FullInvisibility.java)
хранит неизменяемый volatile-снимок для кодировщика Polymer. Добавление,
усиление, ослабление, истечение, очистка и загрузка NBT используют native
effect callbacks. Вход с сохранённым эффектом обрабатывается до первого pairing.
Тип пересоздаётся только при переходе через порог III и при смене камеры.
Изменение позы/scale посылает только metadata с новыми размерами.
Полей Interaction хватает из нативной схемы Polymer; private ID и serializers
не копируются вручную. Default-значения тоже отправляются, чтобы возврат
размера к 1 корректно заменял прежний размер.

Постоянного обхода игроков/мира, таймеров и фоновых world reads нет.
Размеры, эффекты и трекеры читаются на server thread; кодировщик использует
готовый снимок. Смена камеры использует отдельный immutable-набор получателей.

## Транспорт

У Interaction и Avatar разная точка посадки. Поэтому внешний proxy не
включается в клиентский список пассажиров: готовые нативные position sync
packets передают настоящую серверную позицию игрока из Polymer tracker hook.
Серверный игрок продолжает ехать на своём транспорте. Владелец и зритель
внутри камеры получают обычный passenger packet и обычную посадку.

Редкий passenger codec использует concurrent-индекс скрытых игроков по ID
и immutable-снимки, не поиск сущностей мира из Netty. Индекс очищается при
снятии эффекта/удалении сущности и восстанавливается перед pairing после
перехода между измерениями. Дополнительная позиция отправляется только для
скрытого пассажира его внешним tracking-зрителям; обычных игроков этот
обработчик не обходит. Клиентский визуальный прогон транспорта остаётся частью
ручной проверки с двумя настоящими клиентами.

## Подбор предметов: исправление отключения 16 октября 2026

Пользовательский отчёт `disconnect-2026-10-16_13.58.11-client.txt` содержит
`ClassCastException: Interaction cannot be cast to LivingEntity` в обработчике
`ClientboundTakeItemEntityPacket`, а не в обработчике атаки.
Vanilla клиент без проверки приводит сборщика предмета к LivingEntity.

`FullInvisibilityPickupMixin` при кодировании заменяет ID скрытого сборщика
на отсутствующий `-1` только для внешнего зрителя. Vanilla пропускает полёт
предмета к сборщику, но по-прежнему уменьшает стопку/удаляет подобранный
предмет или стрелу. Не отменяем весь пакет: это оставляло бы неправильное
число предметов при частичном подборе. Для владельца, камеры внутри цели
и обычного уровня невидимости ID сохраняется. Серверный подбор не меняется;
исходный broadcast packet не мутируется, обработка работает и внутри bundle.
Используется существующий concurrent-индекс: поиска по миру из Netty нет.

Пакеты атрибутов и анимации пробуждения для неживого представления уже
подавляет `PacketPatcher.prevent` в Polymer Core 0.18.2+26.3. Повторный
фильтр для них не добавлен. Equipment/effect handlers vanilla проверяют
LivingEntity и безопасно пропускают Interaction.
