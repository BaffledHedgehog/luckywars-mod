## Author decision

The user explicitly chose individual version/mode for each TMT ability and
retained Tiny abilities alongside Academy abilities. This supersedes the old
shared `upgraded`/`mode` behavior **for TMT**, including the accidental disabling
of Tiny by a different upgraded property. Ordinary items keep their existing
rules. Native player-level resources, cooldowns, suppression and target policy
still belong to their existing owners.

## Persistent property slots

`LbcTmtAbilities` stores up to seven draws in `tmt_abilities`, each with a stable
ability ID and private component data. Repeated identity uses its last draw,
without extra execution slots. Global category/ability flags remain available
for existing classification; version, mode and type are kept inside their own
property. The generator now accepts typed ability records and persists these
slots through ordinary ItemStack codecs. No released TMT output needs migration:
the previous kernel had no public acquisition or native carriers.

During a property callback, the **actual held stack** receives that property's
parameters. Native owners see the same object, hand, inventory and components.
On return, their data changes are written back to that property, then the outer
metadata is restored. Names, visuals, count and other components are not replaced
by a fake held item. Exceptions restore the scope and retain already-made native
property writes. Missing properties do not execute a fallback.

Runtime reentry is tracked by stack identity in a transient thread-local scope,
cleared in `finally`; it is not stored as an NBT lock. Captured source stacks can
retain `tmt_active_ability` as provenance context and still be saved/restored and
used again. Native long-lived producers retain their own copied parameters while
sibling properties change modes on the held item.

This bridge runs only during explicit property activation: bounded seven-slot
reads, no world scan, per-player poll, new tick task or function interpreter.
It adds no separate implementation of an existing weapon or spell. This is a
structural work bound, not a measured peakTPS/GPU improvement.

## Common-wand dispatcher

The existing `LbcWands` enum supplies 103 native profile descriptions across 58
families. TMT selects one matching version **inside each property**, so another
property's upgrade does not select its Academy version. `tmtAbilities()` is
metadata for the future complete meaningful catalog, not an enabled random pool.

The old native cast body was extracted to `castSpell`, then reused by the private
TMT continuation. Both its 21,880-byte source body and the ordinary early dispatcher
are byte-exact against the committed parent; no damage/payment engine was copied.
Each selected family retains native cost, mode selection, bonuses and suppression.
An unaffordable family does not suppress a later affordable one. Empty, consumed,
replaced, observer, blocked or stopped input cannot continue into another property.
Offhand behavior uses the existing server setting and exact supplied hand.

The deterministic 58-family ordering is the common-wand subset of the source
`lbcr:raycast`, `lbc:workingitems/spell1_default` and `spellsummoner` order, rather
than random draw order. Mixed regular/Academy versions did not exist in the old
shared-flag format; they now use this stable default-family order. Full source
dispatch groups, gadgets, books, weapon events and passive abilities are separate
remaining work. Ordinary first-match item dispatch is unchanged.
