# Wall Wand legacy behavior

Research scope: read-only legacy datapack `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/{lbc,lbcr}`. Source line references below use paths relative to that `data` directory. No user-authored text existed in this file when written.

## Ordinary Wall Wand

- Item `wall:1` is the staff named by `wall_wand`, uses item model `lbc:wallwand`, and has four lore translation keys. Its loot definition tags it `{craftusable:1,transformable:1,staff:1,raycastspell:1,wall:1}`. It is obtainable via `loot_table/transformables_staff.json` (wall entry near line 847); The same display name/model is reused by a joke golden apple in `loot_table/rofls.json`; that edible `eat_damage:1` entry is not the functional wand and is excluded by the importer. Mana lore reads `wall_wand_mana_use`; `function/config.mcfunction:27` sets that objective to **1500**. The generic Academy advancement criterion recognizes `{upgraded:1,transformable:1,staff:1,wall:1}` in `advancement/true_advancements/legends/academy/wall.json:35-41`.
- Right-click/main-hand dispatch is `lbcr:function/raycast.mcfunction:4`; offhand dispatch is `lbcr:function/raycast_left.mcfunction:4`. Both require mana >= 1500 and no `stopper_magic` marker within 20 blocks, then enter `raycast_loop2cd` from eye position. `raycast_loop2cd.mcfunction:1-4` runs the loop and subtracts 1500 mana once after it ends, then applies the full mage armor set's mana-max bonus and trinket cast hook.
- `raycast_loop2.mcfunction:1-5` advances the ray one block per step, emits brick particles, stops at a mob or non-air block, and continues up to `Distance=100` (about 100 blocks); it also halts for `nomagic_active` players or a nearby stopper marker. `raycast_end2.mcfunction:1-7` fills air only with bricks in a vertical plane 7 blocks wide and 6 blocks tall (relative Y −2..+3) at the terminal point, plays placement sound, and sets Distance to 1000. Thus normal use always creates the vertical wall; it does not read the wand's mode field.
- Every impact grants `lbc:true_advancements/staffs/wall` when a non-spectator player is within 3 blocks (`raycast_end2.mcfunction:10`).

## Academy upgrade and modes

- Academy NPC interaction routing checks held `wall:1` at `lbc:function/other/magic_academy/interacted_2.mcfunction:36` (condition prompt) and `interacted_upgrade.mcfunction:39` (upgrade action). The condition handler is `can_upgrade/wall.mcfunction` and only prints `upgrade_condition_wall`; the actual upgrade handler prints `upgrade_succesful_wall` and applies item modifier `lbc:tiers/a` (`upgrade/wall.mcfunction`). The tier modifier only changes the tooltip tier; the shared Academy interaction supplies the upgrade-state flags. The Academy advancement is inventory based, not a count-based advancement requirement.
- The casting-time upgrade condition is also wired in `lbcr:function/raycast_end2.mcfunction:9-10`: if the selected item has `{upgradable:1,wall:1}`, it starts from caster eye position, yaw-only, one block forward and runs `raycast_end2_check_wall_upgrade`. That helper checks four cardinal directions (`raycast_end2_check_wall_upgrade.mcfunction:1-6`); each scans in 0.9-block steps up to 10 for an exact brick (`..._rc.mcfunction:1-2`, `_rc2.mcfunction:1-3`, `_rc2end.mcfunction:1-2`). Only `check=4` invokes generic Academy `can_upgrade` (`lbc:function/other/magic_academy/can_upgrade.mcfunction:1`), which routes to `can_upgrade_book.mcfunction`: it sets `upgrade_available:1`, clears `upgradable`, plays the experience sound and shows `can_upgrade`. This is a spatial readiness condition, not a cast counter.
- Academy-upgraded casting dispatches from `lbcr:function/raycast_upgraded.mcfunction:3` (main hand) or `raycast_upgraded_left.mcfunction:3` (offhand): it requires at least 500 current mana and no stopper marker within 20. `raycast_loop2cd_upgraded.mcfunction:1-7` cycles modes while sneaking: vertical (1), horizontal (2), break (3), stair (4), with feedback keys `mode_vertical_wall`, `mode_horizontal_wall`, `mode_break_wall`, `mode_stair`. Sneaking while looking up/down calls existing `change_mode_4` helpers; otherwise the cast continues. The upgraded loop runs, then subtracts **500 mana once per cast** (`raycast_loop2cd_upgraded2.mcfunction:1-4`), and advances 0.6 blocks per iteration up to `Distance=300` (`raycast_loop2_upgraded.mcfunction:1-5`, roughly 180 blocks); it still stops at mob/block and obeys the same anti-magic guards. `raycast_end2_upgraded.mcfunction:1-8` reads `mode` from the held item's custom data (main hand or offhand) and dispatches modes 1..4.
- Mode 1 is the same 7-wide, 6-high air-only vertical brick wall (`raycast_end2_mode_vertical.mcfunction:1-7`). Mode 2 fills an air-only, 7×7 horizontal brick plane (`..._horizontal.mcfunction:1-3`). Mode 3 clears bricks in a 5×5×5 area and drops the matching number of brick items; source refunds 1500 at ≥15 removed (`..._break.mcfunction:1-7`), changed by user clarification below to a 500 refund cap. Mode 4 places template `lbc:stair5x5x5` with yaw-based rotation and offsets (`..._stair.mcfunction:1-4`); the template file is `lbc:structure/stair5x5x5.nbt`. The source yaw intervals overlap at ±45° and ±135° and miss a negative extreme; user requests one stair with all four directions corrected.
- Mode cycling uses inclusive up/down pitch intervals in `lbcr:function/raycast_loop2cd_upgraded.mcfunction:1-2`; at pitch 0 both execute. The user clarified the intended rule below: pitch <= 0 cycles forward, pitch > 0 backward, using the used hand.
- `raycast_end2_upgraded.mcfunction:9` grants the same staff advancement on a successful nearby cast. Translation text is supplied externally via the `wall_wand*`, `mode_*_wall`, `mode_stair`, `upgrade_condition_wall`, and `upgrade_succesful_wall` keys; the datapack item and `tellraw` definitions reference these keys but do not contain translated prose.
