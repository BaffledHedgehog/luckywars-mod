# Аудит font-template для вертикального AttributeHud

Дата: 2026-10-15. Исходный `all_in_one_1.21.8` читался только в `assets/*/font/`; языковые файлы не читались, исходный RP не изменён.

## Исходное разрешение и два столбика — актуальное исправление 16 октября 2026

По уточнению (user) больше не уменьшаем PNG. Все 36 source-glyph сохраняются
пиксель в пиксель в исходном разрешении 9/16/18/32px. `height` масштабирует
их до 9 GUI px, space-дополнение сохраняет общий слот 10px. Атласы разделены
по исходному размеру. Для верхних строк добавляется прозрачное поле с тем же
pixel scale: например, 32×64 cell при height=18 оставляет иконку 32×32 размером 9px.
Проверяется точное совпадение RGBA каждого исходника во всех используемых строках.

Есть два независимых ограничения клиента: `ascent <= height` и glyph-cell
с рамкой не больше 256px. Поэтому вверх используется максимум шесть строк
(32×224 cell при height=63, ascent=62). До 18 значений идут в первый столбик,
следующие — во второй; начало второго выровнено по первому, горизонтальный
промежуток 6px. Активны 18 row-fonts `row_m6`…`row_p11`, 28 общих PNG.
Одна scoreboard entry и все пользовательские codepoints сохранены.

Удалены только устаревшие собственные файлы template: уменьшенные атласы и
неиспользуемые row-fonts. Настоящий RP не изменён. Проверена имитация ручного
переноса: повторная генерация дала 0 pending files. Исходные SHA проверены.
Инструкция — [README](../resourcepack_template/README.md), runtime —
[SERVER_TESTS.md](../SERVER_TESTS.md). Ниже сохранена история предыдущего решения.

## Авторские иконки — предыдущее решение 16 октября 2026

Все 36 значков из текущего `AttributeHud.icon()` найдены в настоящем default;
символы пользователя не менялись. Исходные PNG имеют разрешения 9/16/18/32 px,
но размер HUD унифицирован до 9×9 GUI px с сохранением пропорций и RGBA-цветов.
Iron Sword и Diamond Pickaxe наследовались из vanilla: эти два исходника взяты
из локального merged JAR 26.3. Полный default и переводы не копируются.

Два atlas PNG обслуживают строки `row_m17`…`row_p18`. У верхнего atlas ячейка
9×161, у нижнего — 9×9; provider height равен высоте ячейки, ascent = 8−9×row.
Таким образом соблюдаются `ascent <= height` и лимит 256 px для bitmap-глифа.
Дополнительное прозрачное поле не растягивает сами 9px иконки.

Каждый row-font получает bitmap и space-провайдер перед прежним TTF.
Невидимый codepoint U+F0000+код иконки дополняет фактический advance до 10 px.
Java вставляет это дополнение и считает пару как один слот 10 px, цифры — 6,
точку — 2. Это сохраняет начало каждой строки и выравнивает числа после иконок
без чтения PNG и без клиентских метрик на серверном тике.

Генератор `--import-icons` пишет только отличия в template. Проверена имитация
ручного применения: повторный запуск дал **0** pending files. SHA всех 71
прочитанных файлов настоящего RP до/после совпали. Формат JSON после переноса
может отличаться: проверка сравнивает JSON семантически. В реальный RP не писали.
Шаблон, включая ранее подготовленный компактный `glyphs.ttf`, нужно применять
вместе с новым JAR. [Инструкция](../resourcepack_template/README.md).
Графического клиента не подключали; серверный smoke и артефакты — в
[SERVER_TESTS.md](../SERVER_TESTS.md). Ниже сохранён исторический аудит.

## Найденные существующие провайдеры

- `assets/minecraft/font/default.json`: 32 символа `type: space`; U+F800…U+F80F имеют advances −1…−16, U+F820…U+F82F — −17…−32. U+F810…U+F81F не определены. Положительных horizontal advances нет.
- `assets/minecraft/font/icons.json` состоит из bitmap glyphs, дополнительных space providers нет. В `default.json` также есть bitmap glyphs.
- Встречающиеся у bitmap ascent/height 12/16, 41/90, 100/300, 240/256, 465/500 задают положение/размер изображений иконок, а не вертикальный пробел. `new_layer`/`newlayer` и вертикальных space providers в RP не найдено.

## Подготовленный template

`tools/build_attribute_hud_font.py` генерирует только `resourcepack_template/assets/skywars2/font/attribute_hud/`. Он создаёт один `glyphs.ttf`, `spacing.json` и 81 font definition для слотов −40…+40. TTF рисуется генератором из собственных контуров простых 5×7 пиксельных глифов через FontTools; сторонние шрифты и PNG не используются. Настройки каждого TTF provider: общий файл `skywars2:attribute_hud/glyphs.ttf`, `size: 10`, `oversample: 2`, `shift: [0, slot * 9]`.

IDs: `skywars2:attribute_hud/row_m40` … `row_m1`, `skywars2:attribute_hud/row_0`, `row_p1` … `row_p40`; дополнительный spacing font ID — `skywars2:attribute_hud/spacing`. Для ширины предусмотрен U+E000 с advance +1; возврат по горизонтали можно собирать из уже имеющихся в default font отрицательных символов.

Покрытие TTF: `0`–`9`, `.`, `+`, `-`, пробел, `NaN`/`Infinity` и ровно символы из `AttributeHud.icon`: `♥◆⚔✦↗↑◈↓☘◇·`. Генератор проверяет cmap, advance 600 units каждого символа, JSON всех 81 сдвигов и spacing provider. Если исходный пак уже содержит `assets/skywars2/font`, генерация прекращается, чтобы не воссоздать применённый template. Существующие выходные файлы без `--force` также блокируют генерацию; `--force` относится только к собственным целевым файлам template.

Успешный запуск проверил 83 template-файла и 33 codepoint; каждый имеет advance 600 units (6 GUI px при размере 10). Фактический проектный RP не имеет `assets/skywars2/font` на момент аудита.

## Ограничения отображения

81 виртуальная позиция превосходит 15 записей native sidebar и 40 видимых ванильных строк. Смещения позволяют рисовать рядки одного scoreboard entry в разных вертикальных позициях, но не гарантируют, что весь столбик поместится на экране: на маленьком GUI или при большом масштабе нижние/верхние строки могут выйти за границы. Самостоятельный визуальный прогон на клиенте не выполнялся.

## После ручного переноса — 16 октября 2026

Предыдущие пути `skywars2` описывают первоначальный template. Пользователь
перенёс шрифты в `assets/lbc/font/attribute_hud/` и изменил IDs в Java на
`lbc:attribute_hud/*`. Применённая папка template удалена, заново не создаётся.
Генератор теперь проверяет именно существование этой папки `lbc`, поэтому
не создаёт повторную копию применённых шрифтов.

Read-only проверка обнаружила в перенесённых `row_*.json` прежние ссылки
`skywars2:attribute_hud/glyphs.ttf`. Пользователь исправил их самостоятельно
на `lbc:attribute_hud/glyphs.ttf`; вспомогательный скрипт удалён по его просьбе.
Исходный RP агентом не редактировался.

## Отдельные значки и компактная точка — 16 октября 2026

`AttributeHud.icon()` теперь содержит 36 отдельных case, сверенных по
`LivingEntity.createLivingAttributes()` и `Player.createAttributes()` текущего
26.3 JAR. Групповых case нет. Прежние значки сохранены, отсутствующие
оставлены пустыми строками для пользовательского оформления.
[Полный каталог](PLAYER_ATTRIBUTE_CATALOG.md).

У десятичной точки в актуальном пользовательском TTF подтверждены контур
200×200 units и advance 600 при UPM=1000/size=10: 2×2 GUI px и шаг 6 px.
Строковый форматтер пробела после точки не вставляет; промежуток получается
из метрики шрифта. Новая запрошенная правка подготовлена только для
`resourcepack_template/assets/lbc/font/attribute_hud/glyphs.ttf`: контур
100×100 units, advance 200 (1×1 и шаг 2 GUI px). Остальные glyph outlines
и hmtx-свойства побайтно/по значениям сверены с источником без изменений.
SHA источника после подготовки не изменился.

Расчёт ширины и возврата X в моде теперь учитывает точку как 2 px,
остальные символы — как 6. Шрифт и мод нужно обновлять вместе. Копии
81 row-font и spacing не восстанавливались; новых генераторов нет.
