# TMT: native aliases, criteria, consumption and material

This stage is verified internally and **not installed**. The author's 7 November
instruction holds all fixes until the next stable release. Full TMT remains open.

The unified catalog now canonicalizes old throwing-item carriers through the same
factory classifier as direct-use profiles. Throwing does not acquire a fake BLOCK
event. The old `imbaxe` carrier resolves to the existing native axe implementation.
The prototype generator also refreshes the already-ported Gayradar/Troll Box source
identities without changing the prototype count or interpreting functions.

The three historical owner-gap records remain as audit evidence. Each declares its
native identity; a gap closes only if that exact native identity and flag actually
entered the bound use domain. Removing an implementation exposes the gap again.
The unified diagnostic consumes that reconciled result rather than repeating stale
historical labels.

Added meaningful properties reuse existing readers:

- Crowbar: original native player-kill advancement predicate, main hand and actual
  player victim. This flag does not invent a combat ability.
- Slimeball: original native inventory-changed advancement predicate, excluding
  spectators. This flag does not invent bouncing physics.
- Aimbob apple: the existing native consumption owner applies its actual effects.
- `govnoq`: one material family and one variant, regardless of presentation/carrier.
  Existing Fartus damage scaling, Shit Katana recipe, loose-material predicate and
  custom armor classification still read the same scalar flag. TMT's existing
  aggregate root already exposes it. No parallel material or consumption engine
  was needed. Frequent Fartus and recipe reads now avoid copying full NBT.

`randomgovno` has no runtime reader in either legacy namespace; its material use
comes from companion `govnoq`. Case reward/suffix/drop-request/coin icons are private
LbcCases payout descriptors, not physical redeemable item abilities. `randomselect`
is the immediately deleted get_random helper. `luck_key` is obsolete delayed
durability cleanup; useful luck/tool/durability values belong to native components
and generated statistics. Those service fields are explicit in the diagnostic.
