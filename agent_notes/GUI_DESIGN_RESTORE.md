# Восстановление дизайна GUI SkyWars

Этот файл фиксирует правки `GameMenus.java` по исходному GUI `swarogskywars`. Источники datapack и пользовательский resource pack открывались только для чтения. Устройство источника, ограничения исходного аудита и точные связи loot table сохранены в [DESIGN_SOURCE_AUDIT.md](DESIGN_SOURCE_AUDIT.md) и `inventory/design_source_manifest.json`.

## Контейнер и исходные страницы

Перенесённый экран остаётся инвентарём из 27 слотов с заголовком `container.enderchest`; пользовательский инвентарь блокируется на время открытия. `GameMenus` использует source loot table для исходных предметов, включая имя, lore, модели, profile и другие компоненты. Если исходный слот динамический, результат зависит от доступного исходного компонента и runtime-данных. Перенос не доказывает совпадение отрисовки клиента.

- Hub — source page `swrg:0`. Слот 0 берётся из исходной кнопки-компаратора; slot 1 начинает игру с уже выбранной картой; slot 6 открывает магазин без добавленной строки баланса; слот 8 использует исходную голову профиля; на кнопках наборов и навыков в 12 и 14 нет придуманных строк текущего выбора. Слот 26 сохраняет исходное сообщение со ссылками Discord и Planet Minecraft, включая открытие ссылок кликом.
- Настройки — source page `swrg:1000`: source-слоты отображаются из импорта, back — 18, reset — 26. По запросу пользователя кнопка «Язык | Language» в слоте 25 удалена: язык выбирает клиент через ресурспак. Сохранены Java callbacks уже поддерживаемых настроек: PvP, время суток, vanilla kits/skills, выбор события стадий, число жизней, границы и здоровье. Диапазон второй стадии — 0..8, здоровье использует исходные пять значений 2/10/20/40/60. Для прочих source-кнопок внешний вид не означает, что соответствующее исходное действие реализовано в Java.
- Карты — исходные страницы `2000`, `2000b`, `2100`, `2200`, а не заново упакованный список каталога. Для каждой source-карты используется её точная связь map ID → исходный слот; пропуски сохраняются. Back расположен в 18, next — в 26. Идентификаторы с `b` сопоставляются отдельно и не приравниваются сами по себе к `GameConfig.broken`.
- Магазин ключей — source page `6000`, исходные 15 карточек в слотах 0–14 и back 18. Их названия, предметы, lore и формат цены берутся из source stack, в том числе trial key и варианты количества. Java callbacks сохраняют покупку по этим слотам; при успешной покупке проигрывается исходный звук level-up. Закрытые/unlock-варианты из исходных handlers не переносятся этим экраном.
- Vanilla kits — source page `3000`, карточки в слотах 0–17 и 19–23; back занимает 18, reset — 26. Синтетический набор 19 не добавляется. Vanilla skills — source page `4000`, slots 0–12, back 18 и reset 26. Исходные карточки сохраняют их lore; строка `swrg.gui.select` и glint появляются только на выбранной карточке. Сохранение выбора карточки не означает, что её gameplay-механика реализована; в частности, текущие ограничения skills 2/4/13 остаются такими, как описаны в кодовом аудите.
- Cases и cosmetics показывают существующие source loot-кнопки без подмены их компонент Java-именами и lore. LBC selector-страницы также строятся из их исходных кнопок. Для cases/cosmetics/LBC здесь сохранён вид; отсутствующие Java click actions этим изменением не добавлены.

## Пробелы исходных компонентов

В обоих языковых файлах источника отсутствуют значения `page1000.s8`, `.s9`,
`.s10`, `.s11`, хотя loot tables ссылаются на их `Name`. Они перечислены в
`gui_design.json/sourceComponentGaps`; имя остаётся пустым, как при исходном
неразрешённом NBT-компоненте. Новые подписи не придумываются.
Для значений, существующих только в RU (включая стрелки достижений и варианты
защиты от TNT), сохраняется исходный русский текст; при отсутствии точного
двуязычного ключа EN временно получает тот же текст.

Значения поддерживаемых настроек разрешаются из `GameConfig`. Для остальных
показывается исходный вариант по умолчанию; это не работающий переключатель.
Глобальные LBC-лимиты пока равны исходным 9 тринкетам и 4 улучшениям. Они не
подменяются личным выбором профиля. Прогресс challenge ещё не перенесён, поэтому
его числовой компонент остаётся пустым.

Статистика профиля сохраняет целый winrate и две цифры KD, включая ведущий
ноль. Магазин добавляет исходные модификаторы `balance`/`balance_mem` к двум
строкам карточки, используя актуальную валюту профиля. Выбор набора/навыка
добавляет одну строку к исходному lore, сохраняя всё описание.

С 11 октября 2026 отдельная страница статистики расширена по запросу пользователя:
исходная голова с играми/winrate/KD остаётся в слоте 8, back — в 18.
Добавлены карточки побед/убийств (10), смертей (11), монет (13), мемкоинов (14)
и пяти балансов ключей (16, порядок индексов профиля 0–4). Это новые карточки,
а не восстановленный дизайн отсутствующей в датапаке подробной страницы.
Используются существующие ключи ресурс-пака; исходные name/lore головы сохранены.
Данные берутся из профиля только при открытии страницы, без нового тикового
обхода или чтения статистики с диска. Подробная история матчей, урон, время игры
и прочие ещё не собираемые показатели остаются будущим расширением.

## Фикстуры для последующей проверки

Ожидаемые стабильные точки раскладки: hub slot 0 comparator; hub slot 6 ведёт на shop slots 0–14; shop slot 3 содержит trial key, slots 12–14 — gold nugget с исходными lore; back 18, settings health 24 и reset 26; kits slot 0 и skills slot 0; skills slots 11/12 — Wind Runner/Dualist. Map fixtures должны сверяться по source page и source slot, а не по плотному порядку `MapManager.catalog()`.

Общие клики по перенесённым кнопкам проигрывают исходный `minecraft:ui.button.click` (громкость и pitch 2), кроме игроков с тегом `developer`. Условия unlock, locked-предметы и различия между условными/статичными исходными вариантами остаются незавершённым переносом. Наличие source stack не означает готовую реализацию исходной логики клика. Серверная проверка описана ниже; клиентская отрисовка отдельно не сверялась.

## Проверено на сервере — 9 октября 2026

Экспорт финального меню содержит 15 страниц и 246 предметов. Сравнение
`check_design_sources.py --snapshot` прошло без расхождений: 146 проверок
фактических компонентов и 352 ссылки на исходные компоненты. Исправлены
reset настроек (повреждённая наковальня, зелёная исходная подпись) и маршруты
LBC: тринкеты → 11000, улучшения → 8000, наборы → 9000, навыки → 10000.

Живые проверки подтвердили покупки, валюту, selected lore без потери описания,
winrate/KD, инвентарь и работу GUI во время асинхронной загрузки. Точные команды,
логи, версия JAR и ограничения перечислены в [SERVER_TESTS.md](../SERVER_TESTS.md).
Графический клиент и все условные/сезонные варианты не проверялись.

## Исправление навигации и моделей — 9 октября 2026

На странице карт `2000b` запись для `12b` содержала только модификатор
выделения без карточки. Загрузчик ошибочно пытался получить из неё предмет,
выбрасывал исключение и оставлял клиентский инвентарь без синхронизации.
Такие записи теперь пропускаются. Названия карт в сообщениях берутся из
тех же компонентов и ключей, что и GUI (например, `swrg.gui.map.2000.0`).

Переходы обновляют содержимое одного открытого контейнера, сохраняя его ID.
Новая страница сначала полностью строится; после клика отправляется полное
состояние, включая пустой курсор. Обработчик ошибок возобновляет синхронизацию,
которую SGui при исключении из callback оставлял приостановленной.

LBC-категории получили исходные пары страниц: улучшения `8000/8100`, наборы
`9000/9100`, навыки `10000/10100`, тринкеты `11000/11100`. Back — 18,
сброс — 25, next — 26 только при наличии следующей страницы. Сброс очищает
соответствующее поле профиля и сохраняет его, не затрагивая другие категории.
В исходном `11100.mcfunction` нет выдачи карточек: эта страница остаётся пустой
с навигацией. Третьих страниц этих категорий в источнике нет.

LBC loot tables раньше оставались в формате `functions`/`function`, который
26.3 молча игнорировал. `import_gui_design.py` теперь переводит их в
`modifier`/`type`; исходные item model и остальные компоненты выполняются
нативным loot codec. Проверены определения всех 109 пользовательских моделей,
на которые ссылаются импортированные страницы: они присутствуют в ресурспаке.
Пользовательский ресурспак не изменялся; применённые языковые файлы не создаются
заново в моде/template.

Проверка `menu-navigation` отправляет настоящие входящие пакеты кликов:
восемь проходов четырёх страниц карт, переходы LBC, сбросы и их сохранение,
наличие item model и отсутствие предметов на курсоре. Игровая выдача перков,
unlock-условия и бонусы challenge этим изменением не переносятся. Кнопка
сброса challenge-бонусов остаётся визуальной: отдельные бонусы ещё не хранятся
в профиле; обычные LBC-перки она не стирает.
