# Blaze, Ghast, and Snow Gem: projectile source contract

Historical, bounded read-only audit of the old datapack at `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc`. Its implementation-status statements reflect the earlier audit snapshot. IDs 1 Blaze and 2 Ghast are now implemented in the native port; see [TRINKETS_PROJECTILE_PORT.md](TRINKETS_PROJECTILE_PORT.md). Snow Gem (ID 18) remains deferred pending its freeze-system port.

## Identity, selection, and dispatch

`function/swrg_kit_integration/game/trinket_select/select_1.mcfunction` maps selection IDs to loot tables. Loot definitions are `loot_table/trinket/blaze.json` (ID 1; command block proxy; `lbc:trinket_0`; name/lore `lbctrinket.0*`; max stack 99; custom data `trinket:"blaze"`), `ghast.json` (ID 2; `lbc:trinket_1`; `lbctrinket.1*`; custom data `ghast`), and `snow_gem.json` (ID 18; `lbc:snow_pearl`; `lbctrinket.17*`; custom data `snow_pearl`). ID 18's runtime key and display model/name numbering differ from the selection label; preserve the emitted key/model if reproducing this item. `select.mcfunction` grants the first slot unconditionally and gates later slots by global `#lbctrinket` values 2 through 12; `select_1` itself has no special per-ID unlock predicate for 1, 2, or 18.

Bow callback uses objective `bow` (`minecraft.used:minecraft.bow`): `players_tick` sees positive score, runs `items/bows`, then that function resets bow to zero after dispatch. The bow-use/charge advancement excludes dimensions `minecraft:nexus` and `minecraft:imprinted`; Blaze/Ghast dispatch runs only under global `#lbctrinket >= 1`. Crossbow callback comes from `advancement/crossbow.json` (`minecraft:shot_crossbow`, also excluding those two dimensions) into `items/crossbows`, which calls the same dispatcher under the same global gate. `bows_get_trinket` counts each custom-data identity with `clear ... 0`; when copies are present it invokes Blaze/Ghast once, and copy count scales the chance rather than repeating launches.

Snow Gem follows a different event: `advancement/gowno.json` triggers on `player_hurt_entity` when damage is unblocked, the damage type is not tagged `minecraft:arrow_only`, the target is not an interaction entity, and the attacker is outside `minecraft:nexus` and `minecraft:imprinted`. Its reward calls `items/swords`; that function dispatches only when `legacy != 1` and global `#lbctrinket >= 1`. The dispatcher counts `snow_pearl` in the attacking player's inventory, then runs the chance helper. Thus Snow Gem is an outgoing non-arrow hit effect, not a damaged-wearer proc.
## Blaze (ID 1)

Dispatch: `items/bows_get_trinket` → `items/trinket_effects/blaze`. The counted stack size is `tmp`. At one copy it rolls `predicate/chance15.json` (15%); at 11+ copies it fires unconditionally. For 2–10 copies it computes chance `(.250 + .075 × tmp - .075)`, i.e. 2 copies = 32.5%, increasing 7.5 percentage points per copy through 10 = 92.5%. The generic macro random predicate in `blaze_chance_storage` performs that roll. Successful roll calls `charge_small_fireball` once.

`charge_small_fireball` summons exactly one `minecraft:small_fireball` at the triggering player's eye position, then creates a marker one local forward unit from world origin using `execute positioned 0.0 0.0 0.0 ... ^ ^ ^1`. This intentionally extracts the facing vector independent of player position. `other/raycastfireballchick_2` stores each marker Pos coordinate with integer scale 1000, then writes Motion using double scale 0.0016: approximately `floor(directionComponent * 1000) * 0.0016`, or speed 1.6 with quantization. The source does not set a shooter/Owner, custom lifetime, or custom hit handler; vanilla small-fireball behavior applies. `can_deleted` is the only added tag. It plays Blaze shoot sound at the firing command position and kills all `reikast` markers.

Port mapping: the native Blaze trinket preserves the observed aim and speed formula and uses SmallFireball native flight/collision. The old source does not set an owner. The user explicitly approved assigning the shooter as owner: (user) "Да, назначать стрелка владельцем". This owner choice is an implementation requirement, independent of the physical-projectile preference that was given for Acid.

## Ghast (ID 2)

Dispatch: `items/bows_get_trinket` → `items/trinket_effects/ghast`. At one copy the roll is `predicate/chance25.json` (25%); 16+ copies fire unconditionally. For 2–15 copies the chance is `(.150 + .050 × tmp - .050)`, i.e. 2 copies = 20%, increasing 5 points per additional copy through 15 = 85%. Success calls `charge_firework` once.

`charge_firework` summons exactly one `minecraft:firework_rocket` at eye position with `LifeTime:100`, `ShotAtAngle:1b`, `LeftOwner:0b`, tag `can_deleted` and `meowmurnya`, plus one firework item containing five burst explosions (twinkle and trail) with explicit colors/fade colors. It then calls `raycast_vpered_slow` on the rocket while oriented as the player. The helper resets Motion, creates an origin-relative one-unit facing marker, stores each coordinate at integer scale 10000 and writes it at double scale 0.0002: approximately `floor(directionComponent * 10000) * 0.0002`, or speed 2 with quantization. It copies the player's `lbcID2` and `team_number` scores to the rocket and copies player UUID to entity `Owner`. There is no explicit gravity setting or custom hit callback in this helper; lifetime is 100 and vanilla firework behavior handles flight/impact. The initial velocity is explicitly aimed at approximately speed 2.

Port mapping: the native Ghast trinket uses the source rocket lifetime, five-explosion visual payload, owner, and aimed Motion formula; implementation details are recorded in [TRINKETS_PROJECTILE_PORT.md](TRINKETS_PROJECTILE_PORT.md).

## Snow Gem (ID 18; runtime `snow_pearl`)

Dispatch: `advancement/gowno.json` -> `items/swords.mcfunction` (with legacy and global trinket gates) -> `items/swords_get_trinket` count of custom identity `snow_pearl` -> `snow_pearl` chance helper -> `snow_pearl_1`. Formula is `.08 + .02 * copies`: one copy 10%, each additional copy adds 2 percentage points. Success copies the attacker's team score into `*tempt`, then selects any entities within `0.001..7` blocks whose `HurtTime` is exactly 10 ticks and whose team differs (`predicate=!lbc:same_team`). It does not explicitly filter entity type or spectator tag. It runs `workingitems/icesword/pre` on each after aligning to its block and plays `block.snow.fall` to all players at the attacker location. This is an outgoing-hit area freeze, not a launched projectile; no projectile position/velocity/owner/lifetime/hit contract exists.

`icesword/pre` sets `*cold_pre` to 10. Only when the target cold score is below 1 does it call `other/freeze/add_cold`, which reads the Slowness amplifier, adds 1 to that multiplier, and multiplies `*cold_pre` by it. It then adds `*cold_pre` to the target cold score, sets `cold_cd=5`, invokes threshold handling in `other/freeze/check`, and emits snowflake particles. Thus a target already at cold 1 or higher gets +10 on this path; the Slowness multiplier is applied only when cold is below 1. The freeze system has score-threshold branches (`other/freeze/1..10`, `full`) and ongoing ticking/cleanup elsewhere. Snow Gem is deferred until this freeze chain can be ported.

## Port boundaries and unresolved choices

- At the time of this source audit, native support had not yet included IDs 1 or 2. Both are implemented now; refer to [TRINKETS_PROJECTILE_PORT.md](TRINKETS_PROJECTILE_PORT.md) for current status.
- Source-specific Motion formulas and old entity settings above describe the datapack. Native port choices and behavior are recorded separately in the port document; Blaze owner attribution follows the explicit user approval quoted above.
- Snow Gem ID 18 is not implemented. Its source effect requires the `icesword/pre` and downstream freeze chain, so it remains deferred pending that port.
