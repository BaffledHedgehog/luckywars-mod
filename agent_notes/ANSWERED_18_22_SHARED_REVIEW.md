## Concrete findings and verified corrections

1. **Ground Quiver101 used a different damage class and missed cold ally filtering.** Original LbcQuiver.explode built CapturedDamage(PLAYER_EXPLOSION,owner,coldCause), whereas LbcWands' explicit mixed WILD/cold policy handled only OwnerDamageSource. The pre-impulse saved-cause filter called Wands but therefore fell through to general nonprojectile admission, permitting allied impulse even if native team checks rejected HP. Root/agentB replaced the ground body with `babylonEffects.quiverExplosionAt`; current `LbcQuiver.java:125` delegates to the shared OwnerDamageSource producer. Living/ground101 now reach the same explicit policy without a proxy entity.

2. **Null explosion source lost native TNT child authorship/policy after proxy removal.** Cached native26.3 `ServerExplosion.getIndirectSourceEntity` bytecode0–7 reads only its Entity source and calls Explosion.getIndirectSourceEntity(source); it ignores explicit DamageSource owner. `TntBlock.wasExploded` bytecode49 consumes that result and constructs PrimedTnt at54 before publishing at79. A radius1 explosion with source=null therefore previously created owner-null TNT; entity-only inheritChild(null,child) could not recover its cause. Root now resolves OwnerDamageSource's saved author in HazardPropagationMixins getIndirectSourceEntity, calls `inheritExplosionChild(explosion.getDamageSource(),spawned)` for null-source chains, and registers children in the Babylon secondary map before publication. Subsequent children use entity-based inheritance. Saved cause, WILD/cold policy and epoch travel together. Native/reflected current authority updates the secondary cause while preserving its policy. Native TNT's discard-before-explode path retains its saved cause through final explosion.

3. **Offline cold101 owner failed open.** Cold contributions can remain on another target after shooter disconnect; their actor lookup can return null. The original OwnerDamageSource admission contained `owner==null`, admitting all living targets. Previous Babylon-only101 was WILD, so ordinary Quiver101 coexistence exposed default ally harm. Current LbcWands.java:1551–1555 now requires an available author for cold policy; WILD retains its original admission. Babylon secondary canAffect similarly fails closed for missing cold authority. The native timing/cause queue is otherwise unchanged.

4. **Explicit self admission still met native player team rejection.** Moisei canAffect and new Quiver fangHit admit the caster, but native ServerPlayer.hurtServer canHarmPlayer rejects self on an own scoreboard team with friendly fire disabled. The actual hook is LbcDamageMixin.java:31–45 (not a separate friendship mixin); it wraps ServerPlayer.canHarmPlayer and calls LbcDamage's existing policy helpers. Root added an exact victim==attacker exception for managed Moisei, Quiver/Babylon secondary and the exact Quiver fang tag. It does not grant other allied players admission. OwnerDamageSource uses its existing native bypass and explicit final cold/WILD filter.

5. **Reflected self met a second, earlier filter.** LbcDamage.allowDamage separately queried reflectedOwner and called projectileTarget, which always excludes the owner itself. The native friendship fix alone could not admit reflected managed self TNT. Current LbcDamage.java:167–173 now has an exact reflected==victim exception for these managed TNT/secondary families before applying the ordinary other-target reflected filter. Family role/Greed and other-allied-player protection remain in force.

All five corrections were observed in the updated shared Java before this review froze. Runtime tests still belong to root.
