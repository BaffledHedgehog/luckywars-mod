# Независимая проверка runtime LBC

Проверка сопоставляет runtime-документ с исходниками пакета, а не с перенесённым Java-плагином. В назначенном job 250 функций: 245 исполняемых и 5 пустых/комментарных (`players_tick90s`, `projectilestick_homing`, `raycastselector_player_check_skill_homing`, `respawn_2pre`, `tick1s_not_nexus`). Перепроверены загрузка и расписания, обычный и остановленный tick, циклы игроков/мобов/предметов, `start`/`resets`/`respawn`/конец игры, raycaster и marker-dispatch, а также NBT-сохранение при time stop. После запроса root stateless helpers и числовые таблицы перепроверены напрямую; exact manifest всех 250 job-source paths с пометкой `focused_helper_reread` лежит в [read manifest](inventory/lbc_runtime_read_manifest.json).

Важное условие достижимости player-веток: локальный entity-type tag явно содержит `minecraft:player` и использует `replace:false`, поэтому вызов `mobs_tick` через `@e[type=#minecraft:mobs]` действительно включает игроков. Та же причина делает достижимыми ветки игрока в `mobs_1s`, `mobs_2t` и `mobs_5t`; при проверке нельзя полагаться на состав vanilla-тега без локального merge. В helper-проходе прочитаны напрямую все raycast_vpered-варианты, rand_motion и позиционные/угловые random-семейства, homing, get/set team helpers, reforge/craft, random_debuff/luck, reduce_count, sqrt и Motion shrink. У `reduce_motion_to_10x_rec` команда `/=10; *=9` означает уменьшение примерно до 90% за шаг (scoreboard floor division), а не деление на10; внешний caller проверяет оси отдельно, внутренняя рекурсия повторяет проверки отдельно для X, Y и Z. В `raycast_vpered_*` marker на `^ ^ ^N` после `positioned 0 0 0` действительно задаёт направленный вектор длины N; scale `data get` × `store` надо перемножать (например, base вариант даёт ×8, `_3` ×3.5, `_big` длину7). Для noise-вариантов описаны итоговые величины после scale, не промежуточные score-ranges.

Проверены интервалы scheduled roots: `load` ставит 12 повторяющихся циклов; каждый непустой цикл сначала планирует следующую итерацию. `time_stop` очищает 11 конкретных расписаний, оставляя `tick1salways` для отсчёта 11→1; завершение вызывает `datapack_enable`, затем `load_aftertimestop` повторно запускает полный набор. Значения `schedule` с `t` — тики, а `s` — секунды; NBT `fuse:Ns` — short со значением N тиков. Coverage содержит все 250 источников; 5 пустых функций отмечены `non_runtime`, остальные связаны с точными заголовками основного runtime-документа. Проверка Markdown targets и точных заголовков выполняется общими checker-ами; семантические ссылки не заменяют описания фактического поведения.

Координатор дополнительно прочитал весь человеческий документ, перепроверил формулы vect/recur, scale и floor, abyss score→Y, sqrt, reforge/reduce_count и cleanup. Исправлены пороги slow/slower, шум storage ±tmp2/10000, привязка Pos к floor, условный bedwars-end и область удаления end_resets. Строгая проверка [26 Motion/Pos-вариантов](inventory/runtime_noise_audit.json) сравнивает весь порядок исполняемых команд с явной таблицей параметров, включая дополнительные вызовы/теги; расхождений нет. Это приёмка описания текущего исходного datapack; совместимость всех старых команд с сервером26.3 запуском не проверялась.
