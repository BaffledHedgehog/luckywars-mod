# Overload armor and Crux: legacy source contract

Read-only source: `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc`. This note records observed behavior for the native implementation; the legacy datapack and its server were not changed.

## Item identity and equipment activation

The four loot tables under `loot_table/neko_set_overload/` create leather armor with custom data `{transformable:1,<slot>:1,overload:1}`. They keep the slot-specific source models `lbc:armors/overload_{helmet,chestplate,leggings,boots}`, tooltip style `lbc:tier_s`, 900 durability, `equippable.asset_id=lbc:overload`, and the source armor/toughness values (helmet 3/2; chest 8/2; leggings 6/2; boots 3/2 and safe-fall-distance +16). The pieces are distinguished for behavior by custom data `overload:1` plus their actual armor slot; display name alone is not an activation condition.

`items/changed_inventory/sel.mcfunction` derives five runtime tags from the equipped slots: `overload_helmet_active` from `armor.head`, `overload_chestplate_active` from `armor.chest`, `overload_leggings_active` from `armor.legs`, and `overload_boots_active` from `armor.feet`, each requiring the `overload:1` custom-data flag. It counts matching pieces in `armor.*`; count >=4 adds `overload_full_active`, otherwise it removes that tag. Since there are four armor slots, this is a complete four-piece set. Do not count matching items in the player inventory, offhand, cursor, or crafting grid.

That selector is rewarded by advancement `lbc:penis` (`advancement/penis.json`, inventory_changed trigger). `players_tick.mcfunction` revokes that advancement each tick so the next inventory change can re-run it. `resets.mcfunction` also calls `items/changed_inventory/sel` directly. The native project has a better event/cache pattern to reuse: `LbcEquipmentMixin.onEquipItem` marks `LbcMana` equipment dirty; `LbcInventoryTriggerMixin` and `LbcCursorCraftingMixin` coalesce inventory/cursor changes through `LbcMagic.inventoryChanged`, which also invalidates the mana equipment cache. `LbcMana.equipment()` recomputes cached gear only when dirty, and `LbcMagic.tick()` drains its dirty UUID set before passive dispatch. Overload state should be derived from the four equipment slots through that cache/dirty path, rather than scanning every player's inventory every tick or trusting stale entity tags. Ensure reset/death/respawn and initial entity load invalidate or refresh the cache when internal inventory mutation does not invoke the normal callback.

## Piece passives and timing

The legacy `minecraft:tick` function runs once per server tick. `tick_not_timestopped.mcfunction` visits entities, and `mobs_tick.mcfunction` calls `players_tick` for non-spectator players not carrying `time_stopped`. `players_tick` is therefore a per-tick path, not the five-tick passive cadence used by some artifacts.

- **Helmet:** `other/negative_mana.mcfunction` skips the ordinary mana-debt tiers while `overload_helmet_active` is present. At mana <= -20001 it still runs `negative_mana_5_helmet`: it computes the source deep-debt health threshold (mana/manamax ratio, 0.045 scale), then explodes if the threshold reaches current health or uses `damage_with_tmp_void` otherwise. The helmet delays the first four negative-mana tiers; it does not make the wearer immune to the deepest tier.
- **Chestplate:** while mana <= -1, `negative_mana_resist.mcfunction` refreshes Resistance for one second each tick. Amplifiers follow debt bands: 0 at -1..-5000, 1 at -5001..-10000, 2 at -10001..-15000, 3 at -15001..-20000, and 4 at <=-20001. This runs alongside the helmet's deep-debt branch when both are equipped.
- **Leggings:** the jump hook is in `items/armor.mcfunction`, called when scoreboard `jump1 >= 1`; it requires `overload_leggings_active` and `predicate=lbc:sneak`. `leggings/jump.mcfunction` gives Levitation for 1 second (20 ticks) at amplifier 76 when mana >= -20000, or amplifier 127 when mana <= -20001; it also grants Resistance amp 4 for 2 seconds (40 ticks), sets `overload_jump=20`, plays sound/particles, and removes 2500 mana from every player within 4 blocks (including the wearer). `players_tick` decrements this timer every tick and clears Levitation when it reaches 18. The countdown continues even if leggings are removed because the countdown is gated by the timer, not the active-leggings tag. Death/reset cancels the pending jump by zeroing the timer.
- **Boots:** the automatic slam starts only while `overload_boots_active`, sneaking, airborne (`OnGround:0b`), `overload_jump<=0`, and `overload_slam=0`; it additionally compares the player's vertical 8-block column against the source reference column at `(10241023,127,10241023)` using `if blocks ... all`. The native implementation adapts that location-dependent condition into a free-fall check after user approval: “Да, проверка свободного падения”. `boots/slam.mcfunction` adds gravity modifier `minecraft:slamslamslaaaaaaamslaaam` +0.6, adds entity tag `overload_slam`, sets `overload_jump=2`, and plays sound. While tagged, `boots/tick.mcfunction` runs every tick: particles, Resistance amp 4 for 1 second (20 ticks), adds 2 to `overload_slam`, and impacts on a non-air block below or `OnGround:1b`. `boots/impact.mcfunction` squares the accumulated score for damage (`tmp=0.04*slam²`), clamps the score to 60..140 for radius/scales, then calls `impact_2`; it removes the gravity modifier, zeros the counter, and removes the active-slam tag. `impact_2` damages non-allied mobs in the radius, emits particles/sound, adds mana to the wearer, and drains mana from nearby players. The helper copies the wearer team number into fake score `*tempt`; predicate `lbc:same_team` compares each target against it, so native damage filtering must preserve the allied-target exclusion. The source does not gate leggings activation or the slam loop on `stopper_magic`; its mana-regeneration/negative-mana dispatcher does have the separate anti-magic gates below.

## Negative mana, full set, and Crux dependencies

`players_tick` calls `other/manaregen` only when the legacy `nomagic` score is zero and no `stopper_magic` marker is within 20 blocks. The `other/manaregen` helper first checks Crux drop eligibility (`mana<=0` and no `obtained_crux` tag), updates mana regen, then calls `negative_mana` when mana is negative. The normal debt ladder is -1..-5000, -5001..-10000, -10001..-15000, -15001..-20000, and <=-20001. Helmet skips the first four; chest applies its resistance bands for every negative amount.

`damage_with_tmp_void.mcfunction` branches on `overload_full_active`: incomplete sets spawn the ordinary tentacle path, complete sets use `tentacle_full_set`. The full-set path changes the tentacle's source scale/trajectory and its target damage helper restores HP to the caster carrying `overload_full_active`. Other full-set consumers are the spell path's temporary +10,000,000 mana adjustment (`items/spells.mcfunction`, removed again when the resulting mana is >=8,000,000) and the five `tentacle_full_set` calls made by `other/overload_crux/use.mcfunction`. Thus full-set activation must update promptly on equip/unequip; it is not just cosmetic.

The Crux loot item is a carrot-on-a-stick with custom data `{craftusable:1,magicwand:1,overload_crux:1}`, model `lbc:overload_crux`, style `lbc:tier_q`, stack size 99, and no max-damage component. Source config sets `overload_crux_mana_use=7500`. Selecting it through `workingitems/spell1_default.mcfunction` casts only outside a 20-block `stopper_magic` region. `overload_crux/use.mcfunction` subtracts the configured mana unconditionally, invokes the full-set tentacle helper five times, replaces each *matching-slot diamond armor item* with its corresponding overload piece (other armor is untouched), plays a sound for each replacement, then consumes one Crux. It does not require all four diamond pieces or an existing overload set.

Crux drop/rearm state is the entity tag `obtained_crux`: `other/manaregen.mcfunction` spawns one at mana <=0 only while the tag is absent, then `overload_crux/give.mcfunction` adds the tag. The same mana helper removes the tag when mana >= manamax and manamax >0, allowing a later debt cycle to grant another. `resets.mcfunction` and `leave_death.mcfunction` also remove `obtained_crux`, so death/reset rearms the drop gate. `leave_death` additionally zeros `overload_jump` and `overload_slam`, removes the `overload_slam` tag, and removes the slam gravity modifier. `resets` zeros both counters and removes the slam tag. Impact itself also removes its temporary gravity state. Preserve these cleanup paths; do not let the cache's durable armor state preserve a transient jump/slam state.

## Reusable native helpers and implementation boundaries

- `LbcMana` already owns scoreboard-backed mana reads/writes, `add`, per-player ticking, `inventoryChanged(UUID cache invalidation)`, and entity load/unload hooks for temporary effects. Crux's explicit cost can use the signed mana API; `trySpend` is intentionally a nonnegative guarded spend and does not match the legacy unconditional subtraction.
- `LbcMagic.inventoryChanged` is the existing coalesced dirty-inventory entry point and also invalidates the mana gear cache. `tickPassives()` demonstrates dispatching only registered carriers rather than scanning all players' inventories. Its five-tick cadence is specific to the existing artifact families; Overload's source passives tick once per game tick.
- `LbcItems.clear(player)` composes Frost, color effects, and Mana cleanup. `LbcItems.clearEffects` is broader and removes native effects plus custom state. `GameController.died`/`resetPlayer` already call item/LBC cleanup; wire overload's temporary slam/jump cleanup there (and on stop) while allowing equipped armor identity to be re-derived after respawn.
- `LbcFrost` is a good pattern for bounded per-entity temporary state, explicit `clear`, and stop cleanup. Its cold/frozen timers are second-based and should not be copied as the Overload tick cadence.

## Native movement implementation

`src/main/java/me/skywars2/game/LbcOverloadArmor.java` owns the leggings and boots movement state. It uses the `LbcMana.overloadArmor(player)` equipment bitmask (head=1, chest=2, legs=4, feet=8) and the existing scoreboard-backed `mana.score`/`mana.add` helpers. The jump hook is shift-gated and uses the cached leggings bit; `tick` uses the cached boots bit, pauses for `time_stopped`, and checks the current feet block and the eight blocks below against the native `minecraft:airs` block tag. This implements the user-approved free-fall behavior without consulting a remote reference column or loading chunks. Temporary gravity, timer, slam tag, and owned Levitation are removed by `clear`.

The source effect durations are seconds (`effect give <duration>`), so the native durations are 20/40/20 ticks for jump Levitation, jump Resistance, and slam Resistance respectively. Jump mana drain includes the wearer and skips observers; slam drain excludes the wearer and allies. Impact targets use native `minecraft:mobs` membership (including players), native alliance checks, the observer predicate, and `DamageSources.outOfBorder()`. The impact score keeps the source's discontinuous clamp: <=60 maps to 60, >=200 maps to 140, and 61..199 is unchanged; damage uses the original squared counter while radius/particle count use the clamped counter.

This class has not been built or exercised in a runtime check. Root owns the `LbcMana` bitmask addition and jump-hook wiring.
