## Findings

- [LbcMagmify.java](../src/main/java/me/skywars2/game/LbcMagmify.java): CAPTURE exhausts a 26-neighbor BFS before submitting a complete detached plan; WRITE starts only after PLAN_WAIT. Every node/cell/lava tick costs a queue step. Thus early capture gives no visible terrain progress.
- [LbcStonekivi.java](../src/main/java/me/skywars2/game/LbcStonekivi.java): shared queue has 3 ms AND 128 steps per tick. A sole Sun captures at most 128 nodes/tick, then writes at most 128 cells/tick. For 100,000 nodes capture alone needs >=782 ticks (~39 seconds at 20 TPS), even when CPU budget is mostly unused. Other terrain/spell jobs share these limits.
- No global busy-cast latch found. Every mode-3 hit appends independent Work. LbcWands admission checks template preparation, time stop, suppression and normal resource/role gates, not pending Sun work. LbcStonekivi.ready() is template readiness. Preserve this behavior.
- Planner adds multiple full traversals/maps/copies and per-cell neighbor allocations after capture; executor is existing MapManager.templatePreloader. It can introduce waiting, but the hard cell-step cap and phase barrier already explain delay without profiling.
- Existing dimension bug: writeOneCell reads captured level but calls restoreSnapshot(pos,...) targeting MapManager.level. Use existing restoreSnapshot(level,pos,...) overload; attribution already distinguishes owner.level()==level.
- Existing MAP_WRITE_FLAGS constant in LbcMagmify is unused. Actual flags/consumption/network writes belong to MapManager.restoreSnapshot; do not add a second writer.

## Simple safe streaming design

Keep the shared Work scheduler and loaded-only server-thread world access. Let one Sun step process a modest bounded microbatch; check a local deadline frequently so the 3 ms budget remains meaningful. Avoid globally raising the shared step cap, which would alter unrelated workloads. A generous cell ceiling should be a fairness safeguard, not the main throughput throttle; choose via measurement.

For each dequeued original cell, capture its complete 26-neighbor halo BEFORE any replacement. Retain first-seen BlockState and solidRender for non-air cells; retain visited air information too. Enqueue original non-air neighbors exactly once. Only then classify that cell from the frozen six-face observations and immediately write its base replacement. The six faces are all within this halo and any original non-air face belongs to the same connected component, so no whole-component knowledge is needed for base classification or original-surface membership.

Preserve exact priority: all six original neighbors solidRender => lava; no original occupied faces => magma; absent below => reinforced deepslate; free horizontal face => ore; absent above => stone; otherwise leave state. Record original surface membership, bounds and reservoir center sample incrementally. Keep final entity impact phase so complete center and once-per-target behavior remain intact.

Record spike proposals during capture but apply them only after BFS drains. This is the simplest way to prevent newly created lava outside the original component from becoming BFS input. Defer fluid ticks until capture ends too; verify native random/fluid updates cannot grow the explored shape mid-capture. Base writes still stream visibly throughout capture. If spikes must stream too, every destination and its relevant original neighborhood must be captured before mutation; this is considerably easier to get wrong.

Use the existing immutable lists/catalogs and selectSpikeDirection/randomState logic rather than creating another terrain service. If no detached computation remains, remove the obsolete future/plan phases rather than retaining a worker merely to move tiny local decisions off-thread. Document the final ownership change in ARCHITECTURE.md.

## Correctness traps

- Reading live neighbors AFTER rewriting a node changes solidRender classification (e.g. lava versus original stone). Looking only in the currently discovered map also mistakes undiscovered faces for air. Halo capture must precede classification and mutation; lookups must prefer original observations over own writes.
- New spikes or flowing lava can bridge components and make the BFS recursively crystallize its own output. Snapshot air as well as non-air; do not enqueue cells introduced by this cast. Do not prematurely discard old original states: later nodes need them.
- Overlapping casts must not share a mutable original snapshot. Each uses its own first observation; recheck current BlockState immediately before writing and skip contested cells. This retains the existing state-based protection (which does not detect ABA or inventory-only edits).
- Deferred spikes can override a base cell this same cast already wrote. Comparing only against its original state would incorrectly reject its own write. Track the last successfully written state per touched cell, and accept only original or that expected own state as appropriate. Never accept an arbitrary replacement-looking state merely because it is lava/ore. Same-state concurrent writes remain inherently indistinguishable under existing equality semantics.
- For spike-only positions preserve existing semantics: loaded/build-height check, immediate sample/write in the server step, destination may be replaced. Do not restore captured container NBT.
- All replacements must use MapManager.restoreSnapshot(capturedLevel,pos,new BlockSnapshot(state,null)): it clears old container contents and suppresses drops. Wrap a microbatch in the existing trapChanges(owner,...) or worldChanges(capturedLevel,owner,...) context, preserving owner after dimension change and delayed attribution.
- Preserve stop/cancel lifecycle, time-stop pause, loaded chunk bounds, observer/service/team target helpers, no queue truncation, and no added owner-death cancellation. Sun currently continues using captured level/owner; changing cancellation policy is separate behavior.
- Keep the broad-phase native entity query and existing touchesSurfaceWithinRange/target/displaced helpers. Existing impact tests original surface even when a contested write was skipped; changing that requires an explicit behavior decision.
- Per-cell setBlock with UPDATE_CLIENTS already queues native network updates; bounded server ticks allow progressive delivery. Do not replace this with full-chunk resend, direct section mutation, or off-thread world writes.
