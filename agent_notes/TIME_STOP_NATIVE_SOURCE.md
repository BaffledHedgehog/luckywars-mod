# Native time-stop audit (26.3, 2026-10-21)

Primary source: `.gradle/loom-cache/minecraftMaven/net/minecraft/minecraft-merged-d6f9bb6878/26.3/minecraft-merged-d6f9bb6878-26.3-sources.jar`. Read ARCHITECTURE and relevant AGENTS entries. No build/server or implementation changes.

## Recommendation

One match-owned manager with per-ServerLevel active predicate and per-entity exemption predicate; never mutate global TickRateManager, execute `/tick freeze`, or change gamerules. Keep vanilla tick-step behavior by combining scoped predicates with existing vanilla conditions. Existing `LbcWands.timeStopped()` currently reads scoreboard `time_stopped` in `lbc.math`; replace/delegate to manager, retain compatibility if needed. Existing timers broadly use global `timeStopped()` and entity tags: exemption-aware player abilities require auditing those call sites, otherwise exempt Stand users still cannot use many abilities.

## Exact native seams

* `ServerLevel.tick(BooleanSupplier):void`, lines 361+: obtains `TickRateManager`, then local `boolean runs = tickRateManager.runsNormally()`. A scoped expression hook at this call can return `original && !manager.worldStopped(this)`. This naturally skips weather advance, tickTime, scheduled block/fluid queues, raids, block events, empty-time advance, dragon fight; it DOES NOT by itself stop entities, chunk simulation or block entities.
* `ServerLevel.tickNonPassenger(Entity):void`, line 829: calls `Entity.commonTick():void` then `Entity.tick():void`, then recursively private `tickPassenger(Entity vehicle, Entity entity):void` (line 842), which calls commonTick + rideTick and recurses. Gate before commonTick for frozen entities, including passengers. commonTick advances invulnerableTime and tickCount. Skipping tick catches native AI, projectile motion, TNT fuse, cloud lifetime, effect duration, fire etc. Prefer also scoped OR at `TickRateManager.isEntityFrozen(Entity):boolean` call in ServerLevel.tick, before checkDespawn, so frozen entities do not despawn. Vanilla isEntityFrozen excludes Players and any vehicle with player passengers; it cannot express this feature unmodified.
* `ServerPlayer.tick():void` (581) runs gameMode.tick, cooldown/menu/camera tasks via level entity path. **Separately**, `ServerGamePacketListenerImpl.tick():void` calls private `tickPlayer():boolean` (322), which calls `resetPosition()`, `ServerPlayer.doTick():void`, then `absSnapTo(DDDFF):void` to firstGood coordinates. `doTick` (651) calls `super.tick()` and food tick: cancelling ONLY level tickNonPassenger does not freeze player physics/effects. Gate frozen `ServerPlayer.doTick` at HEAD or its exact invocation, while keeping connection.tick alive. Do not cancel entire connection.tick: acknowledgements/keepalive must continue. Gate level commonTick/tick path too if all native timers must pause.
* `Level.tickBlockEntities():void` line 529: ticker eligibility uses local `boolean tickBlockEntities = tickRateManager().runsNormally()`. Scoped expression `original && !manager.worldStopped(level)` keeps removed/pending ticker housekeeping while skipping ticker.tick; stronger than cancelling whole method.
* `ServerChunkCache` private `tickChunks(ProfilerFiller):void` line 363 is inner simulation-only overload: natural spawning, tickSpawningChunk, ServerLevel.tickChunk, custom spawners. Gate this overload for affected level; outer private `tickChunks():void` still broadcasts changed chunks; public `tick(BooleanSupplier,boolean):void` still handles tickets/unloads/cache. Do not cancel public cache tick or ServerLevel.tick wholesale. More narrow fallback: gate `ServerLevel.tickChunk(LevelChunk,int):void` (503), which covers precipitation + block/fluid random ticks, but this alone leaves natural spawning/lightning in chunk spawning path.
* Scheduled ticks are `LevelTicks<Block>.tick(long,int,BiConsumer)` / fluids from ServerLevel.tick lines 397/399. Skip queue tick calls, NOT tickBlock/tickFluid callbacks (callbacks would consume scheduled entries). `tickTime():void` (482) increments gameTime and invokes server scheduled functions. Suppressing tickTime keeps deadlines relative; when gameTime comes from a different advancing level/shared data, queued deadlines can become overdue on resume. Verify multi-dimension/shared clock behavior before claiming exact delay preservation. WorldClock daylight is server-managed in 26.3; skipping level tickTime alone does not establish frozen daylight.

## Frozen player controls and momentum

Existing `MovementLimitsMixin` provides verified packet-thread-safe injection sites after `PacketUtils.ensureRunningOnSameThread(Packet,PacketListener,ServerLevel):void`: `handleMovePlayer(ServerboundMovePlayerPacket)`, `handlePlayerInput(ServerboundPlayerInputPacket)`, and grouped vehicle/command/abilities handlers. It also intercepts `handlePlayerPositionChange(double,double,double,float,float,boolean,boolean):void` and `handleAcceptTeleportPacket` absSnapTo redirect. Reuse structurally, with separate stop predicate: electrical stun intentionally simulates involuntary physics and must retain its behavior.

`handlePlayerInput` records lastClientInput and shift state; clear stale input when entering freeze and reject fresh input. `handleMovePlayer` applies rotation even when awaiting teleport; cancel/limit frozen movement after thread enforcement. Retain teleport ID acknowledgement, but prevent ack position/rotation from overwriting frozen anchor. Keep connection first/last-good positions synchronized with anchor and clear floating counters; issue native authoritative correction when needed. Packet cancellation alone leaves client prediction drifting. Native teleport calls may alter velocity: save exact Vec3 before correction and restore deliberately, with a motion packet to client. Preserve original momentum once on transition, rather than repeatedly saving zero/corrected momentum; restore once on thaw, clear snapshot on death/disconnect/dimension/epoch reset. Explicit policy is needed for impulses received during stop (discard versus accumulate); merely skipping tick leaves setDeltaMovement/addDeltaMovement calls from active attackers possible. Exempt observers before any freeze/control predicate; exempt have_stand / real stand_clocks holders per legacy contract. Mounted frozen/unfrozen combinations need policy: skipping a frozen parent prevents its exempt passenger recursion, and an active parent can positionRider a frozen passenger. Do not silently promise correct mixed mounts without handling this.
