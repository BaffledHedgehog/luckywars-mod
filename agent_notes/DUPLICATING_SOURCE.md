# Duplicating: исходное поведение (исследование, 20.10.2026)

Файл описывает legacy-источник. Spelling источника: `dublicating_wand`; папка `avarice` здесь относится именно к Duplicating, не к режиму Consuming Avarice.

## Решения автора (user), 20 октября 2026

Обычный режим переносится по замыслу автора: хаотически перемещать, зеркалить,
копировать, удалять и вращать случайные фрагменты разных размеров/форм около
траектории. Старые последовательности clone ниже описывают костыль исходника,
а не обязательный алгоритм нового режима. Контейнеры копируются с содержимым.
Expand берёт источники в других измерениях, назначения — измерение заклинания.
Испытание нормализуется: основной центр вниз на 200 тиков плюс 90 центров
с разбросом на 30 тиков; все сохраняют владельца. Divide вызывает terminal
только однажды согласно общему правилу первого попадания в AGENTS.md.

Источник S = `E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/`; A = S + `workingitems/awaken_tuntija_wands/avarice/`. Ссылки ниже — точные файлы/строки относительно этих корней.

## Простыми словами

Обычный жезл посылает невидимый движущийся центр. Каждый тик возле него выбирается случайное место и направление; там несколько последовательных clone размножают блоки, после чего центральный маленький куб стирается. Academy Default повторяет это. Expand использует большие области и дополнительно пытается копировать блоки из других измерений. Divide мгновенно ищет точку по взгляду и раскладывает вокруг неё 26 копий куба. BlackHole движется, ставит неполный обсидиановый шаблон, притягивает сущности и понемногу повреждает часть мобов.

## Expand: точная последовательность до пяти больших копий

Все тройки ниже — local ^ coordinates; команды выполняются последовательно, назначения — минимальный угол, не центр.

1. Текущее измерение: (0,0,0)..(15,0,0) → (−16,0,0).
2. Текущее: (8,8,8)..(5,5,5) → (−5,−5,−5).
3. Nether → overworld: (8,−8,8)..(5,−5,5) → (−5,5,−5).
4. Nether → overworld: (−8,8,−8)..(−5,5,−5) → (5,−5,5).
5. End → overworld: (0,0,0)..(0,0,15) → (0,0,−16).
6. End → overworld: (0,0,0)..(0,15,0) → (0,−16,0).
7. nexus → overworld: (8,−8,8)..(5,−5,5) → (5,−5,−5).
8. nexus → overworld: (−8,8,−8)..(−5,5,−5) → (5,5,−5).

A/rand_rot2_2:1–13 вычисляет integer X/Z помощника ±20 и передаёт storage minecraft:lbc.math в rand_from_dim; тот делает forceload add прямоугольника в End, Nether, nexus. После 8 clone сразу rand_from_dim_remove удаляет те же прямоугольники, до 5 финальных clone. Никаких random dimension/coordinate в rand_from_dim нет. В исходнике нет ожидания загрузки или восстановления прежнего forced-состояния.

## Неоднозначности legacy-кода (решения выше имеют приоритет)

- Сохранять ли буквальное межизмеренное копирование Expand? Оно всегда направляет такие копии в overworld, даже если исполнитель не там; координаты локальные, без Nether scaling. Мгновенный forceload не гарантирует готовность чанков; ошибки clone не прерывают оставшуюся цепь. Нужна авторская семантика неуспешных/незагруженных источников. Нельзя слепо remove чужого forceload.
- Все clone без masked/filtered/force/move: стандартный replace normal, включая воздух и BlockEntity, содержимое контейнеров дублируется. Пересечение source/destination может отклонить конкретную операцию. Сохранять содержимое и такие отказы? Последовательность обязательна для наблюдаемого результата: последующие clone могут читать уже изменённую область; единый snapshot на весь импульс изменит поведение.
- facing @e[tag=dublicating(_2),limit=1] без nearest/owner/distance может выбрать чужой или старый центр в измерении. У помощников нет copied owner/team. Связать с родителем или сохранить хаотические конфликты? Локальные селекторы distance .001 также способны выбрать предыдущего помощника, если два совпали.
- Trial создаёт 91 marker всего, но рандомизирует limit90: собственный исходный marker может попасть в эту выборку, один из 91 останется без рандомизации. Новым 90 owner/team не передаются; actived после переноса/разброса ищется у первоначальной точки ^^^7 и обычно никого не найдёт. Требует решения автора, а не тихой нормализации.
- Divide два независимых hit условия могут вызвать divide_end дважды на одной точке (моб внутри не-air), т.к. второе не проверяет уже Distance=1000. Это повтор тех же 26 clone. На промахе цена всё равно списывается. Сохранять?
- BlackHole использует template с вероятностью .65 и финальный куб удаления, не математическую сферу удаления. Союзные обычные сущности притягиваются. Урон outside_border без явного автора в команде; перенос обязан использовать общий owner/lifecycle, но правила фактического типа урона уточняет root.
- Lifetime 200/100/300 указан как фактическое число обычных raycastselector-вызовов при штатном тике, не новый таймер по wall clock. Time stop пропускает tick_not_timestopped; эти сущности не имеют marker_2t. Помощник обычно выполняет clone на следующем доступном проходе и сразу удаляется, не живёт три полных тика.

## Готовые native точки переиспользования

Прочитаны AGENTS.md и релевантные разделы ARCHITECTURE.md. `MapManager.snapshot/restoreSnapshot` (1271/1290) сохраняют состояние и BlockEntity; нативный clone должен сохранять стандартные AABB/normal-проверки и порядок, не создавать второй движок snapshot. Общая бюджетная очередь `LbcStonekivi.queuedWork` (62), покрытие `BlockAreaWork`, native journal/`LbcIndirectKills.trapChanges` предназначены для тяжёлых записей. Owner/epoch/cancel — существующий lifecycle LbcItems и сервисов. Чтение мира/BlockEntity и записи остаются серверными; worker MapManager допустим для чистого плана, не прямого мира. Это карта интеграции, не принятие решений о спорных механиках.
