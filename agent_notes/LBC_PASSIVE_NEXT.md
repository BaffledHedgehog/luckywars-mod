# LBC: следующий срез — `broken_totem` и `phd`

Сверка проведена по отключённому datapack LBC старого сервера, копии datapack в Paper-плагине, Java-таблице выдачи kit и пользовательскому resource pack. Каталожная строка `ITEM_LOOKUP.md` подтверждает item ID/model/custom-data, но сама по себе не описывает игровые callbacks.

## Kit 1 — Broken Totem

`lbc.kit=1` выдаёт loot `lbc:kit/broken_totem`. Это один `minecraft:totem_of_undying`, count 1, с `minecraft:item_model=lbc:broken_totem`, `custom_name` translate key `broken_totem` с `italic:false`, и `minecraft:custom_data={broken_totem:1}`. Lore нет. [Loot](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/kit/broken_totem.json), [kit dispatcher](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/swrg_kit_integration/game/kit_select/select.mcfunction), [Paper loot copy](E:/servers_mew/cringe1_21_4_skywars/plugins/luckywars/src/main/resources/datapack/data/lbc/loot_table/kit/broken_totem.json), [Java kit map](E:/servers_mew/cringe1_21_4_skywars/plugins/luckywars/src/main/java/me/luckywars/swrg/SwrgNativeService.java).

Callback — advancement `lbc:broken_totem`, trigger `minecraft:used_totem`, тот же custom-data предикат. Он срабатывает при штатном спасении тотемом от смертельного урона; отдельного datapack damage-event обработчика здесь нет. Игрок должен быть вне `minecraft:nexus` и `minecraft:imprinted`. Reward вызывает `lbc:drops/skrimmer`, добавляет `skill_issue` +100 и отзывает advancement для повторного срабатывания. В исходной функции `skrimmer` проигрываются ghast/cave sounds, создаются 5000 campfire-smoke particles, затем запрашивается blindness 6 секунд, amplifier 10. В native 26.3 `LivingEntity.tryUseDeathProtection` синхронно вызывает `USED_TOTEM.trigger` *до* `setHealth(1.0F)` и `DeathProtection.applyEffects`; `DeathProtection.TOTEM_OF_UNDYING` первым применяет `ClearAllStatusEffectsConsumeEffect`. Значит, callback blindness очищается тут же штатным тотемом, хотя звук и частицы уже отправлены. Это подтверждено локальным source jar 26.3: `.gradle/loom-cache/minecraftMaven/net/minecraft/minecraft-merged-d6f9bb6878/26.3/minecraft-merged-d6f9bb6878-26.3-sources.jar`, записи `net/minecraft/world/entity/LivingEntity.java` (около строк 1402–1411) и `net/minecraft/world/item/component/DeathProtection.java`. Source jar / runtime 1.21.4 в доступном старом checkout не найден: там есть Paper API 1.21.4, а `versions/` содержит runtime 1.21.11. Поэтому этот порядок подтверждён для native 26.3; совпадение со старым native 1.21.4 остаётся непроверенным, не фактом.

Пока `skill_issue>0`, `players_tick` вызывает обработчик, если рядом нет `stopper_magic` или `stopper`; иначе этот путь приостанавливается. Углы читаются в целые scoreboard значения. Yaw branch проходит только для delta `8..179` или `-179..-8` (дельты около ±180 исключены), pitch branch — для значений вне `-7..7`, без исключения около 180. Два независимых `execute` могут оба пройти в один тик, вызвав до двух `effect_skill_issue_gangbang`; каждый вызов пытается нанести 1 generic damage и даёт blindness 2 секунды. `skill_issue` уменьшается на 1 за вызов обработчика. `leave_death` сбрасывает сам счётчик, но найденного удаления UUID `Rotation` storage или сброса rotation history нет. При первом вызове код пытается прочитать UUID storage без проверки наличия baseline до сравнения. Вывод: если записи ещё нет, первое сравнение зависит от результата неуспешного `store` и текущего/предыдущего global fake-player score `rot0old`/`rot1old`; возможен ложный штраф. Это статический вывод по функции, не наблюдение в запуске. Также при stopper пауза не обновляет baseline, поэтому после снятия stopper вращение за время паузы может попасть в delta. Если переносить rotation punishment, сначала инициализировать baseline из текущего угла и пропускать сравнение при отсутствующей истории; при смерти помечать историю невалидной. Пока stopper блокирует штраф, обновлять baseline либо сбрасывать его при возобновлении, чтобы не наказывать игрока за вращение во время паузы. Это рекомендация для устойчивого переноса, не описание текущего поведения.

## Kit 18 — PHD

`lbc.kit=18` выдаёт `lbc:kit/phd`: один `minecraft:repeating_command_block` с `item_model=lbc:phd`, custom name key `phd` (`italic:false`), custom data `{phd:1}`, и три `minecraft:bone_meal` с именем `compost` и одной строкой lore `compost.lore`. У command block lore из четырёх переводимых строк; первые три white + `italic:false`, четвёртая white + `italic:true`. [Loot](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/loot_table/kit/phd.json), [kit dispatcher](E:/servers_mew/cringe1_21_4_skywars/world/datapacksdisabled/LBC/data/lbc/function/swrg_kit_integration/game/kit_select/select.mcfunction), [Paper loot copy](E:/servers_mew/cringe1_21_4_skywars/plugins/luckywars/src/main/resources/datapack/data/lbc/loot_table/kit/phd.json), [Java kit map](E:/servers_mew/cringe1_21_4_skywars/plugins/luckywars/src/main/java/me/luckywars/swrg/SwrgNativeService.java).

Это не обычный crafting recipe и не use callback. Каждый `players_tick` ищет PHD с `{phd:1}` в `player.crafting.*`; только тогда `changed_inventory_phd` считает органические предметы среди четырёх слотов и при `3..` вызывает `phd_craft`. `phd_craft` начинает `hash` с `#game_seed`, для каждого подходящего слота складывает значения символов item ID из позиций 10–37 через `phd_hash_0..3`/`phd_hash` (a–z и `_` имеют явные значения), берёт остаток `% 144` и выдаёт `lbc:kit/pill`. Перед вычислением ингредиенты копируются в служебный блок, расходуются по одному и возвращаются остатки. Условия матча вне этого callback не добавлены. Зависимости/неопределённости PHD: `#minecraft:bioitems` используется как tag, но его определение и состав в доступных исходниках старого сервера не найдено; нельзя утверждать полный список допустимых ингредиентов по одному комментарию lore. Реализация выхода требует перенести полный каталог 144 исходов `kit/pill` и их атрибутные/эффектные callbacks — это уже самостоятельная крупная механика. В Ignite прямых упоминаний не найдено; в Java есть только kit→loot mapping, а в plugin datapack видны loot tables. ## Рекомендация по срезу

Из этих двух возможный компактный полный kit — `broken_totem`, если вместе с выдачей перенести и проверить всю цепочку наказания `skrimmer` → `skill_issue` → player tick, включая ограничения по dimensions и stopper markers. Нельзя ограничиваться выдачей тега/тотема и заявлять поведение завершённым. `phd` пока не modest slice: без определения `bioitems` нельзя точно сохранить триггер, а выход требует полного набора из 144 пилюль и callbacks. Для полноценной миграции PHD сначала нужен источник tag definitions/реального окружения и отдельный охват pill pipeline.
