# Chef AI rework: implementation audit, 25 October 2026

Read-only source audit. Only this note was written. No Java, resources, builds, server state or git changes. This is an implementation recommendation, not a qualified implementation or live gameplay result. Current source remains the previously qualified Chef with the limitations below. Parent integration is first finishing the frozen Sheep artifact.

## Current requested behavior

User now requests humanlike pursuit of the exact accepted WTF-item melee victim: smooth attention, sprint jumping on suitable ground, careful obstacle traversal, parkour before construction, competent fast bridging, jump critical attacks near the victim, swimming, fire extinguishing, fall water placement and subsequent bucket recovery, actual hunger with eating outside melee range. Infinite HP and 20 accepted damage => 200 active ticks of knock remain. Knock should use the prone/crawling player swimming pose, forbid actions, retain gravity and allow void rescue. This supersedes the old motionless-in-air stasis implementation; it is not already implemented.

## Concrete current defects

- `src/main/java/me/skywars2/game/LbcWtf.java:79?108`: `paused()` combines knock and true Time Stop. Knock skips `super.tick()`, rejects `move`, `setDeltaMovement`, `setPos` and `snapTo`; `halt()` erases the entire velocity. Thus the frozen-in-air behavior is structural. `onBelowWorld()` calls rescue, but native ticking is skipped in knock, and rescue position writes are rejected while paused. This also blocks manually invoked rescue.
- `LbcWtf.java:113?118`: every steering tick snaps body/head yaw to the next cardinal waypoint. Pitch divides target eye-height difference by distance to the waypoint, rather than distance to target. Approaching a nearby waypoint can make pitch spike even for a distant victim. There is no random camera routine; the jitter plausibly comes from waypoint snapping and this mixed reference frame. No live pixels were inspected in this audit.
- `LbcWtf.java:145?159`: close combat calls full-velocity `halt()` every tick and applies fixed 8 damage on a 20 tick interval. There is no critical condition, sprint or attack-jump state; repeatedly clearing Y prevents natural combat jumping. The sword is visible, but damage is explicit native damage-source application, not `Player.attack`.
- `src/main/java/me/skywars2/game/LbcChefBrain.java:51?59`: collision is reduced to empty/nonempty whole cells, and support is any nonempty shape. `standing()` requires an entirely empty feet cell, so bottom slabs cannot be represented at their real half-block feet height. Stairs, fences, walls, trapdoors and narrow supports are similarly misrepresented; breakable partial shapes are routed as mining actions. Hazards are restricted to lava/FIRE, missing soul fire, damaging plants, lit campfires, powder snow and other context.
- `LbcChefBrain.java:103?140`: nodes are reached by 3D distance to integer bottom centers, threshold squared .18. Native jump arcs can cross past a waypoint while above it, preventing retirement until landing and allowing overshoot/backtracking. Horizontal collision requests another jump without knowing whether that jump can clear the obstacle.
- `LbcChefBrain.java:144?189`: graph has four horizontal directions, only one-cell ascents/descents, and vertical pillar actions. There are no diagonal walking edges, multi-block jump gaps, deliberate safe drops, fractional floor heights or swimming nodes. Bridge/mining cost penalties do not provide a staged parkour-first policy. Search stops at the first slice yielding a node with a strictly closer heuristic, so a segment can favor local immediate progress over a more coherent whole route. Search start equality uses current block position, which can invalidate retained search when the actor drifts/falls.
- `LbcChefBrain.java:210?224`: placement exists, uses infinite cobblestone, attached faces, border/unobstructed checks and actual world writes. It is not absent, but the weak route/executor can prevent reaching a build action. Reach is from actor feet, and attachment tests any nonempty neighboring shape rather than a valid face/actual block hit. Its checks prove neither correct fast bridge cadence nor collision-safe support after every step. Placement and mining already capture owner attribution; preserve this.
- `LbcChefBrain.java:64?94`: exceptional spawn/void surface teleports only; no per-tick random teleport or noGravity toggle was found in these classes. `nearestSurface` tests only four cells near the heightmap top per column, so it can miss valid surfaces under roofs/trees. A spawn rescue can teleport after admission; smooth normal movement must not use this as stuck recovery.
- No hunger/food, extinguishing, water bucket, landing prediction, bucket recovery, sprint or crit implementation exists in the two production classes. The water behavior is simply `jumping=...||isInWater()`, which paddles upward during steering. No fluid route or deliberate underwater escape exists.

## Recommended concrete architecture

Keep one real Chef Mannequin and its real native physics. No follower carrier, client bot, per-tick relocation, noGravity or random movement. Split current monolithic behavior into priority state, terrain route planner and native-input executor (separate package-private classes if useful). Existing owner/victim/lifecycle/attribution remains.

1. Separate `timeFrozen()` from `knocked()`. Time Stop preserves its current absolute freeze semantics and pauses the knock clock. Knock ticks ordinary entity physics with zero requested movement/jump, prone pose, no sprint/use/attack/mine/place and incoming damage immunity. Retain vertical velocity/gravity; suppress intended horizontal locomotion without rejecting vertical writes. Decide fluid-current/push semantics explicitly from the request instead of inheriting total freeze. `halt()` becomes stop-input or brake-horizontal; never zero Y during ordinary waiting/mining/eating/combat. Only rescue/real Time Stop may reset full velocity as required.
2. Run lifecycle and exceptional void rescue before the knock/action-block returns. Rescue uses an internal allowed relocation path even during knock, preserves remaining knock timer/prone pose, and does not wake or retarget Chef. Keep rescue bounded/resident chunks with cooldown. Validate an actual body box and support floor, cache last truly safe support and inspect fallback surface candidates if heightmap top is unsuitable.
3. Priority: actual Time Stop/lifecycle; exceptional void rescue; knock; immediate liquid/fire/fall survival; melee; safe food use; route action execution. Fire/fall rescue can preempt path following; resume cached route only if still valid afterward. Actions must own hand equipment and look intent for their duration.
4. Terrain nodes contain continuous feet Y/floor shape, movement mode and action, not only BlockPos. Edges include cardinal+diagonal walk, native step, safe drop, validated sprint/normal jump with takeoff/landing clearance, swim/exit, then PLACE/MINE/PILLAR as fallback. For a short gap validate ballistic native-jump envelope and landing box; prefer feasible terrain traversal/parkour before edits using staged search or a strong explicit construction penalty. Never hardcode all gaps as bridgeable parkour. Test ceiling and side clearance, launch run-up, real speed, jump strength, platform width and landing safety.
5. Cache route segments and action state. Invalidate for meaningful target displacement, changed blocks on the remaining corridor, failed local collision/edge prerequisite or timeout with actual lack of progress; preserve the remaining route when target merely moves within attack radius. Keep per-Chef/global CPU node and collision-probe budgets, fair service rotation and capped memory. Cache shape/path-type results only for a bounded plan or with correct block-change invalidation, not permanently by coordinate. Use a reachable attack goal region rather than the victim occupied feet block.
6. Smooth movement direction along a validated corridor with limited waypoint lookahead and corner clearance; remove waypoints by projected progress/crossing and mode-specific vertical criteria. Decouple movement yaw, bounded head attention and pitch toward the actual look target. Approach a build edge with planned braking/sneak-equivalent guard: a non-Player does not automatically inherit player sneak edge prevention. Feed forward/strafe/jump/sprint inputs to native travel; allow its momentum/drag/step physics. No direct xyz integration for walking.
7. Build action executor aligns and faces a specific reachable attachment face, places a real block ahead while actor remains supported, then advances with bounded placement cadence. Look several blocks ahead for a valid bridge destination; verify each committed block and remaining body clearance before stepping. Same-column pillar needs a jump phase and must place only once the actor box clears the block. Return to ground/parkour routing when available. Mining retains accumulated hardness progress, correct fastest tool/drop rules, break animation, reach and attributed support removal. Preserve infinite supply and no tool extraction.
8. Near target, stop sprint and schedule normal native jump only when floor/headroom and landing are safe; strike on falling crit window with line of sight/reach/cooldown and bound victim checks. Retain ordinary hit fallback where crit is unsafe, target leaves range or liquid disallows crit. Prevent combat `halt` from erasing jump Y. Hunger/exhaustion from actual traveled sprint/swim distance and jump/attack events should change state, with sprint denied when food <= 6. Eating is actual timed native use started only outside melee danger on safe ground or other explicitly safe mode, interrupted if threatened/knocked, and credited only at completion. Food need should be observable in checks, not just occasional cosmetic eating.
9. Water survival predicts actual landing from position/velocity and resident collision, then places source water at a reachable suitable block at the correct last-safe moment through native bucket APIs. Do not teleport, reset fallDistance early or pretend a successful MLG when placement evaporated/failed. Swim out using surface/air-aware inputs. Remember exact placed source and expected state; recover with bucket API only after landing/extinguishing and safety permits, respecting reach/line of sight. Keep owner attribution for fluid/block effects and do not delete unrelated/replaced sources. Bucket ownership must be independent from infinite cobblestone.

### Vanilla reuse alternatives

Preferred: adapt the small relevant vanilla geometry/walker logic to a Mannequin-native controller and extend the existing bounded action graph. This preserves one physical Mannequin and permits explicit parkour/build/mining actions.

An optional unspawned `Mob` planning adapter can compute vanilla walk paths by mirroring Chef position, standing dimensions, movement/jump/step attributes, path malus and fluid ability. Never add this proxy to the world or tick it physically. Follow its resulting path using Chef inputs. This reuses `WalkNodeEvaluator`/PathFinder for ordinary ground route only; full navigation/controllers remain bound to the proxy, vanilla walking does not plan bridges/mining or player parkour, and pose-dependent dimensions/nearby entity collision require care. It adds integration cost, so it is not a drop-in superior solution. No claim that vanilla has a complete Baritone for Mannequin is supported by source.

Record source/fixture/runtime/client evidence separately; existing checks do not establish these new outcomes.
