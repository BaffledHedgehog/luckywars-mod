# Machinegun implementation — 2 November 2026

Implementation ownership: only `LbcMachinegunSkill.java`, `MachinegunBowMixin.java`, and this note. Root owns integration, catalog, runtime checks, builds and qualification. This note does not claim a passing build or runtime verification.

Author policy provided by root: skill14 entirely unjammed, actual native used bow in either hand, normal final release preserved. Continued growth after one burst per tick must be slower: one additional arrow per twenty completed saturated bursts. The helper is `1 + max(0, progress - 19) / 20`; the denominator is explicit and adjustable. `bow_charge_sub` advances once per completed burst, never per arrow. Intervals before saturation retain `20-progress` with floor1 and the original remainder threshold. Source counters `bow_charge` and `bow_charge_sub` remain scoreboard-owned, including external KFC mutation and full scoreboard rewind.

Actual use is observed in `LivingEntity.updateUsingItem(ItemStack)`, because pinned BowItem inherits Item.onUseTick and has no override into which to inject. Native stopUsingItem resets actual tracked draws. Identity includes native owner body, used hand, stack reference and selected slot; invalidation removes one narrow owner lane. No player-wide inventory polling or nearby-arrow/world selectors are used. Ammo scans happen only at a due burst or actual arrow publication and match minecraft:arrow including custom-component variants, independently from creative/Infinity; every published arrow has its own50% consumption draw. Tipped/spectral arrows alone do not admit the factory.

Delivery uses128 native arrows per server tick and a soft4ms CPU budget, round-robin one arrow per owner per pass. At most one unfinished burst per owner exists; later callbacks cannot add debt until it completes. This is resource backpressure at extreme counts. No recursive production, exponential multiplication, per-arrow progression or growing collection of pending shots exists. TimeStop/native frozen input pauses charge and delivery. Core may cancel short pending emissions through clearTransient while canonical scoreboard counters restore. Synthetic native checkpoint stop/use callbacks are guarded with MatchPlayerCheckpoint.restoring. Root wires owner lifecycle clear, global stop clear and checkpoint transient clear.

Every automatic shot is a fresh ordinary native Arrow, actual shooter owner, base damage2, native default pickup, killedarrow and narrow machinegun tags. Aim quantizes speed-scaled Cartesian look components to1e-4 then adds independent uniform integer XYZ jitter `[-max(2000-charge,0), +max(2000-charge,0)] * .0001`. Speed retains original `1+.005*charge` and late q9800 drop to10. No normal bow ammo components/enchantments/custom release behavior are copied. No projectile body pushing occurs. Existing shared ProjectileLifetimes tracks resident arrows; a narrow tagged native-arrow tick callback advances that queue and deletes killedarrow on block entry. Root wires restored-arrow load registration before any blanket epoch rewriting.

Shared trinket service shot runs exactly once per successful auto-arrow publication; native release keeps its own ordinary once-per-shot hook. Current public native service implements Blaze and Ghast only; the other six legacy trinkets remain unavailable in its catalog and are not newly exposed. Source-compatible fast_charge, strong_charge, strong_charge_1 and gravitas tags are honored only while global levelups are enabled. Current catalog exposes none of those tag levelups; no new selection entries are invented. fast_charge retains source1.3 motion quantization and recursive-equivalent90% Cartesian reduction to absolute component<=10, with a finite arithmetic loop.

Register both `MachinegunBowMixin` and `MachinegunBowMixin$ArrowTick`. Integration accessor is `LbcItems.machinegunSkill()`. APIs: usingBow, tick, loaded, arrowTick, clear(owner), clear(), clearTransient(); pure static interval/arrowsPerBurst/speed/spread/component and package-local charge/progress/pending/accelerated support root-owned native diagnostics. This implementation leaves final native bow release and current custom release handlers intact.

Synthetic restore callbacks remain guarded. Root also clears on selection/slot invalidation so deselection cannot retain a restored inactive draw phase.
