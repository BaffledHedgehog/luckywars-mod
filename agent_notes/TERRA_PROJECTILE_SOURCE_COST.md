# Terra: мгновенный Tiny и persistent обычный/улучшенный луч

**Tiny Terra до native-hitbox изменения:** прежняя реализация была одним синхронным вызовом с sample step 0.35 и индексами 0–100 (101 точка). Перед циклом выполнялся broad entity query, затем по каждой точке перебирались кандидаты с unit-cell hitbox test. Это соответствовало старому source-стилю, а не новому пользовательскому решению для летящих Terra и последующих снарядов.

**Текущее решение `(user)`:** «Да, нативное попадание по хитбоксу». `terraRay` оставляет 101 sample только для визуального следа и определения стены, после чего один раз вызывает нативный `ProjectileUtil.getManyEntityHitResult` с margin 0 и `includeFromEntity=true` по сегменту, ограниченному стеной. Каждая подходящая цель получает не больше одной попытки 5 cactus damage за каст. Геометрия урона теперь определяется пересечением реальных entity hitboxes с отрезком, а не серией кубов 1×1×1; численно с прежними selector cells она не эквивалентна. Адресный runtime после интеграции прошёл; отдельного CPU-сравнения каста Tiny Terra нет. [Результаты и отдельный нагрузочный сценарий кислоты](PROJECTILE_PERFORMANCE.md).

На каждую из 101 достигнутых точек отправляется amethyst hit sound; random roll делается на каждой точке, particle с шансом <30% (ожидание около 30 из 101, не фиксированное количество). Эта визуальная работа сохранена после смены геометрии попадания. Tiny Terra не создаёт persistent projectile/marker; 200–300 разовых casts означают соответствующее число отдельных вызовов, а не живые ray entities на каждом следующем tick.

OLD LBC tiny `workingitems/sauvojen_staffs_tiny/terra.mcfunction` вызывает `terra_2` сразу, а та рекурсивно делает шаги 0.35 до Distance 100: те же 101 точки, per-point chance30 dust transition particle, amethyst hit sound и entity damage selector. Это мгновенная рекурсия в одном function execution, не marker и не последовательность по server ticks. Старый selector имеет `dx=0,dy=0,dz=0,distance=..8,limit=1`; область начинается от текущей fractional ray position и extends на 1 по осям, без округления origin к block coordinate. Повторные соседние samples могли снова выбрать уже задетую сущность; native намеренно дедуплицирует каждую цель внутри каста.

Обычная Terra в `workingitems/sauvojen_staffs/terra_preloop.mcfunction` создаёт `raycastterra` marker с `slowraycast` и lifetime 200. Её selector запускается из `tick_not_timestopped.mcfunction` каждый игровой tick; `lbcr:raycast_terra` делает максимум 7 шагов по 0.3 за вызов/tick (Distance 1…7), то есть до 7 клеточных mob selectors, 7 force particles и соответствующих block checks на marker tick. При стене луч завершает marker раньше. В каждой точке selector ищет mobs в fractional unit-cell с `distance..10,limit=1`; при кандидате `dmg_bypl_8` повторно ищет цель/союзников и наносит до двух 8 cactus damage. Звук amethyst break проигрывается один раз при создании луча, не на каждом sample.

Улучшенная Terra из `terra_preloop_upgraded.mcfunction` создаёт `fast_terra` marker lifetime 20. `lbcr:raycast_terra_fast` проходит до 26 sample по 0.3 в одном вызове marker tick, с force particle и entity lookup радиусом 15 без limit на предварительном условии; `dmg_bypl_11` затем повторно ищет до двух mobs и наносит 17 cactus damage каждому. Максимум 26 таких шагов/первичных selector checks и particles на marker tick; блок прекращает луч досрочно. При N одновременно активных marker rays объём этих per-tick циклов масштабируется примерно как N × 7 для обычных или N × 26 для улучшенных до ранней остановки; например 200 обычных — до 1400 шагов, 300 улучшенных — до 7800. Это счётчик function samples/selectors по исходному control flow, не TPS или CPU benchmark. Улучшенный marker стартовый звук также задан один раз в preloop.

Ключевое отличие по жизненному циклу остаётся: Tiny Terra мгновенный cast, старые обычная и улучшенная Terra — persistent marker rays, повторяющие луч на каждом tick до стены или lifetime. Их source шаги 7/26 × 0.3 не смешиваются с визуальными 101 × 0.35 Tiny samples. Старые selector cells привязаны к fractional origin; текущий Tiny damage path вместо них использует native segment-versus-hitbox query. Исторические числа описывают OLD control flow; производительность новой геометрии не измерялась.

Проверенные OLD LBC источники: `data/lbc/function/workingitems/sauvojen_staffs_tiny/{terra,terra_2,terra_end}.mcfunction`, `data/lbc/function/workingitems/sauvojen_staffs/{terra,terra_preloop,terra_preloop_upgraded}.mcfunction`, `data/lbcr/function/{raycast_terra,raycast_terra_fast,dmg_bypl_8,dmg_bypl_11}.mcfunction`, `data/lbc/function/{raycastselector,raycastselector_player,tick_not_timestopped}.mcfunction`.
