шаблонов и общая очередь с бюджетом CPU. Sun делегирует `LbcMagmify`: потоковый
обход с исходным 26-соседним halo и записью небольшими порциями на серверном
потоке, без ожидания полного плана. Каждый каст получает отдельные ходы;
packed-long cache хранит исходное/ожидаемое состояние для защиты чужих правок.
Лавовые выступы и тики жидкости завершают обход; затем идёт один surface impact.

и native setBlock с явным измерением; Sun откладывает shape/on-place callbacks,
прежние callers сохраняют исходные flags. Tannerkivi — `LbcTanner`:
автоматические две руки, начальное покрытие и только реальные новые полосы
при движении, объединённые BitSet-задания по секциям и индекс событий блоков
по чанкам. Пустые/готовые секции пропускаются по нативной палитре; чтение
блоков идёт из загруженной секции, запись — прежним setBlock с общей атрибуцией.
`BlockAreaWork` обрезает pending-маски целыми Y/Z/X-диапазонами BitSet, без
поклеточного прохода при движении. Только живой Tanner включает раннюю
проверку палитры до постановки секции; изменения снова поступают через индекс
block/chunk events. У одноразовых заклинаний семантика постановки сохранена.
Ввод/мана, NPC и крафт остаются в прежних владельцах.

Для снаряда сначала проверьте имеющийся `canHit`/hit helper и передачу owner; для эффекта — общий путь очистки через `LbcItems`. `GameChecks` — большой runtime-набор: ищите suite по имени механики, не читая файл целиком.

Дальние снаряды используют [`ProjectileLifetimes`](src/main/java/me/skywars2/game/ProjectileLifetimes.java),
общую геометрию — `LbcWands.firstHit`/`LbcTerra.wallHit`. Воздушные ракеты
[`LbcAir`](src/main/java/me/skywars2/game/LbcAir.java) используют общий
`LbcExasperato.protectedBlast`: нативный TNT-взрыв с временным источником,
который не добавляется в мир. Тот же helper обслуживает SLR, Fulminate,
Cultus и контакт летящего динамита. `instantBlast` явно исключает конфиг-защиту
для исходного fuse=0. `LbcDamage.protectedTntDamage` через Player-super hook
применяет `tntProtection` только к игрокам после сложности, до штатной брони
и эффектов, без выдачи Resistance. Электрический HEAD hook остаётся отдельным.
Нативный задержанный/цепной TNT учитывает конфиг по умолчанию. Его физика,
owner и очистка эпохи остаются в существующем `LbcItems` lifecycle.
85 защищённых взрывов Exasperato проходят ту же очередь с бюджетом CPU,
что и ядерные серии. Общая `ProjectileLifetimes.protectedWandProjectile`
задаёт политику магических носителей: `EntityVelocityMixin` пропускает для них
весь native explosion branch через `ignoreExplosion`, а `WandProjectileMixin`
отсекает обычные атаки/столкновения/deflection. Кислота исключена; электрощит,
Curse и намеренные изменения скорости/owner сохраняются. Это заменяет прежний
частный фильтр собственных взрывов Exasperato; учитываются позиции/мощность/политика каждой
серии, без потери принятых взрывов. Временные Academy/Exoperso источники
освобождаются сразу после синхронного взрыва.

`ElectroNativeMixins.Impact` сохраняет авторство нативных молний через отдельный
`LbcDamage.LIGHTNING` / `skywars2:lightning`. Он входит в electrical/no-knockback
классификацию, но не в bypasses_cooldown; обычная погода остаётся ванильной.
У Teleport-снарядов нет отдельного прямого HP-урона. Дуги и ауры продолжают
использовать свои ранее согласованные типы с обходом cooldown.

`data/minecraft/tags/damage_type/bypasses_cooldown.json` объединяет все 14
ванильных записей legacy LBC и 11 собственных skywars2 типов. Нативный hurt
pipeline сам принимает повторные попадания; ручных сбросов HurtTime нет.
Фовос использует generic, обычные стрелы — arrow, оба типа теперь без cooldown.
Vanilla/managed lightning исключены и сохраняют обычную частоту попаданий.

Default model Polymer-предмета задаётся через `Item.Properties.effectiveModel()`:
в 26.3 финальный initializer перезаписывает ранний `.component(ITEM_MODEL,...)`.
`LbcElectro.registerShield` использует `minecraft:shield`; Polymer штатно
переносит base_color/banner_patterns, которые рисует vanilla shield renderer.
Ресурспак для электрощита не нужен; per-stack модели из loot сохраняются.

Ближняя аура Electroblocker в `LbcElectro.tickShields` после успешного ELECTRIC
урона отдельно вызывает native `dealDefaultKnockback`: полный импульс мобам,
0,1 изменения скорости игрокам (user). Общий тег `no_knockback` не меняется;
отклонённый удар, союзники и иммунные к электричеству цели не отбрасываются.

Все девять пар одинаковых Tiny объединяются в обычный жезл через
`LbcCraftingRecipe.tinyPair`; native/legacy/mixed пары используют те же
2×2/3×3 output slots и take hooks. Preview берёт source loot и разрешает
его mana-score lore через серверный ResolutionContext, поскольку у рецепта
нет THIS_ENTITY; translate-компоненты и стили сохраняются. Обычный Acid
зарегистрирован в `LbcWands`, один заряд создаёт
`LbcClouds.ordinaryWandAcid`: постоянный профиль на общей AcidProjectile,
сфера 5, Poison 600 / горящий урон 4, прежняя физика/прилипание/owner/lifecycle.
См. [перенос крафтов](agent_notes/TINY_WAND_CRAFT_PORT.md).

Жезл телепорта — [`LbcTeleport`](src/main/java/me/skywars2/game/LbcTeleport.java):
нативный заряд, upward/inverted payload и облако на Arrow. Инверсия повторно
использует `MapManager.placeMapSlice` для BlockEntity без дублирования дропа и
`LbcIndirectKills.displaced` для автора последующего падения. Облако повторно
использует `LbcShooters.orient` до spawn; `WandProjectileMixin$Cloud` ограничивает
только его нативный tick/столкновение. Стоимость и ввод остаются в `LbcWands`,
испытание и улучшение — в `LbcAcademy`, lifecycle — в `LbcItems`.

Обычный/Academy Ruby — [`LbcRuby`](src/main/java/me/skywars2/game/LbcRuby.java).
Для всех вариантов Ruby разрушение одной клетки и автор утраты опоры общие:
`LbcWands.destroyRubyCell`. Набор packed координат убирает повторный loot одной
клетки внутри тика/каста. Stone и Ruby ставят исходные структуры через
`MapManager.placeLoadedTemplate`, который обрезает их по загруженным чанкам,
а затем вызывает прежний `placeMapSlice`. Медитация использует общий фильтр
`LbcWands.target(..., true)` с узким разрешением притягивать союзников (user).

Первый этап — работающий цикл обычного SkyWars на Fabric 26.3: лобби → выбор
карты/настроек → загрузка → клетки/отсчёт → матч/стадии → победа/ничья → лобби.
Это самостоятельная Java-реализация по документации, без параллельного исполнения
старых mcfunction. Пометки `(user)` в agent_notes имеют приоритет; исходный сервер
не изменяется.

## Владельцы данных и поведения

`LbcTransformator` owns the dropped-token encounter pair and native fireball/TNT
lifecycle; `LbcSpecialDrops` owns admission/debit and `LbcNpcDropItems` owns exact
base token presentation. It reuses `LbcWands.ElectroTrace` for mechanism electricity:
nullable player owner plus retained NPC cause, with shared hitboxes/conduction/
reflection and native electric damage rules. `LbcIndirectKills` resolves the token
thrower; explicit current projectile/reflection ownership wins over that fallback.
A native hurting projectile cannot expose a removed owner during flight; its
causal author is retained separately. Native TNT block children are adopted through
HazardPropagationMixins, and shared native owner/explosion hooks retain that author.
[Current contract](agent_notes/TRANSFORMATOR_ACADEMY_PORT.md).

`LbcAcademy` remains the only building/trial owner. Placement captures level/epoch
and source position, validates full resident bounds before debit, pauses under
Time Stop, and enables NPC interaction/teleport only after finished native rows.
`LbcReactive` owns player cooldown/platform and Shish Wall's terrain-only consumer
of the existing budgeted Exasperato ray search; LbcWall still owns its brick shapes.
[Reactive contract](agent_notes/REACTIVE_FAMILY_PORT.md).

Wall Wand — статический `LbcWall`: один мгновенный native hit и четыре
кирпичные формы, без собственного состояния/тикера. Ввод, цена и бонусы
остаются в `LbcWands`, испытание четырёх сторон и NPC — в `LbcAcademy`.
`LbcMagic.suppressionFraction` вычисляет первую границу известных сфер один раз
на луч, без запросов сущностей на каждом visual sample. Все изменения блоков
проходят через общий учёт отложенных убийств. Поворот лестницы использует
перегрузку `MapManager.placeLoadedTemplate` с нативными повёрнутыми bounds,
по-прежнему ограничиваясь загруженными чанками.

Бедроковый жезл — `LbcBedrock`: обычная/регенерирующая комнаты, три лучевых
режима и послойный возврат прежних блоков. Один слой хранит снимок перед
наложением; отзыв нижнего слоя передаёт снимок следующему, не снимая верхний.
Состояния/данные контейнеров сохраняет общий `MapManager.snapshot`, возвращает
`restoreSnapshot`. Новый сериализатор BlockEntity не нужен.
Отзыв выполняет общий `LbcIndirectKills.worldChanges`, чтобы падение после
исчезновения пола наследовало автора жезла; отложенный возврат сохраняет
вместе со снимком исходную комнату и владельца.
`ArenaBlockMixin` сообщает пробоины, очередь чинит только изменившийся воздух;
chunk-load планирует восстановление доступной части без загрузки соседей.
`LbcMagic` при размещении маяка навсегда снимает метку комнаты без изменения
мира. Эти события нельзя заменять редким опросом: маяк мог уже исчезнуть.
Ввод и item types — `LbcWands`, особый платёж комнаты отделён от бесплатного
отзыва/режимов; `wandCasted` — общие бонусы только созданного заклинания.
Крафт — прежний `LbcCraftingRecipe.Kind.BEDROCK`, NPC/испытание — `LbcAcademy`.

Exoperso — `LbcExoperso`: подготовка, фиксация направления, swept collision,
smart lifetime и достижение за убийства одной серии. Использует общий
`LbcExasperato.exopersoBurst`: те же 32 позиции, очередь с бюджетом CPU,
нативный TNT без сущности в мире. Перед каждым взрывом callback привязывает
источник к серии, после взрыва освобождает его. Цепной TNT получает серию через
существующий `HazardPropagationMixins.ChainTnt`; `AFTER_DEATH` учитывается до
перехода матча в завершение. Не дублировать очередь и правила урона.
Общий `LbcMana.trySpendWand(required, cost)` разделяет допуск и расход;
прежний вариант с одной ценой делегирует ему без изменения контракта.

`LbcItems.hud(source)` собирает одну строку маны, холода/заморозки, запретов,
проклятия, таймеров мановых зелий, RTP и ракеты в исходном порядке. Кэш HUD
сравнивает примитивные значения до построения компонентов; `hudValue` читает
scoreboard без создания score. Камера наблюдателя использует тот же сборщик
для настоящей цели, не копируя её игровые статусы на сервере.

При попадании кислоты в блок `AcidProjectile` сохраняет точку поверхности и
неподвижное состояние; дальнейшие тики пропускают flight/collision sweep,
но сохраняют базовый entity tick, ауру и прежний возраст. NBT восстанавливает
прилипание, исходный TTL не перезапускается. Полный Overload-комплект больше
не возвращает ману за попадания щупалец; остальные стадии долга остаются.

Не добавлять отдельные singleton, registries, interfaces, factories или service
для каждого меню/таймера/кнопки. Дополнительный класс оправдан только отдельной
ответственностью, которую нельзя понятно разместить здесь. Зависимости создаются
один раз на сервер; игровой код и изменение мира выполняются в серверном потоке.
Карты физически загружаются только при выборе/старте карты и только из готового
лобби; запуск и смена карты из другого состояния не начинают физическую вставку.
Загрузка карты 0 по умолчанию после старта сервера асинхронна. Если запросы выбора
перекрываются, применяется только последний запрос (latest request wins). Один
daemon-поток читает и декодирует NBT, затем один раз разбивает шаблоны на части
до 8×8×8 блоков. Целые шаблоны удаляются из нативного кэша после подготовки;
готовые части принадлежат одной операции. Серверный поток проверяет готовность
future между тиками, предварительно загружает чанки через
`addTicketAndLoadWithRadius` и ставит готовые части с бюджетом 4 мс/64 операций
за тик. Обычный `getChunkFuture` на серверном потоке не используется: в 26.3 он
сам выполняет `managedBlock`. Временные билеты `skywars2:map_loading` не
сохраняются в мир и освобождаются при успехе, ошибке или остановке.
Изменение мира, BlockEntity и создание сущностей остаются в серверном потоке.
Отдельная нативная операция может превысить бюджет; он ограничивает очередь
работ, а не гарантирует максимальное время тика. Журнал очистки сохраняется
перед изменениями; покрытые им блоки во время вставки не журналируются повторно.

## Контракты

- В лобби и при загрузке карты инвентарь фиксирован: один компас меню в пятом
  слоте хотбара; остальные слоты, броня, вторая рука, личная сетка крафта и курсор
  пусты. Пакеты перемещения, выбрасывания, переноса во вторую руку, creative-выдачи
  и автокрафта отклоняются в серверном потоке с синхронизацией клиента.
  Подбор предметов запрещён. SGui самостоятельно блокирует инвентарь игрока,
  сохраняя клики кнопок; при начале отсчёта блокировка снимается.
- Пользовательский текст передаётся как `Component.translatable`: сообщения,
  GUI, lore, боссбар и ошибки настроек/карт. `SkyWars2.text` добавляет префикс
  `skywars2.`; новые подписи меню используют `skywars2.gui.*` и общие
  `skywars2.common.*`. Для имеющихся подписей используются полные исходные
  ключи `swrg.*`, `golden_pumpkin`, `wind_runner_skill` и другие ключи
  пользовательского ресурс-пака, без новых псевдонимов.
  Параметры включают числа, строки идентификаторов и вложенные компоненты,
  а не заранее собранные предложения. `getString()` используется для логов
  и имён игроков. `MapManager.Result.message` и `GameConfig.SettingError`
  сохраняют компонент до отправки клиенту. Переводы `assets/skywars2/lang`
  попадают в ресурс-пак через Polymer; отдельного класса локализации нет.
  Эти файлы и `resourcepack_template/assets/minecraft/lang` содержат только
  недостающие записи для каждого языка. Исходные переводы остаются в
  пользовательском паке, который разрешено только читать.
  Имена и lore перенесённых наборов/навыков сохраняют оригинальные ключи,
  порядок строк, цвета и `italic=false`. `GameMenus` задаёт `CUSTOM_NAME`
  напрямую и использует `setLoreRaw`, чтобы SGui не сбрасывал оформление.
  Эталон GUI — исходный эндер-сундук на 27 слотов с заголовком
  `container.enderchest`. Раскладка и пустые ячейки сохраняются; придуманные
  рамки, дополнительные строки lore и статусы не добавляются. Подготовленный
  импорт компонентов создаёт `tools/import_gui_design.py`, читая старый сервер
  и ресурс-пак. Проверка фактических предметов меню — экспорт
  `/sw check design-export` и `tools/check_design_sources.py --snapshot ...`.
- `GameController` имеет стадии `LOBBY`, `LOADING`, `COUNTDOWN`, `PLAYING`,
  `PHASE_ONE`, `PHASE_TWO`, `ENDING`. Загрузка не означает готовность карты:
  следующий переход только после установки блоков, контейнеров и маркеров.
- Карта готовится при выборе, пока стадия остаётся `LOBBY`. Центр лобби —
  `(0.5, 200, 0.5)`, шаблон начинается на Y=199. Кэшированный оверлей проверяется
  каждый тик и восстанавливает только изменённые клетки. Общий native paste
  сохраняет блоки/BlockEntity карты под лобби, включая совпадающие состояния
  и воздух; старт снимает оверлей и раскрывает карту. После матча карта
  сохраняется до следующего явного выбора или старта. Открытое меню,
  навигация и настройки остаются доступны во время подготовки.
  Быстрые смены выбора сохраняют последнюю версию; callback устаревшей карты
  запускает подготовку последнего выбора. Старт разрешён только после успешной
  установки всё ещё выбранной карты. `begin()` фиксирует состав, закрывает
  контейнеры и сразу переводит игроков на готовую карту в `COUNTDOWN`; отдельного
  ожидания карты над ареной при старте больше нет. Вошедшие после фиксации состава
  становятся наблюдателями. `LOADING` остаётся стадией восстановления лобби и
  кратким внутренним переходом начала матча.
  При остановке сервера загрузчик прекращает подготовку после текущего чтения,
  не прерывая общий ZIP-канал ресурсов. Ожидание завершения ограничено 5 секундами
  и выполняется только при остановке, а не в обычном игровом тике.
- Участники фиксируются при старте. Поздний вход и выбывшие игроки — наблюдатели
  из реестра `Spectators`; отключение исключает участника из матча. Переподключение
  не возвращает выбывшего в живые. Отсоединённый наблюдатель клиентски остаётся в
  adventure, серверно считается spectator; наблюдение за целью переключает камеру
  в реальный spectator через пакетный путь. `/sw inventory` открывает read-only
  GUI инвентаря цели, `/sw detach` возвращает к инструментам наблюдателя. Действия
  наблюдателя отменяются, инвентарь цели и эффекты для HUD пересылаются клиенту без
  копирования активных эффектов на сервер.
- Раздельные счётчики: подготовка, игровое время, 5 тиков проверки победы,
  10 секунд финала. Первая стадия через 120 секунд, вторая через 360 секунд
  от начала игры. Повторы событий принадлежат текущему матчу.
- Конфигурация режима хранит варианты 1–4, но реализован только обычный SkyWars
  (`mode=1`). Остальные кнопки/варианты режима неактивны и не запускают матч;
  Lucky/BedWars требуют следующего этапа игрового и предметного движка.
- Поддержаны наборы LBC 1/2/4/5/7/9/10/15/17/22/23, навык 5 и 30 улучшений. Loot tables используют кодек 26.3; выдача и очистка выполняются через нативный lifecycle без старых функций. Импортированы 357 критериев, но их достижимость зависит от перенесённых механик. 122 уведомления используют успешный native award; пять acidman требуют все десять исходных достижений. Предметы находятся в `LbcItems`, химические облака и кислота — в его компоненте `LbcClouds`; сохранены ключи, модели и lore без дополнений ресурспака. Результаты: [SERVER_TESTS.md](SERVER_TESTS.md); текущая пачка: [BRBAD_PORT.md](agent_notes/BRBAD_PORT.md).
- Исходный недостижимый SWRG респаун исправляется: смерть уменьшает жизни,
  оставшиеся жизни возвращают игрока на его спавн; ноль — наблюдатель.
- Карты из неполных манифестов показывают причину недоступности. Новая карта
  не добавляется фиктивной процедурной заменой. Лобби/карты используют реальные NBT.
  Стеклянные блоки по умолчанию имеют вариант 21; очистка пола выполняет полное
  удаление блоков в заданной области перед заполнением, а не только замену верхнего
  слоя.
- Меню общих настроек сохраняет наблюдаемую доступность для игроков; запрет
  изменения во время матча защищает фиксированные параметры текущей игры.
- Настройки хранятся в JSON, без scoreboard и удалённых шалкеров. Команда
  `/settings <параметр> <значение>` доступна оператору в лобби. Сброс настроек
  не удаляет счётчик сыгранных матчей.
- В лобби огонь снимается непосредственно с игрока. Арена сохраняет сущности
  исходного whitelist; остальные измерения удаляют все загруженные сущности
  кроме игроков, независимо от тегов, согласно уточнению `(user)`.
  Новые сущности поступают из Fabric `ENTITY_LOAD` в очередь, проверяемую
  в конце серверного тика: вызывающий код успевает назначить исходные теги
  после `addFreshEntity`. Полный обход выполняется при входе в лобби и раз
  в 20 тиков, чтобы обнаруживать изменения тегов и пропущенные события.
  Для удаления тега с уже сохранённой сущности задержка теперь до 20 тиков;
  условия whitelist и правило остальных измерений сохранены. Очередь
  очищается при переходе в лобби/из лобби и остановке. Проверка инвентаря
  остаётся каждый тик: счётчик `Inventory.getTimesChanged()` не покрывает
  прямые изменения стаков и все серверные способы выдачи.
- Ресурсы карт/выдачи переносятся из исходного снимка с сохранением namespace;
  несовместимые/отсутствующие ресурсы диагностируются. Старые load/tick/advancements
  не подключаются одновременно с Java-контроллером.
- Журнал границ записывается до начала изменения карты и включает изменения
  блоков во время матча. После перезапуска предыдущая арена очищается перед
  лобби. Ограничения журнала: X/Z ±8192, Y −2048..4096; изменения вне этих
  координат диагностируются и не гарантируют автоматическую очистку.

## События обычных навыков

Воздушный навык 12 добавляет за qualifying air-sprint tick вектор yaw-relative
`0.1` вперёд и `-0.01` по Y; `ClientboundSetEntityMotionPacket` синхронизирует
серверный delta с клиентом. Наблюдатели не получают навыки и не становятся целями.
Обычные навыки 2/4/13 используют события: `PlayerMechanicsMixin` передаёт полную
дистанцию завершённого падения, `ConsumableSkillMixin` срабатывает сразу после
`CONSUME_ITEM.trigger`, до расходования стака и штатных эффектов еды.
Fabric `AFTER_DAMAGE` ставит только пострадавшего владельца навыка 13 в очередь;
`MatchEvents` проверяет фактический `HurtTime=5`, не сканируя всех игроков/сущностей
ради поиска попаданий. Мутации мира остаются в серверном потоке.
`SkillVex` использует ванильный ID/AI Vex и проверяет владельца и союзников при
выборе цели и непосредственно перед ударом. Список призывов принадлежит
`SkillState`; смерть/выход/респаун/смена навыка/конец матча удаляют их и
инвалидируют ожидающие срабатывания. Выгрузка снимает ссылку через
`ENTITY_UNLOAD`; Vex не сохраняется, чтобы после загрузки не потерять владельца.
Нового TTL/лимита призывов внутри матча нет. Параметры исходного кода и
расхождение 0,1 HP с lore «1 HP» отмечены в
[VANILLA_SKILLS_2_4_13.md](agent_notes/VANILLA_SKILLS_2_4_13.md).

## Проверка

Сборка Java 25 и запуск выделенного Fabric-сервера. Для участников проверок
использовать обычные `ServerPlayer` с тестовым соединением Carpet: его стандартные
fake players отключаются после смерти и не подходят для проверки нескольких жизней.
Проверить загрузку
реальной карты, старт/клетки, смерть и несколько жизней, поздний вход/выход,
победу/ничью, сброс и повторный матч, отмену стадийных задач. Проверки используют
обычные методы контроллера и серверные сущности; их результаты записываются
отдельно от документации исходного поведения.
