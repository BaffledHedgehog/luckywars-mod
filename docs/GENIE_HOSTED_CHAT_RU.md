# ChatGPT для джина на отдельном сервере

ChatGPT открывается в выделенном Chromium на хостинге. Профиль сохраняется в
постоянном томе; игровой сервер обращается к приватной очереди HTTPS. Компьютер
оператора нужен только при ручном входе или повторной проверке аккаунта.

## Вход

1. Подключите локальный SSH-туннель к порту `15800` машины с Chromium.
   Не публикуйте интерфейс браузера и CDP (`19222`) в интернете.
2. Откройте `http://127.0.0.1:15800` и войдите в ChatGPT в удалённом браузере.
   Пароли и одноразовые коды вводятся непосредственно на странице входа.
3. В игре выполните `/skywars genie chatgpt probe`. Команда проверяет доступ
   к Chat и GPT-5.6 Sol с усилием Medium, не отправляя желание. Успех включает резервный
   транспорт; существующий основной провайдер Gemini сохраняется.

Если сайт запросит повторный вход или проверку браузера, повторите первые два
шага. Работающий Chromium сохраняет штатные изменения cookies в профиле.
Это не гарантирует бессрочную сессию: сервер не обходит проверки сайта.

## Конфигурация

В `config/skywars2/genie/chatgpt-remote.json` игрового сервера:

```json
{
  "url": "https://HOST:18443/v1/",
  "token": "GENERATE_A_PRIVATE_RANDOM_BASE64URL_TOKEN_OF_AT_LEAST_43_CHARACTERS",
  "certificateSha256": "SHA256_OF_THE_EXACT_SERVER_CERTIFICATE_64_LOWERCASE_HEX_CHARACTERS"
}
```

Токен и закрытый ключ остаются вне Git. Клиент проверяет точный сертификат,
срок его действия и имя узла HTTPS. Замена сертификата требует обновить pin.
Флаг `chatgpt-enabled.json` создаётся штатной командой `probe` только после
успешной проверки. Без remote-конфига прежний локальный транспорт сохраняется.
Импорт cookies предназначен для прежнего локального профиля; удалённый профиль
авторизуется непосредственно через выделенное окно.

## Сервис

`tools/genie_chat_gateway.Dockerfile` собирает шлюз. Контейнеру нужны сеть хоста
для CDP на `127.0.0.1:19222` и каталог `/data` с файлами `token`, `tls.key`,
`tls.crt`. Сервис слушает HTTPS на `18443`. И Chromium, и шлюз должны
перезапускаться автоматически и иметь ограничения памяти.

Очередь принимает не более четырёх заданий. Разные желания имеют разные UUID
и выполняются по одному. Сервис сохраняет одну инициализированную вкладку;
каждое желание начинает отдельный новый чат через навигацию приложения.
Это избавляет от повторной загрузки профиля, которая на небольшом VPS может
занимать больше минуты. Существующие диалоги и чужие черновики не используются.
После ручного входа используется стартовая страница выделенного рабочего
профиля. Восстановленный сервисный черновик очищается перед новым запросом;
личный профиль браузера оператора не подключается. Отмена закрывает рабочую
вкладку. Активный запрос не ограничен общим таймаутом: игровой сервер
продлевает аренду опросом. Если он исчезает, через минуту задача отменяется.
Результаты и вложения не записываются на диск шлюза. Вложения передаются
буферами, поскольку Chromium и Playwright работают в разных контейнерах.

Проверка прямого HTTP-доступа в текущем аккаунте дала успешное чтение сессии и
списка моделей, но отправка сообщения получила `403 Unusual activity`.
Поэтому текущий транспорт использует штатный веб-клиент для авторизации,
загрузки вложений и отправки. Ответ и настоящий stdout Python-верификатора
получаются по HTTP из только что созданного диалога; отрисовка ответа и старые
CSS-классы вывода больше не нужны. Проверяются исходный текст запроса, активная
ветка диалога, точная модель и происхождение stdout от инструмента Python.
Возможность полностью убрать браузер пока не реализована. Человеческие проверки
сайта выполняет оператор через выделенное окно.

Проверки: `node tools/check_genie_chat_gateway.mjs`,
`node tools/check_genie_hosted_chat_worker.mjs` и
`node tools/check_genie_chat_http.mjs`, а также
`tools/GenieRemoteChatChecks.java` (настоящий локальный HTTPS с тестовым
сертификатом). Проверки не входят в серверный JAR.
