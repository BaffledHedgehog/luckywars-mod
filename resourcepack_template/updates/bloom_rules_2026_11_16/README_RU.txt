РЕДАКТОР СВЕЧЕНИЯ LBC — ОСНОВА ДЛЯ ХУДОЖНИКА

Что можно настроить
• RGB пикселя, который означает конкретный светящийся материал.
• Независимый цвет его ореола.
• Силу ореола от 0 до 4: 0 — выключен, 0.25 — слабый, 1 — обычный, 3 — сильный.
• Сердцевину: исходный цвет, белая либо цвет ореола.
Радиус размытия пока общий для материалов. Это настройка текстуры и ресурс-пака;
она не добавляет реальный свет на соседние блоки.

ПЕРВЫЙ ЗАПУСК — ОДИН РАЗ
1. Скопируй ВСЮ папку assets из этого дополнения в свой ресурс-пак с заменой.
   Один bloom_sample.fsh недостаточен: метка проходит через core-шейдеры,
   извлечение bloom и финальное смешивание.
2. Положи edit_bloom.py, OPEN_EDITOR.bat и bloom_rules.json в корень этого же
   ресурс-пака, рядом с assets и pack.mcmeta.
3. Нужен Python 3 с tkinter. Двойной клик по OPEN_EDITOR.bat открывает редактор.
   Для кнопки разметки PNG дополнительно нужен Pillow:
       py -m pip install Pillow
   Правила и GLSL можно редактировать без Pillow.

КАК ДОБАВИТЬ СВЕЧЕНИЕ ПРЕДМЕТУ
1. Нарисуй нужную область текстуры точным RGB, например 255,3,3.
   Обычные части предмета оставь обычными; прозрачный фон сохраняй прозрачным.
2. В редакторе нажми «Добавить». Выбери RGB из PNG, цвет ореола, силу и
   сердцевину. Для красного ореола с белым центром: RGB 255,3,3;
   ореол 255,3,3; сила 1; сердцевина «Белая». Это правило уже добавлено в пример.
   Если оно есть в списке, просто нажми «Изменить».
3. Выдели правило и нажми «Разметить PNG…», выбери текстуру предмета.
   Кнопка выставит альфу 254 только непрозрачным пикселям с ЭТИМ точным RGB.
   Другие цвета, прозрачный фон и полупрозрачные пиксели сохраняются.
   Рядом создаётся .png.bak; первая резервная копия не перезаписывается.
4. Нажми «Сохранить», затем F3+T в Minecraft.
   Новая сборка сервера для изменения этих правил не требуется.

Если редактор оставлен в папке дополнения, а не в корне ресурс-пака, после
«Сохранить» скопируй его assets в ресурс-пак ещё раз. Редактор записывает
правила только рядом с собой и меняет только явно выбранный PNG.

МЕТКА: ПОЧЕМУ СЛУЧАЙНО СОВПАВШИЙ ЦВЕТ НЕ ДОЛЖЕН СВЕТИТЬСЯ
• RGB 255,3,3 + альфа255: обычный пиксель, bloom не включается.
• RGB 255,3,3 + альфа254: явно размеченный материал, применится его правило.
• Альфа254 с RGB вне таблицы: существующий fullbright, без ореола.
• Альфа0: прозрачность.
Одинаковый RGB обычного блока или скина не включает bloom. Core-шейдеры
обычной поверхности очищают служебную метку; bloom_sample проверяет метку
до поиска цвета. Две служебные полосы камеры/ядерок тоже исключены из поиска.
Альфа254 — зарезервированная разметка материала: не ставь её случайно на
обычные области предметов/скинов. Если два предмета ЯВНО размечены одинаковым
RGB+альфа254, они используют одно правило. Для разных стилей возьми разные RGB.

Можно разметить PNG вручную: ровно A=254 из255 (99.607843% непрозрачности),
не приблизительные «99%». Экспорт нужен в PNG RGBA без потери значений альфы.
Кнопка редактора надёжнее, чем округление процентов в графическом редакторе.

ПРИМЕРЫ
Красный ореол + белый центр:
    {"source":[255,3,3],"halo":[255,3,3],"strength":1.0,"core":"white"}
Слабый зелёный ореол, исходная основа:
    {"source":[3,255,3],"halo":[3,255,3],"strength":0.25,"core":"keep"}
Сильный синий ореол, основа сохранена:
    {"source":[3,3,255],"halo":[3,3,255],"strength":3.0,"core":"keep"}
Другой цвет ореола и такой же центр:
    {"source":[255,3,3],"halo":[255,160,30],"strength":1.0,"core":"halo"}
Последний пример ЗАМЕНЯЕТ первое правило для255,3,3: дубли RGB запрещены.
Выбор цветов в редакторе открывает обычный системный диалог, где можно
ввести точные значения RGB. Двойной клик по строке открывает её настройки.

БЕЗ ГРАФИЧЕСКОГО РЕДАКТОРА
Можно менять bloom_rules.json, затем выполнить:
    py edit_bloom.py --write-glsl
Проверить JSON и соответствие GLSL без записи:
    py edit_bloom.py --check
GLSL-таблица находится в assets/lbc/shaders/include/bloom_rules.glsl.
Не редактируй её генерируемый блок одновременно с JSON: сохранение из
редактора заменяет этот блок данными JSON. Шейдер не читает JSON сам;
его собирает маленький локальный скрипт. В шейдере нет зависимости от Python.

КАК ЭТО БЫЛО У СВЕТОВЫХ МЕЧЕЙ
lightsaber_sith.png: красный клинок RGB255,14,14/A254.
lightsaber_jedi.png: синий клинок RGB0,48,255/A254.
У обеих текстур есть почти белая часть RGB255,252,252/A254; рукоять — A255.
До дополнения item.fsh делал A254 независимой от освещения и тумана, но
bloom_sample искал список RGB в готовом кадре без проверки A254, включая
обычные поверхности. Теперь источник ореола обязан иметь разметку материала.
Старые 15 RGB сохранены в таблице; новый пример255,3,3 добавлен отдельно.
Кольца Exoperso и сфера полиморфа используют отдельный outline-канал;
это дополнение не переписывает их способ извлечения и размытия.

ГРАНИЦЫ ЭТОЙ ОСНОВЫ
Проверен обычный opaque/cutout-рендер предметов, entity, terrain и particles.
Обычный предмет, включая световой меч, относится к основному сценарию.
Настоящие полупрозрачные/OIT-слои и видимость свечения через стекло требуют
отдельного канала маски: при смешивании альфа может потерять метку. Нельзя
лечить это включением глобального поиска RGB — вернутся засветки блоков.
Для новых прозрачных материалов сначала нужна отдельная интеграция этого
рендер-пути; не считать этот комплект проверкой всех режимов прозрачности.
Добавление glow к particles этим редактором не предусмотрено.
В игре после установки ещё нужно проверить внешний вид; GPU-проверка не
подменяет F3+T и просмотр на настоящем клиенте.

ПРОВЕРКИ ДЛЯ РАЗРАБОТЧИКА
tools/build_bloom_rules_patch.py воспроизводит точечные замены из читаемого
авторского пака. Шаблон правил и редактор лежат в этом дополнении.
tools/check_bloom_rules.py проверяет реальные шейдеры на GPU: совпадения RGB
обычных поверхностей, явную метку, белую/цветную основу, слабый/сильный ореол
и отсутствие повреждения служебных alpha-данных. Отчёты приложены отдельно.
Основной авторский пак при подготовке и проверках не изменялся.
